## 0.3 竞品分析与定位（按 V4 数据重算）

> 数据口径：竞品数据来自 2026-10 公开检索（厂商官网、高校图书馆采购介绍、第三方测评），**未逐一实测**。本产品数据全部为本地实测，可复跑。

### 0.3.1 重算：差距从「4–5 个数量级」变成「1–2 个数量级」

V3 的对比表写的是「8 部 / 419 条 vs 320 万篇，差 4–5 个数量级」。V4 的库不是那个量级了：

| 资产 | 规模 | 能不能直接引用 |
|---|---:|---|
| 地方目录（`items` 表，含法律名录 308 与国家级条目 22） | 65,111 条 | ❌ 只有标题 / 文号 / 日期 / 链接 |
| 国家级政策清单（gov.cn 全量） | 18,916 条 | ❌ 同上 |
| └ 其中已取到正文的 | 18,608 份 / 7,291 万字 | ✅ 有正文，可逐条引 |
| 核验语料（条数表 + 时效台账覆盖） | 8 部 / 419 单元 | ✅ 可做 C1/C3 判定 |
| **合计记录** | **84,027 条**（65,111 + 18,916，两表无重叠） | **能直接引用的占 22.1%** |

对照竞品：北大法宝 44 万+ 件、威科 320 万+ 篇、法信 1.42 亿篇文献。

- 按「件」比：84,027 vs 440,000 = **差 5.2 倍**
- 按「篇」比：84,027 vs 3,200,000 = **差 38 倍**
- 按「能引原文」比：18,608 vs 3,200,000 = **差 172 倍**

**这个变化必须写清楚，因为它改变了论证方式。** v3 可以说「不可比」，所以换战场；V4 不能这么说了——1–2 个数量级是可以被追问的差距，用户会直接问「那你为什么不用法宝」。答案不再是「量级不同」，而是下面这三条：

1. **78% 的库是「有名字没正文」**，这不是缺陷，是分工：目录层回答「有哪些文件」，全文层回答「这一条怎么写的」。竞品把两者混在一个检索框里，用户分不清「搜到了」和「能引」。
2. **C1–C5 是机器闸门，不是概率改善。** 这一点与数据量无关，是结构差异。
3. **私有稿件入口**，三家都没有。

### 0.3.3 「能引」与「有」是两件事，这是 V4 的组织原则

| | 竞品 | 有据 |
|---|---|---|
| 回答的问题 | 有哪些文件 | 有哪些文件 **+ 你引的这一条站不站得住** |
| 判据 | 覆盖 | 覆盖 **+ 判定** |
| 赢的条件 | 数据量 | 数据量够用之后，**规则完备** |

V4 的赌注是：**在 8 万条这个量级上，覆盖已经「够用」了**——足够让一个规划师做完鹰潭这种城市更新项目的前置政策梳理。继续往 44 万爬，边际收益递减；把 8 万条里「哪一条能引、哪一条已经废了、哪一条引错了」判准，边际收益上升。

这是一个**可被证伪的判断**，证伪条件是 §7.2「数据层质量组」的两个指标：目录主题召回率 ≥ 85%、时效台账覆盖率 ≥ 60%。两者达不到，说明 8 万条不够用，得回去扩库。

### 0.3.4 竞品的三个盲区，以及我们自己新暴露的两个

原三条（地方非立法文件、无私有稿件入口、不对结论负责）仍然成立。V4 新增两条自己的：

**新盲区一 · 我们抓不到 38% 的政府门户。** 2,491 个站点，可抓 1,545 个（62%）。省级 21/31、市级 409/685、县级 1,115/1,775。抓不到的 946 个站分三类：前端渲染（Vue/React 壳）、反爬（412 / 隧道不通）、首页真的没有文件入口。**这三类里只有第一类能靠渲染解决，而给 2,491 站上浏览器要 8.3 小时且模板一改全废**（论证见 `scripts/harvest/README.md`）。

**新盲区二 · 我们抓到的条目，七成多缺关键字段。** 文号缺失 76.6%（49,897/65,111）、日期缺失 10.7%（6,952）。没有文号，效力级别只能靠标题后缀猜；没有日期，新旧排序失效。这两个字段在列表页上根本没有，只在正文里。**出路不是调模型猜，是把正文抓回来抽**——`gov_full.py` 那条链路已经证明可行，只是还没接到地方站上（FR-03 的 P0 理由）。

### 0.3.5 一处必须如实记录的数据分歧

威科的时效能力，两个来源结论相反（官网详情页有「时效性」字段 vs 第三方 MCP 测评说没有筛选参数）。**推断（非事实）**：网页端有，接口层未开放。若成立，集成方会撞上与本产品目录层相同的困境——能查，接不进来。**未验证前不得作为对外口径**（T-11）。

### 0.3.6 定位（V4 版，可采纳）

> 有据是一个政策引用的确定性校验层，外面套了三层可检索的数据。
> 目录层告诉你**有哪些文件**（8.4 万条，来自 62% 可达的政府门户）；
> 全文层告诉你**这一条怎么写的**（1.86 万份国家级正文，可逐条引）；
> 法律名录告诉你**这部法还在不在**（308 条现行有效名录）。
> 三者之上是核验层：不调用模型，逐条核对条号是否越界、引文是否真实、法规是否失效、名称是否错配、所问法规划界。
> 核不过，就不给结论。

V3 说这条定位「有三个前提，一个都没验」。V4 的进展：前提 2（C3 时效可用）**部分验了**——法律层 308 条可以判「在不在现行名录」，实测《环境保护法》已不在目录、被 2026 年《生态环境法典》替代；前提 3（C5 在稿件场景失效）**没变**，稿件里没有「问题」，C5 仍需重新定义；前提 1（送审被打回常因引用错）**仍是未访谈**。

# 1. 背景与目标

## 1.1 业务背景

规划师写的东西要交出去，交出去的东西会被人追问「依据是什么」。这个追问在三个环节上出现，每个环节现有工具都不管用。

**环节一：立项前的政策梳理。** 接了江西鹰潭的城市更新项目，需要知道鹰潭市本级有哪些文件、江西省有哪些、国务院和部委有哪些，以及历史文化保护方面的相关规定。现状是人工在 4–6 个政府站之间翻。**判据是不能漏。**

**环节二：起草时的引用核对。** 写完一章，逐条核对引用的条号是否存在、引用的法规是否还有效。**判据是不能错。**

**环节三：送审前的自查。** 出引用清单 + 时效状态 + 疑似问题列表。**判据是可解释**——每条问题要能指到具体位置。

V4 的变化是：环节一现在有 8.4 万条可查，环节二现在有 1.86 万份能反查原文，环节三仍然只有 8 部的判定能力。**这三个环节的完成度第一次不一样了，这是 V4 主要要处理的不平衡。**

## 1.2 问题定义（全部换成实测）

| 编号 | 问题 | V3 的写法 | V4 的实测 |
|---|---|---|---|
| P1 | 政策清单靠人工翻站 | **基线未测** | 已测：鹰潭 × 城市更新，13 秒（浅抓 2 页/源）→ 24 条；2 分 19 秒（全量翻页）→ 扫 3,197 条。**省级仍缺**（江西站无可用接口） |
| P2 | 已废止文件混在检索结果里 | 8 部语料中有失效文件 | 全文库 **702/18,608 = 3.8%** 被源端标「已宣布失效」；其余 96.2% 是「未知」。此前抽样的 11.3% 是只看了最早几千份造成的偏差 |
| P3 | 大模型引用的条号会编 | 「具体错误率待从 CSV 提取」 | 66 题上真编造 **0%**、引用可追溯 **100%**——**但这组成绩建立在「模型只看到 8 条召回」的窄上下文上，1.86 万份库没有重测** |
| P4 | 政策文件格式不统一 | `.doc`/`.pdf` 零依赖不可解析 | 实测 18,900 份里 **308 份（1.6%）** 正文拿不到，抽样 60 份全是 1980–1990 年代扫描件 |
| **P5** | **新增：目录大面积缺文号与日期** | — | **无文号 76.6%（49,897 条）、无日期 10.7%（6,952 条）、未来日期 87 条（最大 2099-11-20，明显脏数据）** |
| **P6** | **新增：抓不到的地方不显示为空，而显示为「没有」** | — | 2,491 站里 946 站抓不到（38%）。如果界面只打印清单，用户会以为那些地方没发文件 |

**P5 和 P6 是 V4 新增的两条，也是这一版最重要的两条。** 前四条是「能力不足」，后两条是「不足会伪装成正常」。按 §7.2 的定义，后者属于状态不诚实，门槛是 100%。

## 2.3 端到端场景（鹰潭城市更新，V4 版）

```
① 规划师输入：地域=鹰潭，主题=城市更新
   → 目录层返回：国家级 24 条 / 省级 0（显式标缺，附原因）/ 市级 3 条
   → 覆盖度条写明「江西省站无可用检索接口，需人工补」
   → 同时给出「全库全文命中 47 条」：这些是能直接看原文的

② 规划师点开一条，看到的是：
   → 标题 + 文号 + 发布日期 + 发文机关 + 原文链接
   → 若是国家级全文命中：直接给条号 + 原文片段
   → 若是地方目录：只有元信息，**界面明写「本条未取正文，引用前请回源」**

③ 勾选 30 份申请装配
   → 管理员执行：抓全文 → 解析 → 判型 → 体检 → 出条数表
   → 失败进「待人工」，附原因（按格式分类统计，不笼统报「N 份失败」）

④ 管理员确认效力状态
   → 落台账；进入「可引用池」的只有「现行有效」+「未知（已标注）」

⑤ 规划师提问 / 贴稿 → 检索 → 生成 → 闸门 2 → 结论 + 逐条依据 + 时效

⑥ 出报告：引用清单 + 问题列表 + 漏引候选（目录 N 份 vs 稿子引了 M 份）
```

**第 ① 步和第 ② 步的分工是 V4 的关键。** 目录层的条目和全文层的条目在界面上必须长得不一样：前者是「我知道这份文件存在」，后者是「我知道它怎么写的」。混在一起显示，用户会把前者当后者用。

## 4.2 AI 参与节点（决策表）

| 节点 | AI 做什么 | 人工做什么 | 自主程度 | 失败怎么办 |
|---|---|---|---|---|
| 发现 | 出清单 + 覆盖度 | 决定用哪些 | L1 | 显示「该源未覆盖」 |
| 全文检索 | 2-gram 召回 + 排序 | 判断哪条能用 | L1 | 无命中就明说「库里没有」，不给近邻凑数 |
| 装配 | 抓取 + 解析 + 判型 + 体检 | 确认效力 | L2 | 失败的进「待人工」，不静默丢弃 |
| 核验 | 生成结论 + 规则校验 | 看结论是否采信 | L2 | 校验不通过降级为「部分作答」或「拒答」 |
| 时效 | 给候选与来源链接 | 确认 | L2 | 无证据标「未知」，不默认有效 |

## 4.3 异常与降级

| 异常 | 判定 | 降级动作 | 用户看到什么 |
|---|---|---|---|
| 模型超时 | > 30s | 返回检索到的原文 | 「已切换为原文模式」 |
| 模型不可用 | 连续 3 次失败 | 全局关生成，只留清单 + 原文 | 「只读模式」 |
| 检索无结果 | 闸门 1 判不命中 | 不生成 | 「库里没有这个话题」+ 目录清单作替代 |
| 条号越界（C1） | 条号 > 条数表 | 该依据不通过，结论降级 | 「引用的第 X 条不存在，该文件共 N 条」 |
| 引用废止（C3） | 台账命中且非现行有效 | 拦截该依据 | 「《X》已于 YYYY-MM-DD 废止，替代为《Z》」 |
| **条目无正文（L1 命中）** | 只命中目录 | 只给元信息 | **「本条仅目录，未取正文，引用前请回源」** |
| **条目无文号** | `doc_no` 为空（76.6%） | 效力级别标「按标题推断」 | 「文号缺失，级别为标题推断」 |
| **条目无日期** | `published` 为空（10.7%） | 排到末尾并标 `undated` | 「发布日期缺失」 |
| **站点抓不到** | `blocked/error` | 保留上次缓存标 `stale` | 「该源今日未更新，数据截至 YYYY-MM-DD」 |
| 成本超预算 | 日成本 > 120% | 降 topk，关闭重排 | 无感 |

**四种产品形态，任何一个都比报错好：**

1. 完整：清单 + 结论 + 依据 + 校验
2. 原文：清单 + 检索到的原文
3. 清单：只有目录层
4. **空清单 + 缺口说明**：什么都没有，但说清为什么没有

第 4 种是 V4 新增的，因为 38% 的站抓不到这件事不会消失，它必须有一个体面的表达形态。

# 5. 功能需求

## FR-01 三级政策清单（目录层）

- **优先级**：P0 · **状态**：✅ 已实现（`scripts/catalog/`、`scripts/harvest/local_catalog.py`、`/api/local`）
- **功能描述**：按地域 × 主题输出国家 / 省 / 市 / 县四级文件清单，带覆盖度与缺口原因
- **数据规模**：65,111 条（省 15,864 / 市 16,303 / 县 32,614 / 国家名录 330），覆盖 1,491 个地域
- **处理规则**：
  1. 地域按 `regions.chain` 向上展开（鹰潭市 → 江西省 → 国家）
  2. 主题按 11 个词表匹配标题，跨领域可多选
  3. 每个源独立状态：`ok / empty / blocked / unavailable / error / skipped`
  4. 多源命中合并，**每个推断字段带依据**（文号 / 台账 / 来源库 / 站点 / 标题 / 无法判定）
  5. 排序：完整串命中优先 → 日期倒序（6.5 万行 LIKE 扫描实测 110–265 ms）
  6. 覆盖度四级汇总，`missing` 必须显式输出并附原因
- **异常处理**：
  - 源端空 → `empty`，不当「没有文件」
  - 结构变化 → `error`，保留缓存标 `stale`
  - 反爬 → `blocked`，附探测记录
- **验收标准**：
  - AC-01：输入「鹰潭 / 城市更新」，国家级 ≥ 20 条、市级 ≥ 3 条，省级显式 `missing`
  - AC-02：任一源失败时，界面不出现「该级没有文件」这类断言
  - AC-03：离线自检 `crawl.py --selftest` 30/30 通过
  - AC-04：覆盖率数字与 `data/catalog/local_sites.json` 一致（当前 1,545/2,491）

## FR-02 全库全文检索

- **优先级**：P0 · **状态**：✅ 已实现（`/api/kb`、`scripts/harvest/build_index.py`）
- **功能描述**：在 18,608 份国家级正文里检索，返回条号 + 原文片段 + 文号 + 链接
- **规格**：FTS5 + 中文 2-gram（trigram 不支持两字词，「征收」「补偿」会失效）；167,595 块，平均 9 块/份
- **实测**：查询 5–35 ms；「历史建筑 修缮」首条命中《历史文化名城名镇名村保护条例》第三十三条，返回原文「历史建筑的所有权人应当按照保护规划的要求，负责历史建筑的维护和修缮」
- **异常处理**：
  - 两字词必须能查（2-gram 是为此设计的，不是优化项）
  - 命中块边界可能带上一块尾部（已知缺陷，见 §6.4）
- **验收标准**：
  - AC-05：`--search 征收` 能返回结果（验证两字词）
  - AC-06：任一命中的 `url` 可回源打开
  - AC-07：P95 查询延迟 ≤ 300 ms

## FR-03 专题库装配

- **优先级**：**P0**（V4 从 P0 升为「唯一 P0 阻塞项」） · **状态**：⬜ 未开发
- **功能描述**：从清单勾选 N 份 → 抓全文 → 判型 → 体检 → 出条数表与时效台账
- **为什么 V4 把它提到最高**：核验层要工作，必须有条数表（C1）和时效台账（C3）。现在这两张表只覆盖 8 部。**扩库扩了 4 个数量级，核验能力原地不动——这个错配是本项目当前最大的结构性问题**（T-16、T-17）。
- **处理规则**：
  1. 抓全文：HTML 优先；`.docx` 用 `zipfile` 读 `word/document.xml`；`.doc`/`.pdf` 归 `pending_convert`
  2. **判型**：分条型 / 分段型 / 无结构型，按型选判据
  3. 体检三重判据：结构完整性、内容完整性、可引用性
  4. 通过者自动生成条数表；不通过进「待人工」并附原因
  5. **同时抽文号与日期**，回填目录层（解决 76.6% 无文号）
- **验收标准**：
  - AC-08：对已解析的 `.docx`，条数与原文「第X条」计数一致
  - AC-09：体检不通过的 100% 出现在待人工清单，且带原因
  - AC-10：按格式分类统计成功率，不笼统报「N 份失败」
  - AC-11：装配 20 份真实省市文件后，文号抽取率 ≥ 80%

## FR-04 逐条核验（闸门 2）

- **优先级**：P0 · **状态**：✅ 已实现（`scripts/gatekeeper.py`），**语料仍是 8 部**
- **五项检查，全部不调模型**：

| 检查 | 判据 | 数据来源 | 在 1.86 万份上的可用性 |
|---|---|---|---|
| C1 条号越界 | 条号 > 条数表 | `article_counts.json` | **0.04% 可用**（8 部） |
| C2 引文查不到 | 引用文本在原文中找不到 | 语料正文 | ✅ 可用（有全文就能查） |
| C3 时效违规 | 文件已废止/失效 | `stale_ledger.json` + `doc_meta` | **3.8% + 308 条** |
| C4 名称错配 | 简称与全称对不上 | `doc_names.json` | 🟡 8 部精确 + 全库模糊 |
| C5 所问法规划界 | 引用了问题范围外的法规 | 问题 → 法规映射 | ✅ 可用 |

- **验收标准**：
  - AC-12：C1–C5 每组既有应通过用例，也有应拦截用例（现有 11 组）
  - AC-13：校验层不发起任何网络请求（断网可跑）
  - AC-14：同一输入两次运行结论完全一致
  - AC-15：**任一检查无法执行时必须标「未核」并降级结论，不得默认通过**

**AC-15 是 V4 里最重的一条 AC。** 因为在新库上，C1 和 C3 在 96% 以上的条目上是执行不了的。如果这时默认「通过」，整个产品就变成了一个假的核验器。

## FR-05 全稿自查

- **优先级**：P1（V4 保持 P1，但理由变了：V3 说「这是最重要的战略发现，应提 P0」，V4 说「先解决 FR-03，否则稿件核验也一样没条数表」）
- **状态**：⬜ 未开发
- **规则**：抽引用（《X》第 N 条 / 依据《X》/ 文号）→ 逐条走 FR-04 → 漏引候选（目录 N 份 vs 引用 M 份）→ 按「必须改 / 建议看 / 可忽略」分级
- **默认模式**：**纯规则，不调模型**（合规要求，见 §10.1）
- **验收标准**：AC-16 抽取召回率 ≥ 95%（20 条人工标注）；AC-17 漏引候选必须显式标注「以下是候选，请自行判断」

## FR-06 时效台账维护

- **优先级**：P0 · **状态**：🟡 部分（8 部 + 308 条名录）
- **现状数据**：`doc_meta.eff_status` —— unknown 17,906 / repealed 702
- **规则**：机器给候选（源站文末标注）→ 人工确认 → 未确认标「未知」，不参与「现行有效」判定 → 废止必须记替代文件
- **验收标准**：AC-18 每条有确认人与时间，无「机器自报」；AC-19 C3 只读台账，不读模型输出

## FR-07 评测与 badcase 看板

- **优先级**：P1 · **状态**：🟡 部分（`eval_run_app.py`）
- **规则**：评测集分层（能力 × 难度）→ 每次改动跑全量 → 逐题 diff → 线上反馈进 badcase 池 → 每月补 ≥ 10 题
- **验收标准**：AC-20 任意两版可对比；AC-21 badcase 每条带原始输入与当时判定

## FR-08 覆盖率与缺口语义（诚实层）

- **优先级**：P0 · **状态**：🟡 部分（`coverage` 字段已返回，前端已展示）
- **功能描述**：把「我没抓到」在界面上说成「我没抓到」，而不是留白
- **必须存在的五个显示位**：
  1. 清单顶部：各级命中数 + 各级状态
  2. 缺口区：**哪些源没通、原因、最后成功时间**
  3. 每条目录条目：`仅目录` 徽标（无正文）
  4. 每条缺字段条目：`文号缺失` / `日期缺失` 徽标
  5. 报告页：库的整体覆盖度（站点 62%、全文 22%、条数表 0.04%、时效 3.8%）
- **验收标准**：
  - AC-22：任一 `blocked` 源在界面上有可见说明
  - AC-23：全量检查 1,000 次查询，无一次把「未抓取」渲染成「0 条结果」
  - AC-24：五个显示位在默认视图全部可见，不需要点开详情

**AC-23 是全项目唯一的 100% 门槛指标**，理由见 §7.2。

## FR-09 一键降级

- **优先级**：P0 · **状态**：⬜ 未实现（当前需改代码）
- **验收标准**：AC-25 关闭后所有问答返回「原文模式」而非报错；AC-26 关闭动作不发版

# 6. AI 能力设计

本产品的特殊之处：**模型只承担链路上的一小段，其余全是确定性工程。** 这一节的重点是「哪些地方故意不用模型」。

## 6.1 能力全景

| 要办的事 | 方案 | 为什么不用别的 |
|---|---|---|
| 这个方向有哪些文件 | 结构化查询（SQLite，6.5 万行） | 不用向量：要能穷举、按级别过滤、能说「没有」 |
| 这一条怎么写的 | **FTS5 + 2-gram ← RAG 的检索在这** | 不用结构化：同一意思有多种说法 |
| 模型说的第 42 条有没有 | 确定性查找（全称 + 条号 + 原文子串） | 不用模型：要可复现、断网可跑 |
| 这份文件还有效吗 | 查台账 + 法律名录 | 不用模型：自报「有效」等于自验 |
| 该归哪一级 | 文号 + 标题规则，无依据就留空 | 不用模型：推断必须能说清依据 |

**不用微调的理由（V4 补充）**：18,608 份全文里，政策口径每年在变。微调改的是风格与格式，注不进「第 42 条是什么」，也注不进「什么时候废止的」。**而且 1.86 万份的时效变更频率，决定了任何训练周期都追不上。**

**工作流式而非自主 Agent**：一个要写进合同的准确性承诺，承受不起不可复现。

## 6.2 模型分级

| 任务 | 档位 | 实测/预估 |
|---|---|---|
| C1–C5 核验 | **规则引擎（非模型）** | 每次问答 |
| 目录字段推断 | **规则引擎（非模型）** | 每条目 |
| 抓取 | **HTTP + 解析（非模型）** | 每次刷新 |
| 结论生成 | 中杯（`qwen-plus`） | 每次问答 |
| 引用抽取 | 轻量模型或规则（优先规则） | 每次自查 |
| 评测打分 | 旗舰 + 人工抽检 | 每次跑批 |

## 6.3 提示词

系统提示 4,317 字 / 实测 2,863 token，占单次输入 72%。四条硬约束 + 边界判定四行字段 + 固定拒答句式。

**两条边界必须写死**：N1 不给法律意见（「该问题需由主管部门认定」）；N3 不声称效力状态（「效力状态由系统台账给出，你的输出不包含该字段」）。

**为什么不把五项校验写进提示词**：C5 的诞生就是实证——Dify 链路上 66 题一次没犯的错，换直连 `qwen-plus` 第一次跑就犯了。写在提示词里的硬约束，可靠性跟模型绑死；搬进规则层才成立。

## 6.4 检索策略（V4 重测）

| 项 | 规格 | 依据 |
|---|---|---|
| 检索方式 | FTS5 + 中文 2-gram | trigram 不支持两字词；2-gram 是必需项 |
| 索引规模 | 167,595 块 / 980 MB | 平均 9 块/份 |
| 召回数 | top 8 | 8 部语料上标定，**1.86 万份上未重标** |
| 实测延迟 | 5–35 ms（4 次查询） | 2026-10-20 |
| 上下文 | 830–2,125 字 ≈ 550–1,410 token | 占输入 14%–36% |
| 闸门 1 阈值 | 0.40 | **8 部语料标定，换库必须重标** |
| **已知缺陷** | **块边界可能带上一块尾部** | 命中的 `label` 会出现「（五）建筑的测绘信息记录和相关资料。 第三十三条」这种拼接 |

**这个缺陷为什么必须在 PRD 里写**：因为 C2（引文查不到）依赖「引用文本能在原文中找到」。如果块边界是错的，拿 label 去做引用比对就会误判。C1/C2 在 1.86 万份上要真正可用，必须先解决切块与条边界的对齐（FR-03 的工作之一）。

## 6.5 核验层

见 FR-04。新增一条设计原则：

**三张表缺失时的行为，比三张表存在时的行为更重要。** 缺条数表 → C1 标「未核」；缺台账 → C3 标「未核」；两者都缺 → 结论最高只能到「部分作答」，且必须在界面上写清楚「本次核验只覆盖了 X 项」。

## 6.6 失败与降级

| 类型 | 例子 | 处理 | 用户看到 |
|---|---|---|---|
| 技术异常 | 超时、格式错 | 重试 → 降级 | 「已切换为原文模式」 |
| 能力异常 | 检索未命中 | 兜底 + 回流 | 「库里没有这个话题」+ 清单 |
| 正确性异常 | 幻觉、引用失效 | 规则拦截 + 强制溯源 | 「第 X 条不存在」 |
| **覆盖异常** | 源站抓不到 | 显式标缺 | 「该级未覆盖，原因：…」 |

第三类最危险，因为**它不会报错**。第四类次危险，因为**它会伪装成「没有」**。

## 6.7 幻觉治理

| # | 防线 | 状态 |
|---|---|---|
| 1 | 只引用检索到的条文 | ✅ |
| 2 | 条号越界拦截（C1） | ✅（8 部） |
| 3 | 引文子串比对（C2） | ✅ |
| 4 | 废止拦截（C3） | ✅（8 部 + 308 条） |
| 5 | 名称白名单 | ✅ |
| 6 | 合理拒答算正向 | ✅ |
| 7 | 每个数字/期限能追到原文 | ⬜ |
| 8 | badcase 自动回流 | ⬜ |
| **9** | **「仅目录条目」不得被当成引用依据** | 🟡 界面已标，规则层未拦 |

# 7. 效果标准

## 7.1 评测集

**现状**：`eval/golden-set.csv` 66 题，L1 基础 12 / L2 推理 8 / L3 边界 6 / L4 对抗 40。**对抗占 60.6%，测的是「多难被打穿」，不是「正常使用多好用」。**

**重建规格（V4 不变，仍未执行）**：120 题上线门槛 / 200 题目标；能力维度 基础 25% 推理 30% 边界 20% 对抗 25%；难度 简单 30% 中等 45% 复杂 25%；3 个专题各 ≥ 30 题；样本 50% 来自非本人提供的真实提问；2 名规划师交叉复核。

**V4 新增一个分层要求**：题目必须标注**目标数据层**（目录层 / 全文层 / 核验层）。现在 66 题全部测核验层，没有任何一题测「清单全不全」。这是评测集的结构性偏斜，比对抗题占比过高更严重。

## 7.2 指标与阈值

### 效果组

| 指标 | 定义 | 目标 | 门槛 | 来源 |
|---|---|---|---|---|
| 引用可追溯率 | 引用能指到真实条款 | ≥ 99% | ≥ 95% | 评测集 |
| 真编造率 | 编出不存在的法条/文号 | ≤ 0.5% | ≤ 2% | 评测集 |
| 对抗通过率 | 对抗样本正确处理 | ≥ 95% | ≥ 85% | 评测集 |

| 误拒率 | 不该拒却拒 | ≤ 5% | ≤ 8% | 评测集 |
| 结论强度准确率 | 三档与人工判定一致 | ≥ 85% | ≥ 75% | 人工抽检 |
| **状态诚实率** | 未覆盖/未成功时显式说明，未伪装成「没有」 | **100%** | **100%** | 全量检查 |

### 数据层质量组（V4 新增，此前完全没有）

这组指标衡量的是「库本身好不好」，与模型无关：

| 指标 | 当前实测 | 目标 | 说明 |
|---|---|---|---|
| 站点可抓率 | **62%**（1,545/2,491） | ≥ 75% | 省级 21/31、市级 409/685、县级 1,115/1,775 |

**为什么单列这一组**：V3 的指标全部是「模型答得对不对」，而 V4 的产品问题有一半在数据层。一个 100% 准确的模型，配一个文号缺失 76.6% 的目录，交付物依然是不可用的。

**为什么状态诚实率定 100%**：这一条没有「差不多」。抓到 3 份报 3 份、没抓到报「没抓到」都是诚实；抓到 3 份却让人以为这是全部，就是不诚实。前一种错能修，后一种错会让人基于错误前提工作。

## 7.3 评分标准

| 档 | 判定 |
|---|---|
| 通过 | 结论方向正确，且每条依据可核验 |
| 部分通过 | 结论正确但有依据不通过，或降级过度 |
| 不通过 | 结论错误、编造依据、该拒未拒 |
| 应拒已拒 | 正确拒答，计入分子，**不算失败** |

## 7.4 评测流程

1. 改动前跑基线存档
2. 改动后跑全量，逐题 diff
3. 只看两类变化：由过转变不过（回归）、约束内变过（提升）
4. 任一门槛跌破，阻断发布
5. 补题后重跑历史基线，确认不是靠改题刷分

## 9.2 扩容对部署形态的影响（V4 新增）

这是 V4 最容易被忽略的一条产品约束：

| 形态 | V3（8 部） | V4（三层全量） |
|---|---|---|
| 可拷走的最小集合 | **约 400 KB** | **约 1.0 GB**（`kb.db` 980 MB + `catalog.db` 53 MB） |
| 拷走要多久 | 秒级 | 分钟级（U 盘 / 网盘） |
| 能不能塞进 git | 能 | **不能**（需 LFS 或外置） |
| 演示时启动 | 秒开 | 秒开（SQLite 局部读，不需要全载入） |

**结论：MVP「拷到任何地方都能跑」这个卖点，在 1.86 万份的量级上失效了。** 需要拆成两个包：轻包（8 部 + 校验层，400 KB，用于演示核心主张）与全包（三层数据，1 GB，用于真实查询）。这不是工程细节，它决定了这个产品怎么被交付。

## 9.3 延迟

| 指标 | 实测 | 目标 | 结论 |
|---|---|---|---|
| 首字延迟 | 中位 558 ms，最大 788 ms | ≤ 2.0s | 达标 |
| 完整响应 | 中位 6,328 ms，最大 9,456 ms | ≤ 8.0s | 8 次中 1 次超线 |

# 10. 风险与合规

## 10.1 数据合规

| 项 | 要求 | 措施 |
|---|---|---|
| 抓取对象 | 政府网站公开发布 | 只抓公开栏目与检索接口；限速 0.3–0.8 s/请求；带正常 Referer |
| 抓取频率 | 不对源站造成压力 | 单主机串行 + 间隔；**不做并发爆破**（N12） |
| **用户稿件外泄** | 稿件可能含未公开内容 | 默认只发检索条文与问题，不发全文；全稿自查走纯规则模式 |
| 数据留存 | AI 调用可审计 | 记时间、能力、输入摘要（不存全文）、输出、判定 |
| 模型服务商 | 政策文本经第三方 | 首次使用前明示；提供纯规则模式 |
| 来源标注 | 每条依据可回溯 | 目录条目必带 URL；失效链接保留原 URL 标 `stale` |
| **商业数据库** | 不得系统性导出再分发 | **禁止 `--import` 商业库导出物**（V3 §0.3.7，V4 仍在） |

## 10.2 内容安全

| 风险 | 措施 |
|---|---|
| 输出被当法律意见 | 提示词硬约束 + 界面固定提示 |
| 提示词注入（稿件藏指令） | 用户输入用分隔符隔离；规则层不读用户输入里的指令 |
| 敏感项目推断 | 不推断能否获批、能否拿资金 |

## 10.4 预期管理

界面上必须一直存在的四句话：

1. **「本工具不给法律意见。」** 效力认定以法制部门口径为准。
2. **「清单可能不全。」** 覆盖度写明哪一级缺、为什么缺。
3. **「仅目录的条目没有正文。」** 引用前请回源。
4. **「依据请自行复核。」** 每条都给原文与链接，点击可核。

## 11.1 术语

| 术语 | 含义 |
|---|---|
| **L0 法律名录** | 全国人大《现行有效法律目录》，308 条，判断「这部法还在不在」 |
| **L1 目录层** | 只存文件元数据（名称、文号、级别、地域、日期、链接），追求穷举 |
| **L2 全文层** | 有正文、可逐条引用的文件（当前 18,608 份国家级） |
| 专题库 | 一个主题 × 地域链上的 50–80 份全文 |
| 地域链 | 鹰潭市 → 江西省 → 国家 |
| 闸门 1 | 话题级：检索分数过低判「库里没有」 |
| 闸门 2 | 条文级：C1–C5，不调模型 |
| 三张表 | 条数表、时效台账、名称映射 |
| 判型 | 分条型 / 分段型 / 无结构型 |
| 覆盖度 | 四级各自状态（ok / partial / missing） |
| 状态诚实率 | 「没抓到」被如实说出的比例 |
| 自主程度 L1/L2/L3 | L1 机器建议；L2 机器执行人确认；L3 全自动（不用） |
