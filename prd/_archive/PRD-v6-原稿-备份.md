# 1. 背景与痛点

这一节不谈我们做了什么，先谈这件事现在是怎么被解决的、为什么那个解法不行。

## 1.1 现在这个活儿是怎么干的

一个规划师要给方案里某句话找依据，手上的动作顺序基本固定，六步：

1. **翻自己电脑**。以前做过的项目文件夹，凭印象找。找到了算运气，但这台电脑只有他一个人能看。
2. **翻院内共享盘**。按项目名建的文件夹，没有检索，只能一层层点。他知道大概有，但不知道叫什么名字。
3. **搜百度、必应**。输入「XX市 城市更新 实施办法」。返回十页，前三条常常是资讯、政策解读、问答，第五条才是原文；原文常常是转载页，不是发布机关的页面。
4. **进政府网站翻栏目**。市政府 → 政务公开 → 政策文件 → 按部门筛。栏目四到五层，站内检索经常只搜标题不搜正文，改版一次路径全变。
5. **问人**。微信里问做过这个城市的同事。
6. **写进稿子**。多数情况写「根据相关政策规定」，或者凭印象写一个文件名。

**第六步就是把风险留在了稿子里。** 前三步的产出不落账，第四步的产出是一个网页（下次还得重走一遍），第五步的产出在人的脑子里。

一句话概括现状：**这是一条每次都从头开始、而且终点不明确的流水线。**

## 1.2 四种失败，代价完全不同

用户提的那三件事，成本结构差别很大，混在一起说就看不出该先解决哪个。拆开。

### 第一种：搜了很久，最后找到了

耗时。看得见，可计量，也是四种里最轻的——至少有个结果。

代价：一条依据 25—40 分钟（分档见 2.4）。一份专题要 20—40 条，张工的原话是「半天到一天」。

### 第二种：搜了很久，最后没找到

这是最贵的一种，但它贵的地方不在花掉的那两个小时。

**贵在不知道该在哪停。**

你搜了两小时没搜到，你无法判断是「确实没有」，还是「我关键词不对」「栏目没翻到」「文件挂在区一级网站上」。这两种情况在行为上完全一样，在结论上完全相反：前者可以写「经检索未见相关规定」，后者是失职。

所以人不会停，会继续搜。**没有终止条件的搜索，时长由人的心理承受力决定，不由任务本身决定。**

搜完之后的东西也不好使。稿子里写一句「经检索未见相关规定」，这句话不可复核——换个人来，还得再搜一遍才能确认；领导问「你真查过了？」，你答不出过程。

### 第三种：找到了，但不能用

用户说的是「发现可能还没发布或者已经结束公示了」。这一类坑最多，分四种：

| 情形    | 长什么样                        | 后果                 |
| ----- | --------------------------- | ------------------ |
| 征求意见稿 | 标题跟正式文件几乎一样，页面上只有「征求意见」四个小字 | 引了不算依据，被专家一句话打回    |
| 已废止   | 文件本身还是原文，页面不标状态             | 张工那句「你引的这条废止了你知道吗」 |
| 被修订   | 新文件末尾一句「原XX同时废止」，旧文件里不提自己   | 你手里的是旧的，旧文件不会告诉你   |
| 尚未生效  | 发布日在前，施行日在后                 | 报审时点早于施行日，引了白引     |

**这四种情形的共同点：文件本身不会告诉你。**

废止信息写在另一份文件里，修订信息写在新文件末尾，效力状态要靠跨文件比对才能得出。所以「时效」这个字段不能从单份文件里读出来。

【决策】这也是为什么产品里必须有「时效未知」这一档，而不是「现行有效／已失效」两档。66,851 条标的是「未见废止记录」——意思是全库正文都读过、没有一份说它失效。这跟「确认有效」是两件事，界面上必须分开写，否则就是拿不确定冒充确定。

还有一个更隐蔽的：**搜索结果里最危险的不是「没有」，是「长得像有」。** 一堆标题近似的解读文章、转载、征求意见稿堆在结果页，会让人误以为文件存在、且能用。

### 第四种：这个市就没有

规划编制里有个常态：要做的事本地没有先例。中小城市的城市更新、控规调整、历史建筑活化，本地一份文件都没有。

现在的办法是凭经验想起某个城市做过类似的，或者问同行。这个动作完全依赖个人阅历。**一个工作 12 年的人和一个工作 3 年的人，在这件事上差一个量级，而这个差距没有任何办法被复制。**

用户说的「没有这个市的文件但是有别的市的可以借鉴」，说的就是这一条。

### 还有第五种，用户没提，但每天都在发生：文件在公司里，没人知道

涉密文件不能上外网、不能进公有云，只能放在个人电脑或者项目文件夹里。

结果是：**这类文件的复用率接近 0。** 不是因为它没价值，而是因为没有人知道它存在。做过那个项目的人调走了，文件就彻底消失。

这一条直接决定了产品的部署形态：只能内网。不是为了合规好看，是因为这批文件根本没有第二条路。

## 1.3 二十年都这样，为什么

三个机制，缺一个都不会是今天这样。

**机制一：三个事实分散在 1,493 个站点。**

「有没有这份文件」「它现在有效吗」「它管不管我这个事」，这三个问题的答案分别在三个不同的地方：不同站点、不同栏目、不同文件。没有任何一个入口能同时回答。搜索引擎解决第一个，解决不了后两个。

**机制二：判断的结论不留痕。**

每次有人花两小时判断「这个市没有相关规定」，这个结论跟着项目结项一起消失。下一个人来了从零开始。**同一件事被不同的人重复做了 N 遍，N 等于做过这件事的人数。**

**机制三：政策是状态量，不是静态物。**

一份文件的状态会变：起草 → 征求意见 → 发布 → 修订 → 废止。任何一次「存下来」都只是某一个时点的快照。所以这件事不是「把文件存起来」，是「维护一本带状态和出处的账」——这个区别决定了后面所有设计，尤其是 §4.6 的时效判定。

底下还有一个经济学事实，是这件事值得做的理由：**政策依据的复用率极高，留存率极低。** 一个城市的城市更新政策就那么十几份，每个项目都在引同一批。但这些引用关系从来不落账，所以每次都得重来。

## 1.4 现有的解法，各自卡在哪

用户让我「分析现在这个问题解决的方式」。逐个过一遍，包括我们自己的位置。

| 解法               | 能给什么            | 卡在哪                                            |
| ---------------- | --------------- | ---------------------------------------------- |
| 百度／必应            | 覆盖最广，冷门市的文件也能搜到 | 不认行政层级（把区级文件当市级）、不标时效、不认文号、原文常是转载页             |
| 商业法规库（北大法宝、威科先行） | 法规体系完整，有失效标注    | 地方规范性文件覆盖弱，分类口径不是规划口径；按账号年费；不能私有化部署到内网；涉密文件进不去 |
| 政府网站站内检索         | 权威，是一手源         | 站内检索质量普遍差，栏目层级深，改版即失效；1,400 多个站点各一套，没有统一口径     |
| 院内共享盘            | 能放涉密文件，没有外泄风险   | 只有目录树，没有检索；放进去就沉底；不标时效；谁放的谁记得                  |
| 问人／微信群           | 最快，对人而言也最准      | 不可扩展，不留痕，人走了能力归零                               |
| 通用 AI 对话工具       | 会总结，会说人话        | 会编法名和条号；给不出原文出处；内网用不了                          |

**六个解法，五个在解决「找到」，没有一个在解决「敢引」。**

这就是这个产品的位置。速度上打不过搜索引擎，法规覆盖上打不过商业库，唯一能占的是最后一公里：**给出结论的同时，说清依据是什么、依据现在是什么状态、哪一段没查到。**

【决策】不跟搜索引擎比覆盖，不跟商业库比法规全。定位放在「文件已经有了，判断它能不能引、引哪一条」。这个定位也决定了对错标准：一条引错比十条没找到更严重——因为没找到会被标出来，引错了不会。

## 1.5 公网没有护城河，内网有

这条单独说，因为它决定商业形态，不是技术细节。

爬政府网站这件事，技术上谁都能做。所以公网版本没有壁垒：今天做出来，明天有人做一样的。但涉密文件出不了内网，这意味着**谁能把院内的政策资产（含涉密那部分）组织成可检索的东西，谁就拥有一个别人拿不到的东西。**

内网部署是价值来源，不是合规上的妥协。

代价也清楚：内网没有外网出口，爬虫能力全部失效，所以必须有离线包；离线包又必须解决更新问题（§4.9）。这条链是产品形态的由来。

## 1.8 这套东西的欠账

排期要算它，所以放在背景里。`catalog.db` 是 2024 年那版采集脚本演进来的，几笔账还在还：

- `items` 主键叫 `key` 不叫 `id`。写 `WHERE id=?` 直接报 `no such column`，我踩过三次。

# 2. 目标与衡量指标

## 2.1 一句话

**把「查一条政策依据」从一次开放式搜索，变成一次有终点的查询。**

「有终点」是这句话的重心。1.2 里最贵的成本不是时间，是不知道该在哪停。

## 2.2 什么算终点：四种结束方式，三种算交付

一次查询只能有四种结束：

| 结束方式    | 输出                                 | 算不算交付   |
| ------- | ---------------------------------- | ------- |
| 有       | 条文原文 + 条号 + 时效状态 + 出处链接            | 算       |
| 半有      | 只有目录（标题、文号、机关、日期），明确标「仅目录，未取正文」    | 算，但要标清  |
| 没有      | 明确说「本次没找到」，附试过的关键词和区／市／省／国家四层各自的状态 | 算       |
| 转圈、假装没有 | 空页面、超时无提示、把「没抓取」渲染成「0 条结果」         | 不算，这是失败 |

**第四种是全项目唯一一个 100% 门槛：1,000 次查询里，出现 0 次。**

## 2.3 三个初衷，三个能力目标

用户提的三件事，各对应一个能力，指标不同。

### （一）存下来，省时间

- 单条依据耗时：25—40 分钟 → ≤ 3 分钟（含读结果、确认时效）
- 一份专题依据梳理：4—8 小时 → ≤ 1.5 小时
- 同一条依据第二次被查时，直接出库，不再联网

### （二）本地没有时，给替代

- 空白城市的查询不返回空页面：需要替代时，至少给 3 个可比城市的同类文件
- 替代建议被采纳率：给出的参照里用户实际勾选的比例 ≥ 30%
- **红线**：替代文件必须标「仅可参照，不可直接引用」。参照和引用混在一起，就是拿别人的地方法规当自己的依据，这个错比找不到严重得多

### （三）内网能用，涉密文件能被找到

- 断外网环境下，除「联网补漏」外全部功能可用
- 进内网库的文件，检索可达率 100%（进了库却搜不到，等于没进）
- 每一次涉密文件的查看留痕（责任人待定，见 §9 Q-07）

# 3. 用户场景

不写画像，写人。

## 3.1 三个人

**张工，42 岁，主创规划师。** 用 Word 写方案，微信群里收资料。电脑是院里的台式机，Chrome 版本被 IT 锁在 90 出头，装不了插件。他不会去学新工具，但愿意试一次——前提是第一次用就见效。

**小李，26 岁，工作 3 年。** 用 AI 写东西，但不敢直接信。她的习惯是「AI 给一版，我自己核一遍」。如果工具能告诉她哪几条已经被核过、哪几条没核，她会用得比张工狠。

**王总，50 岁出头，审核岗。** 不看过程，只看结论和引用清单。他判断一份稿子的第一动作是翻到参考文件那一页，看有没有引废止的。

## 3.2 主场景：周三下午四点

张工手上是老门西那片的一个更新方案，周五要交初稿。他在方案里写了一句「建筑高度可按程序适当突破」，但不确定依据在哪、能不能这么写。

他打开工具，输入：**「老门西历史文化街区更新，建筑高度和密度能不能突破现行控规」**。

1. 系统拆成 8 个取证方向，其中三个标了「必查」（市级法规、省级条例、国家行政法规）。
2. 1.1 秒后回来 89 条候选，每条右边标着 `可引` 或 `仅目录`。
3. 他勾了 14 份有正文的，点生成。
4. 17 秒后出五段报告。判断段第一句是「高度可以突破，但有条件」；依据段引了《南京市控制性详细规划执行与调整规定》的具体条款；路径段给了四条路，每条标了审批层级和大概周期。
5. 他把判断段和依据段复制进 Word，路径段留着回领导问话用。

**这一步的价值在于：他不用再花半小时去核「这条废止了没有」。**

## 3.3 两个异常场景，必须能用

**场景 A：内网。** 张工的台式机在内网，没有外网出口。所以「联网补漏」这个功能在他机器上直接不可用。系统必须：

- 一进页面就检测，内网环境下 `web` / `both` 两档置灰，鼠标悬停提示「当前网络不能访问外网，只用本地库」
- 不弹错误框，不报「网络异常」，因为这不是异常，是环境。报异常等于让用户以为系统坏了

**场景 B：弱网或接口超时。** 院里出口带宽不稳，下午三四点尤其明显。形态是：

- 单次请求超时 25 秒，重试 2 次，仍失败就返回已经拿到的部分结果，页面顶部挂一条黄条「本次有 3 个方向没取到，已标注」
- 不许转圈不动，不许给一个空页面说「没有相关政策」

# 4. 功能方案

## 4.0 边界

一句话：**输入一个问题，输出一份每条依据都能回查到条款、并标明时效状态的判断。** 除此之外都不做。

## 4.1 第一步：把问题拆成取证方向

输入一句话，输出 3—10 个方向，每个方向带「为什么必须查」和「这一层通常是空的还是满的」。

规则（跟 v5 一致，不改）：

- 地域按 `regions.chain` 往上展开（区 → 市 → 省 → 国家）
- 每个数据源独立状态：`ok / empty / blocked / unavailable / error / skipped`
- 多源命中合并，每个推断出来的字段都带依据（文号 / 台账 / 来源库 / 站点 / 标题 / 无法判定）
- 排序：完整串命中优先，然后日期倒序
- 缺的那一层必须显式输出并写原因，不许吞掉

验收：AC-01 鹰潭 / 城市更新，国家 ≥ 20 条、市 ≥ 3 条、省显式 missing；AC-02 任一源失败时界面不出现「该级没有文件」这类断言；AC-03 离线自检 30/30；AC-04 覆盖率数字跟 `data/catalog/local_sites.json` 对得上（1,545/2,491）；AC-26 新增城市不改检索代码，`region LIKE '%城市名%'` 就命中（上海已验证）。

**异常流程**：所有源都空 → 输出「本次没找到任何文件」，附试过的关键词和三层状态，不许说「没有相关政策」。源站结构变了 → 该源标 `error` 并保留上次缓存，标 `stale`。

## 4.2 第二步：取证

### 检索三档

用户自己选从哪查：

- `kb` 只查本地库。南京实测 1.1 秒 / 89 条。
- `both` 库优先，某个方向正文不足 3 份才出去补。默认这档。
- `web` 只联网。库外城市靠它。

【决策】`both` 不做「每个方向都联网」。  
权衡：8 个方向各抓一轮要一分多钟，而大多数问题在库里已经够用。全方向联网让平均耗时从 1 秒变一分半，换来的增量只有最后几个方向。**先按现在的做法上，如果数据显示「库内不足」的方向超过一半，再改成全方向。**

### 联网两条通道


1. **城市政策库 JSON 接口**。广州 `gz_gfxwjk` 6,989 份，带 `file_status`（有效 / 失效 / 失效（提前废止））。上海另一种形态：列表 `POST /gwk/policy/page` + 详情 `POST /gwk/policy/detail`，10,501 条，详情 0.17 秒/条，返回带 `evolutionList` 沿革和 `expired`。上海这个通道数据质量比广州好。
2. **现探门户栏目**。复用 `local_catalog.probe_site`，成功率约 62%。

三条硬规矩写在 `websearch.py` 文件头：只收政府域名、抓不到正文不算数、失败要说话。

### 踩过的坑，写下来省得再踩

- **别接公开搜索引擎。** 必应无视 `site:`——搜 `site:www.gz.gov.cn 城市更新`，前两条是国务院文件，一条广州的都没有。搜狗反爬，360 链接加密，百度拒绝裸请求（回 1.4 KB 拒绝页）。接了等于给用户「搜到了但不对」的错觉。
- `quote()` 默认把 `site:` 的冒号编成 `%3A`，必应就不认前缀了。要 `safe=":"`。
- `with ThreadPoolExecutor` 会让超时预算失效——`with` 退出时 `shutdown(wait=True)` 要把没跑完的线程等完。必须显式 `shutdown(wait=False, cancel_futures=True)`。
- **4 个方向并发打同一个站会互相拖死。** 按目标站分组，组内串行、组间并发。
- `gz.gov.cn` 证书配置老旧，默认 SSL 上下文会卡在旧版重协商，裸 urllib 稳定挂死 30 秒。必须 `net.get(insecure=True)`。
- **相关性闸门**：只命中「行动方案」「详细规划」这类纯形态词等于没命中。之前省级方向捞回过《广东省遏制与防治艾滋病行动方案》。
- **时效排序**：广州那批 2015—2019 的失效文件在召回里占多数，不排的话首屏全是作废规定。
- **单页上限不稳定**。`limit=50` 只回 41 条、`limit=100` 只回 64 条，分页会漏。保持 `limit=20`。
- **源端自报总数会变**。广州从 6,989 掉到 6,209（隔几小时）。结束条件必须是翻到空页，`total` 只用来显示进度。
- **合肥查不了。** 全站 HTTP 521 + 加速乐，第二层是混淆 JS，要完整浏览器环境。停在 `BLOCKED_SITES`，0.00 秒返回原因，界面用橙色阻断框写「看不到，不等于没有」。放灰色空状态里会被读成「合肥确实没这方面政策」。

验收：AC-31 三档返回的条目能用 `where` 字段区分来源；AC-32 `kb` 档不发任何网络请求，断网能跑；AC-33 `both` 档在库内充足时不发起联网；AC-34 广州方向命中率 ≥ 90%，每条带源端时效标记；AC-35 安徽省方向返回 0 条时报告里写明「源站只收省政府规章」；AC-36 单方向联网总耗时 ≤ 60 秒，超时要留部分结果。

**异常流程**：接口 429 / 限流 → 等 45 秒重试一次，仍失败就跳过并记录；字段名变了 → 该通道整体标 `error`，报告里降级为「本城市暂不可联网查」；证书错 → 走 `insecure` 并记一条告警日志。

## 4.3 第三步：核验（这块最值钱）

五项检查，全部不调模型，纯加减和字符串比对：

- **C1 条号越界**：引的「第 88 条」超过这份文件实际条数。判据来自 `blocks` 里 `kind='art'` 的块，覆盖 4,144 份。
- **C2 引文查不到**：引的那句话在原文里搜不到。有正文就能查。
- **C3 时效违规**：引了已废止文件当现行用。判据读台账，不读模型输出。
- **C4 名称错配**：简称跟全称对不上。
- **C5 所问法规划界**：引了问题范围外的法规。

**⚠️ 最重要的一条：任一检查执行不了，必须标「未核」并降级结论，不许默认通过。**
不是洁癖。C1 只覆盖 4,144 份，C3 只有 3.9% 有确定状态。这种覆盖率下默认「通过」，产品就变成一个假的核验器——它会给一份看起来很专业、实际什么都没核的报告。**这比直接报错危险得多，因为用户看不出来。**

验收：AC-12 C1—C5 每组都有「该过」和「该拦」两类用例（现 11 组）；AC-13 校验层不发任何网络请求，断网能跑；AC-14 同一输入跑两次结论完全一致；AC-15 判据缺失必须标「未核」并降级。

**异常流程**：文件没正文 → C2、C4 标「未核」，C1 标「无法判定」，结论降为「部分作答」；台账里没有这份文件 → C3 标「未核」，界面写「未查到废止记录」。

## 4.4 第四步：出报告

固定五段，第一段必须给立场。

| 段 | 回答什么 | 硬要求 |
|---|---|---|
| 判断 | 能做 / 不能做 / 有条件能做 | 第一句给立场，不许用「需视情况而定」收尾 |
| 依据 | 硬约束 / 程序义务 / 可争取空间 | 每条引到条号或文号；只有标题的文件不许进 |
| 路径 | 审批层级 + 周期 + 代价 | 三条要素齐全 |
| 缺口 | 哪一层、缺什么、意味着什么 | 每条写「要去找哪份文件、为什么必须找」 |
| 下一步 | 办什么事、找谁、拿哪条去说 | 「加强学习」「高度重视」不算建议 |

【决策】从四段改五段。
原来四段交付出来就是一次依据梳理，把有的东西排一遍，用户还是不知道该干嘛。加「路径」这段，逼着把「走哪级审批、大概多久、代价是什么」写出来。**代价是报告变长（实测 5,367 字），这条还没跟真实用户验证过，见 U-03。**

判断段的要求：把堵点分成「明文禁止」和「程序没走到」两类。这两类处理方式完全不同，前者只能改方案，后者是补手续。南京老门西那一问实测拆得挺准：高度是「明文限制＋有限例外」，考古是「程序没走到」。

两个补丁：

- **只有标题的文件不许进依据段。** 上一版允许写「据《某通知》，该文件已由某机关发布，从名称看针对……」——依据段混进三条这种凑数句，零信息量，还显得专业。现在这类只能进缺口段，写「需调取原文核实」。
- **提示词里必须注入当天日期。** 模型不知道今天几号，读到《南京历史文化名城保护条例》「自 2026 年 7 月 1 日起施行」，就写「届时才施行，需核对旧版过渡期」。当时已经生效快四个月。

验收：AC-44 五段齐全，缺段算失败；AC-45 判断段第一句必须是「能做 / 不能做 / 有条件能做」三选一（正则可判）；AC-46 依据段每条都能回查到 `chars > 300` 的正文文件；AC-47 连续 5 个不同问题跑通，五段结构都成立。

## 4.5 覆盖与缺口怎么说（这块决定用户信不信）

六个显示位，缺一个这产品就开始骗人：

1. 清单顶部：各级命中数 + 各级状态
2. 缺口区：哪些源没通、原因、最后成功时间
3. 每条目录条目：`仅目录` 徽标
4. 每条缺字段条目：`文号缺失` / `日期缺失`
5. 报告页：整体覆盖度（站点 62% / 正文 18.6% / 条文 4,144 份 / 时效 3.9%）
6. **`已抓未索引` 徽标**——上海那 8,903 份就是这种状态：文件在磁盘上，检索里没有

验收：AC-22 任一 `blocked` 源有可见说明；AC-23 全量 1,000 次查询，没有一次把「未抓取」渲染成「0 条结果」；AC-24 六个显示位默认视图全部可见；AC-29 被拦站点用橙色阻断，不用灰。

## 4.6 接口与发布

给低代码平台用的 JSON 接口，不走 SSE。`POST /v1/plan|gather|write`、`POST /v1/jobs` + `GET /v1/jobs/{id}`、`GET /v1/coverage|health`、`GET /v1/openapi.json`（OpenAPI 3.0.3）。

**为什么必须有异步**：`/v1/write` 实测 17—60 秒，超过百炼插件和魔笔数据源的等待上限。同步调用会「服务端跑完、结果丢了、token 也花了」。异步实测提交 0.08 秒，16.8 秒后取到结果。

鉴权走 `PV_TOKEN` + 请求头 `X-PV-Token`，默认为空即不校验，公网必须开。`/v1/health` 免校验。

上线前四件事，一件不能省：公网可访问、HTTPS、开 token 加限流、异步结果落库（现在在内存里，重启即丢，多实例不共享）。

⚠️ 索引 1.9 GB。低代码平台上只能走「服务端部署 + API 调用」，别想着把库塞进平台。

验收：AC-37 `openapi.json` 能被 Swagger Editor 解析、五个 path 齐全；AC-38 异步 60 秒内完成或明确 `error`；AC-39 开 token 后无 token 返回 401、health 仍可访问；AC-40 异常返回 `{"ok":false,"error":"..."}`，不抛裸栈。

# 7. 风险与应对

## 7.1 技术风险

- **并发扛不住。** 现在 `ThreadingHTTPServer` 单进程，异步任务在内存 dict 里。三个用户没问题，但院里推广到 20 人就会撞两件事：内存里的任务重启即丢、多实例不共享。**应对**：本期不做集群，上线前把「最多 5 人同时用」写进使用说明；真要扩，先把 jobs 落 SQLite。
- **索引 1.9 GB。** 部署包太大，内网拷一次要十几分钟。**应对**：拆轻包 400 KB / 全包 1 GB，内网用全包，外网测试用轻包。
- **地域归属整批误标。** 上海 8,903 份曾被标成国家，等于地方文件冒充上位法。**应对**：三级判定（url 精确 → 域名投票 → 只有 www.gov.cn 算国家），每次入库后核对 region 分布。
- **「抓到了」不等于「能用」。** 上海那批白放两天就是例子。**应对**：加「已抓未索引」状态，独立显示。

## 7.2 业务风险

- **可能得罪老用户。** 三个人已经习惯四屏流程，改成五段报告加检索范围选择，他们的第一反应大概率是「原来的怎么没了」。**应对**：老接口和老页面全保留，新版做成并行的开关，不替换。**这是刻意的技术债，认了。**
- **承诺过度。** 一旦跟院里说「能查政策」，对方会理解成「什么都能查」。**应对**：所有对外材料只写具体覆盖（上海、南京、江苏、昭通），不写「全国」。
- **法务口径。** 输出必须带免责声明。这条不是产品选择，是硬约束。

## 7.3 运营风险

- **答疑成本没算过。** 没有客服，答疑就是我。按每人每周 3 次估，三个人约 9 次/周，每次 5—10 分钟，**一周 1 小时左右**。这个成本在报审那周会翻倍，因为张工会连着问。

## 8.2 上线后只看三个数

1. **取证空结果率** = `gather_done` 里 `n_usable=0` 的比例。超过 30% 说明检索或数据坏了。
2. **未核占比** = `verify_result.n_unchecked / (n_cite × 5)`。超过 70% 说明核验层没起作用，报告页的横幅要加重。
3. **复制率** = `copy_report` / `report_done`。低于 20% 说明报告写出来没人用，问题在内容不在功能。

## 口径钉死，不许换

- 目录条目 = `items` 行数，**不是文件数**，同一份文件多源多行。

- 条文数 = `blocks.kind='art'` 行数，不是「第X条」字符串出现次数。
- 「可引」和「有目录」严格分开报。
