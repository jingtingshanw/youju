## 1. 为什么做这个 [随便改]

规划师写更新方案、写保护规划、写审查意见，绕不开一句「这么做允不允许」。这句话的答案散在三层文件里：国家法律、部委文件、省市规定，加上已经批复的控规图则。

现实是四件事一起发生：

- **找不到**。一个中等城市的主题政策散在 3—8 个部门栏目里。市级平台只收规范性文件不收规划；省级平台只收省政府规章、不收省人大立法——所以省级法规那一层，我们库里现在是**空的**，不是没抓，是源站就没有。
- **不知道还算不算**。2015 年的文件可能被 2023 年的新规废止，两版并排躺在搜索结果第一页。
- **引不准**。知道「有个规定说高度可以突破」，引不出第几条、哪一项、什么条件。
- **错了没人发现**。方案被退、意见被质疑，而写的人在提交前没法自查——他没第二个人替他核。

这四件事的共同点是：**错了有后果，而犯错的人当场发现不了。** 这就是做它的全部理由。

### 1.1 竞品大概什么水平 [随便改]

| | 覆盖到哪 | 缺什么 |
|---|---|---|
| 北大法宝 | 法律、行政法规、2019 年以后大部分地方规章 | 控规图则、批复文件、部门规范性文件基本没有；不回答「这个片区能不能突破」 |
| 威科先行 | 偏金融税务，规划类很薄 | 同上 |
| 政府门户站内搜索 | 本站 | 不跨站；命中里两成多重复转载；不判时效 |
| 通用大模型 | 什么都能答 | 不知道文件失效没有，法名条号会编，引文查不到 |

四家都没干同一件事：把「这条依据站不站得住」做成一次能复现的判定。

### 1.2 我们手里有什么、欠什么 [随便改]

**有的**：

- 国家层面 18,608 份正文，切出 166,588 条带条号的块
- 上海 / 南京 / 江苏 / 昭通 四个地区整库带正文，目录条目里能对上正文的 12,558 条（18.6%）

**欠的**，写在前面省得后面被问：

- 75.1% 的目录条目没有文号（50,745 条）。没有文号就没法在报告里精确指名，只能写标题。
- 时效只有 3.9% 是源端给的确定状态，剩下 66,851 条写的是「未知」。
- 法律条文原文一份没进库。人大网那个站被 WAF 拦死，要执行 JS 换会话，先不碰。规划最常引的《城乡规划法》正文因此不在库。

### 1.3 老系统的坑 [改完记一笔]

`catalog.db` 是 2024 年那版 `harvest` 演进来的，有几个当年为了省事留下的东西，现在每次接新城市都要被绊一下：

- `items` 表主键叫 `key`，不叫 `id`。写 `WHERE id=?` 直接报 `no such column`，我踩过三次。
- 去重键是「有文号用文号、没文号用折叠后的标题」。这个折叠规则是硬编码的正则，改它等于重刷全库。
- 正文落盘路径有两条并存过：`data/fulltext/<key>.txt` 和 `data/fulltext/<key前2位>/<key>.txt`。索引只读后者。第一条是我上一轮写错的，6 份文件已经迁回去了，但以后加新采集器必须调 `local_full.key_of / ft_path`，别自己拼路径。
- 广州接口的元数据字段名全带前缀，`_gz_zcwjk_gzgfxwj_file_status` 这种。我当时照着文档写 `file_status`，`.get()` 不报错，跑完发现失效标记 0 份、文号全空。⚠️ **凡是接 JSON 接口，先打一份字段快照存下来再写映射。**

### 3.4 四条不许破的底线 [别动]

1. **看不到不等于没有。** 抓不到、被拦、未收录、已抓未索引，四种状态分开显示，都不许渲染成「0 条结果」。
2. **「未见废止记录」不是「现行有效」。**
3. **「有 N 份」和「有 N 份能引」分开报。** 案例层 19 条里 16 条正文 0 字，只报 19 会让人以为能引。
4. **「已抓未索引」单独成态。** 上海那 8,903 份就是这种状态：文件在磁盘上，检索里没有。承认它，比事后解释便宜得多。

## 4. 核心三块，写在前面 [改完记一笔]

### 4.1 核验层（F-04）

这是整个东西跟「普通 RAG 问答」唯一不同的地方，也是唯一值得花钱做的地方。五项检查，全部不调模型，纯加减和字符串比对：

- **C1 条号越界**：引的「第 88 条」超过了这份文件实际条数。判据来自 `blocks` 里 `kind='art'` 的块，现在覆盖 4,144 份。
- **C2 引文查不到**：引的那句话在原文里搜不到。有正文就能查。
- **C3 时效违规**：引的是已废止文件却当现行用。判据读台账，不读模型输出。
- **C4 名称错配**：简称跟全称对不上。
- **C5 所问法规划界**：引了问题范围外的法规。

**⚠️ 最重的一条是 AC-15：任一检查执行不了，必须标「未核」并降级结论，不许默认通过。**
这条不是洁癖。C1 现在只覆盖 4,144 份，C3 只有 3.9% 有确定状态。在这种覆盖率下默认「通过」，整个产品就变成一个假的核验器——它会给出一份看起来很专业、实际上什么都没核的报告，这比直接报错危险得多。

验收（编号跟 v5.0 一致，不许改）：

- AC-12 C1–C5 每组都要有「该过」和「该拦」两类用例（现 11 组）
- AC-13 校验层不发任何网络请求，断网能跑
- AC-14 同一输入跑两次，结论完全一致
- AC-15 判据缺失必须标「未核」并降级

**这块没底的地方**：C1 对上海文件到底准不准，还没测。上海是整库抓的，条文块 46,816，但里面有大量「通知」类文件其实没有分条结构，可能被切成一整块。见 U-07。

### 4.2 联网取证（F-11）

用户要的是「能不能选联网」，所以做了三档 `scope`：

- `kb` 只查本地库。南京实测 1.1 秒 / 89 条候选。
- `both` 库优先，某个方向正文不足 3 份才出去补。默认用这档。
- `web` 只联网。库外城市靠它。

**`both` 刻意不做「每个方向都联网」。** 8 个方向各抓一轮要一分多钟，库里够用的方向再抓是纯浪费。

联网两条通道，都不用搜索引擎：

1. **城市政策库 JSON 接口**。广州 `gz_gfxwjk` 6,989 份，带 `file_status`（有效 / 失效 / 失效（提前废止））。上海是另一个形态，列表 `POST /gwk/policy/page` + 详情 `POST /gwk/policy/detail`，10,501 条，详情 0.17 秒/条，返回带 `evolutionList` 沿革和 `expired` 标记。上海这条通道的数据质量比广州还好。
2. **现探门户栏目**。复用 `local_catalog.probe_site`，成功率约 62%。

三条硬规矩写在 `websearch.py` 文件头：只收政府域名、抓不到正文不算数、失败要说话。

几个踩过的坑，写下来省得再踩：

- **别接公开搜索引擎**。必应无视 `site:`——搜 `site:www.gz.gov.cn 城市更新`，前两条是国务院文件，一条广州的都没有。搜狗反爬，360 链接加密，百度拒绝裸请求（回 1.4 KB 拒绝页）。接了等于给用户一个「搜到了但不对」的错觉。
- **`quote()` 会把 `site:` 的冒号编成 `%3A`**，必应就不认这个前缀了。要 `safe=":"`。
- **`with ThreadPoolExecutor` 会让超时预算失效**，`with` 退出时 `shutdown(wait=True)` 会把没跑完的线程等完。必须显式 `shutdown(wait=False, cancel_futures=True)`。
- **4 个方向并发打同一个站会互相拖死**。按目标站分组，组内串行、组间并发。
- **`gz.gov.cn` 的证书配置老旧**，默认 SSL 上下文会卡在旧版重协商上，裸 urllib 稳定挂死 30 秒。必须 `net.get(insecure=True)`。
- **相关性闸门**：只命中「行动方案」「详细规划」这类纯形态词等于没命中。之前省级方向捞回过《广东省遏制与防治艾滋病行动方案》，就是这个词表漏的。
- **时效排序**：广州那批 2015—2019 的失效文件在召回里占多数，不排的话首屏全是作废规定。
- **单页上限不稳定**。`limit=50` 只回 41 条，`limit=100` 只回 64 条，分页会漏。保持 `limit=20`。
- **源端自报总数会变**。广州从 6,989 掉到 6,209（隔几小时）。结束条件必须是翻到空页，`total` 只能用来显示进度。
- **合肥就是查不了**。`BLOCKED_SITES` 里短路，0.00 秒返回原因，界面用橙色阻断框写「看不到，不等于没有」。放灰色空状态里会被读成「合肥确实没这方面政策」。

验收：

- AC-31 三档返回的条目能用 `where` 字段区分来源
- AC-32 `kb` 档不发任何网络请求，断网能跑
- AC-33 `both` 档在库内充足时不发起联网
- AC-34 广州方向命中率 ≥ 90%，每条带源端时效标记
- AC-35 安徽省方向返回 0 条时，报告里写明「源站只收省政府规章」
- AC-36 单方向联网总耗时 ≤ 60 秒，超时要留部分结果

### 4.3 五段报告（F-14）

固定五段，第一段必须给立场。

| 段 | 回答什么 | 硬要求 |
|---|---|---|
| **判断** | 能做 / 不能做 / 有条件能做 | 第一句给立场，不许用「需视情况而定」收尾 |
| **依据** | 硬约束 / 程序义务 / 可争取空间 | 每条引到条号或文号；只有标题的文件不许进 |
| **路径** | 审批层级 + 周期 + 代价 | 三条要素齐全 |
| **缺口** | 哪一层、缺什么、意味着什么 | 每条写「要去找哪份文件、为什么必须找」 |
| **下一步** | 办什么事、找谁、拿哪条去说 | 「加强学习」「高度重视」不算建议 |

**为什么从四段改五段**：原来那版是「结论 / 依据 / 缺口 / 下一步」，交付出来就是一次依据梳理——把有的东西排一遍，用户还是不知道自己该干嘛。加了「路径」这段，逼着把「要走哪级审批、大概多久、代价是什么」写出来。

**判断段的要求**：把堵点分成「明文禁止」和「程序没走到」两类。这两类处理方式完全不同，前者只能改方案，后者是补手续。南京老门西那一问实测拆得挺准：高度是「明文限制＋有限例外」，考古是「程序没走到」。

实测：17 秒 / 5,367 字，路径段给了 4 条，每条带审批层级和周期。

两个补丁：

- **只有标题的文件不许进依据段。** 上一版允许写「据《某通知》，该文件已由某机关发布，从名称看针对……」——依据段混进三条这种凑数句，零信息量，还显得很专业。现在这类文件只能进缺口段，写「需调取原文核实」。
- **提示词里必须注入当天日期。** 模型不知道今天是几号，读到《南京历史文化名城保护条例》「自 2026 年 7 月 1 日起施行」，就写「届时才施行，需核对旧版过渡期」。当时是 10-24，已经生效快四个月。

**这块最没底的**：五段到底几段合适，我只在南京老门西这一问上验过（U-03）。先这么发，跑 20 个问题看情况再调。5,367 字对一份内部备忘可能太长，对一份能进方案的东西又可能太短——先按 A 做，上线看数据。

验收：

- **N09 不做移动端。** 场景是坐在电脑前写文档。

- **N14 不破解 JS challenge（合肥）。** 长期对抗，源站一升级就废。

### 7.3 口径 [别动]

- 目录条目数 = `items` 行数。**不是文件数**，同一份文件多源多行。
- 有正文 = `fulltext.status='ok' AND chars>=300`。抓到了抽不出算失败。
- 正文覆盖率 = 目录条目里标题能对上 `chars>=300` 正文的比例。**必须按标题算**，按 url 算只有 4.7%。
- 条文数 = `blocks.kind='art'` 行数。不是「第X条」字符串出现次数。
- 可引 = 有正文且能引到条或句。跟「有目录」严格分开报。

### 7.4 不许再用的旧数字 [别动]

「全文库 21,774 份 / 196,343 块」「地方只有南京和江苏有正文」「正文覆盖 22%」「条数表覆盖 0.04%」「效果 100% 可追溯」「单次成本 ¥0.00368」。前五条已被新数取代，第六条没重算。

## 8. 当时的决定 [改完记一笔]

每条写完顺便写「什么情况下该推翻」。不写推翻条件，后面的人要么盲从要么重踩。

**D-01 放弃公开搜索引擎，改政府源直连。**
必应无视 `site:`，搜广州返回国务院文件；搜狗反爬；360 链接加密；百度拒绝裸请求。四家都试过。
→ 什么时候改：出现能用的政务垂直搜索 API。

**D-02 检索范围做三档，`both` 不做全方向联网。**
8 个方向各抓一轮一分多钟，库里够用的方向再抓是浪费。
→ 联网单方向压到 5 秒以内，这条就推翻。

**D-03 报告改五段，判断先行。**
原来四段交付出来就是依据梳理，用户还是不知道该干嘛。
→ 用户反馈要更短、说路径段没用，就砍回四段。

**D-04 只有标题的文件不许进依据段。**
「从名称看针对……」是凑数句。

**D-05 提示词注入当天日期。**
模型把已生效四个月的新条例写成「届时才施行」。

**D-06 上海、广州走 JSON 接口整库，不走目录逐条。**
接口带时效和文号，比目录可靠。上海一次 10,501 条、详情 0.17 秒/条。
→ 接口下线或改参数就得退回逐条抓。

**D-07 合肥不破解，标不可用。**
第二层混淆要完整浏览器环境。
→ 出现官方开放接口再开。

**D-08 加异步任务 + 可选 token。**
撰写 17—60 秒，超过平台等待上限。
→ 平台支持长连接可以砍掉。

**D-09 采集并发锁 4。**
广州站对同一 IP 的并发不友好，实测 6 页并发 57 秒、串行 44 秒。

**D-10 正文按标题挂到目录。**
两次采集 url 规则不同，按 url 挂不上。
→ 统一 url 规则后改回按 url。

**D-11 兜底词从方向自身抽，不用固定领域词表。**
固定词表让「控规」方向捞回一堆名城条例。

**D-12 形态判定里「规定 / 规则 / 细则」优先于「规划」。**
《控规执行与调整规定》被误判成规划，从法规方向整个消失。

**D-13 专题装配从 P0 降 P1。**
整库入库已经覆盖 4 个地区，装配只对整库拿不到的类型有用。
→ 需要大量规划图则类文件时再提回来。

**D-14 索引的地域按「url 精确 → 域名投票 → 只有 www.gov.cn 才算国家」三级判，不许默认「国家」。**
