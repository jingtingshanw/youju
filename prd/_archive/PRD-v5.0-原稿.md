## 1. 问题与定位

### 1.1 问题陈述 `[自由]`

规划师写一份更新方案、一份保护规划、一份审查意见，需要回答「这么做允不允许」。答案散在三层文件里：国家法律、部委文件、省市规定、批复的控规图则。真实情况是四件事同时发生：

1. **文件找不到。** 一个中等城市的主题政策，散在 3—8 个部门的栏目里，市级平台只收规范性文件、不收规划，省级平台只收省政府规章、不收省人大立法。
2. **找到了不知道还算不算。** 2015 年的文件可能已被 2023 年的新规废止，而两版都在搜索结果第一页。
3. **引了但引不准。** 知道「有个规定说高度可以突破」，引不出是第几条、哪一项、条件是什么。
4. **错了没人发现。** 这四件事的后果是方案被退、审查意见被质疑，而写的人在提交前无法自查——他没有第二个人替他核。

这四件事有一个共同点：**错误有实际后果，而犯错的人在当下发现不了。** 这是本产品存在的全部理由。

### 1.2 现有替代品为什么不够 `[自由]`

| 替代品 | 覆盖 | 缺什么 |
|---|---|---|
| 北大法宝 / 威科先行 | 法律法规、部分地方规章 | 规划类批复、控规图则、部门规范性文件基本不收；不回答「这个片区能不能突破」 |
| 政府门户站内搜索 | 本站内容 | 跨站不聚合；「276 条命中」里 26% 是重复转载（鹰潭实测）；不判时效 |
| 通用大模型问答 | 全 | 不知道文件是否失效；法名和条号会编；引文查不到 |
| 同事 / 专家口头意见 | 全 | 不可溯源，无法写进文档，无法复用 |

四者都没有做同一件事：**把「这条依据站不站得住」变成一次可复现的判定。**

### 1.3 为什么是现在 `[自由]`

三层数据第一次同时具备：

- 国家层面有 18,608 份正文，条文可切到 166,588 条
- 地方层面有 4 个地区整库带正文（上海、南京、江苏、昭通），覆盖从「只有南京江苏」扩到 12,558 条目录条目可引正文
- 有 3 个城市拿到了 JSON 接口（广州、上海，以及待接的合肥替代通道），可以带源端时效标记

在此之前，核验层只能对着 8 部法规工作，覆盖率 0.04%。现在条文索引覆盖 4,144 份，覆盖率问题换了个形态：从「没有表」变成「有表但只覆盖一部分地区」。

### 1.4 定位 `[需记录]`

**给规划师用的一台「依据核验机」：输入一个问题或一段稿子，输出一份每条依据都能回查到条款、并标明时效状态的判断。**

三条不承诺（写进界面，写进提示词）：

- 不承诺覆盖全国所有地市
- 不承诺「未见废止记录」等于「现行有效」
- 不给只有标题、没有正文的文件编内容

## 2. 用户与场景

### 2.1 三类角色 `[自由]`

| 角色 | 是谁 | 他要的 | 对错误的容忍 |
|---|---|---|---|
| **规划师（主用户）** | 规划院项目负责人、主创 | 一份能进文档、能被追问的清单与依据 | 零。错一次不再用，且不会主动告诉你 |
| **审校人** | 总工、审核岗 | 快速看别人稿子里引了什么、有没有引废止的 | 低。要可解释，不接受「模型说的」 |
| **维护者（你）** | 一人维护全部数据 | 库别烂、别过期、缺口看得见 | 中。要能批量、要能跑 |

### 2.2 主场景：一次完整使用 `[自由]`

以「老门西历史文化街区更新，建筑高度和密度能不能突破现行控规」为例，实测时间：

| 步 | 谁做 | 动作 | 实测耗时 | 产物 |
|---|---|---|---|---|
| 1 | 规划师 | 输入一句话 | — | — |
| 2 | 机器 | 拆成 8 个取证方向（含必查层） | 数秒 | 方向清单 + 每层为什么必查 |
| 3 | 机器 | 按方向取证，标注每份是「可引条文」还是「仅目录」 | 1.1 秒（库内）/ 15—40 秒（联网） | 候选清单 + 覆盖说明 |
| 4 | 规划师 | 勾选要用的，或改一个问题重跑 | 人工 | 选定集 |
| 5 | 机器 | 撰写五段报告 + 逐条核验 | 17—60 秒 | 报告 + 核验明细 |
| 6 | 规划师 | 拿去改方案；不确定的看「缺口」段 | 人工 | — |

**第 4 步是本产品的关键设计**：机器不替人决定用哪份文件。它给出「哪些能引、哪些只有标题、哪些层是空的」，人做取舍。这样出错时责任链是清楚的。

### 2.3 不服务的对象 `[自由]`

- 想查「最新政策新闻」的人
- 想要法律意见、想要「你建议我怎么做」的人
- 需要覆盖全国所有区县的人（做不到，且不估算）
- 手机端用户（使用场景是坐在电脑前写文档）

### 4.4 四条诚实底线 `[勿动]`

1. **看不到不等于没有。** 抓不到、被拦、未收录、已抓未索引，四种状态必须分开显示，都不许渲染成「0 条结果」。
2. **「未见废止记录」不是「现行有效」。** 界面写全句，不出现单独的「有效」绿标。
3. **「有 N 份」和「有 N 份能引」必须分开显示。** 案例层 19 条里 16 条正文 0 字，只报 19 会让用户以为能引。
4. **「已抓未索引」必须单独成态。** 上海 8,903 份就是这种状态：数据在磁盘上，检索里没有。承认它，比事后解释便宜。

### 4.5 已确认取不到的东西 `[勿动]`

### FR-03 专题库装配

**优先级** P1（v4 为 P0，本期降级）· **状态** ⬜ 未开发

- **为什么降级**：v4 把装配定为唯一 P0，理由是核验层需要条数表。这一轮改走「整库入库」，上海 / 南京 / 江苏 / 昭通 四个地区直接整库带正文，条文索引从 0.04% 覆盖变成 4,144 份 / 166,588 条。装配的必要性收窄到**整库拿不到的文件类型**（广州库只有规范性文件，不含规划图则）。

- **验收**

  - AC-09（沿用）：体检不通过的 100% 出现在待人工清单，带原因

### FR-10 检索范围三档

### FR-14 五段报告撰写

**优先级** P0 · **状态** 🟡 单例验证 · **证据** `app/write.py`

- **描述**：输出固定五段，第一段必须给立场。

| 段 | 回答什么 | 硬要求 |
|---|---|---|
| **判断** | 能做 / 不能做 / 有条件能做 | 第一句给立场，禁止「需视情况而定」 |
| **依据** | 硬约束 / 程序义务 / 可争取空间 | 每条引到条号或文号；只有标题的文件不许进 |
| **路径** | 审批层级 + 周期 + 代价 | 每条路径三要素齐全 |
| **缺口** | 哪一层、缺什么、意味着什么 | 每条写「要去找哪份文件、为什么必须找」 |
| **下一步** | 动作级：办什么事、找谁、拿哪条去说 | 「加强学习」「高度重视」不算建议 |

- **规则**：
  1. 注入当前日期。模型不知道今天是哪天，会把已生效的新条例写成「届时才施行」（实测发生）
  2. 判断段要把堵点分成「明文禁止」与「程序没走到」两类，两者处理方式不同
  3. 资料里有冲突规定时，写清冲突在哪、按什么规则解（上位法优先 / 新法优先 / 特别规定优先）
  4. 输出上限 3,200 tokens
- **实测**：南京老门西一问，17 秒 / 5,367 字；判断段拆出两个性质不同的堵点（高度是「明文限制＋有限例外」，考古是「程序没走到」）；路径段给 4 条并标审批层级与周期。
- **验收**
  - AC-44：五段齐全，缺段视为失败
  - AC-45：判断段第一句必须是三选一的立场（正则可判）
  - AC-46：依据段里每一条都能回查到 `chars > 300` 的正文文件
  - AC-47：连续 5 个不同问题跑通，五段结构都成立（现只验证 1 个，见 U-03）

## 7. 指标体系

### 7.1 口径定义 `[勿动]`

| 指标 | 定义 | 易错点 |
|---|---|---|
| 目录条目数 | `items` 表行数 | 不等于「文件数」，同一文件可能多源多行 |
| 有正文 | `fulltext.status='ok' AND chars>=300` | 不是「抓到了」；抓到了抽不出算失败 |

## 附录 C · 术语 `[自由]`

| 词 | 意思 |
|---|---|
| 三层数据 | L0 法律名录（有哪些法）/ L1 目录（有哪些文件）/ L2 正文（这一条怎么写的） |
| 条文块 | 一段以「第X条」开头的正文，能单独引用 |
| 可引 | 有正文，且能引到具体条或句 |
| 仅目录 | 只有标题、文号、日期，没有正文，不能引用 |
| 未见废止记录 | 全库正文读过，没有一份说它失效。不等于一定有效 |
| 已抓未索引 | 正文在磁盘上，但没进检索库 |
| 闸门 1 | 话题级：检索分数过低 → 判「库里没有」，不生成 |
| 闸门 2 | 条文级：C1–C5 五项确定性检查 |
| scope | 检索范围：`kb` 只查库 / `both` 库优先补联网 / `web` 只联网 |
| 城市政策库 | 城市官方的文件检索 JSON 接口，比翻网页可靠（广州、上海已接） |
