# 1. 背景与痛点

## 1.1 现在手里有什么

先摆数，不摆形容词。

| 项 | 量 |
|---|---|
| 政策目录（只有标题、文号、机关、日期） | 67,541 条，覆盖 1,493 个地域 |
| 有正文、能引到条的 | 30,687 份 |
| 切成可检索的块 | 270,694 块 |
| 其中带「第 X 条」的条文块 | 166,588 条，摊在 4,144 份文件上 |
| 索引体积 | 1.9 GB |

覆盖是不平均的，这个必须说清楚，不然用户会以为哪都能查：

- 上海 82.7%（8,467 / 10,235）
- 南京 93.8%（1,483 / 1,581）
- 江苏 79.8%（1,350 / 1,691）
- 昭通 64.2%（854 / 1,331）
- 广州 1.3%（11 / 849）——上一轮抓崩了，没补
- 其余 1,486 个地域，约等于 0

三个结构性缺口：

- **文号缺 75.1%**（50,745 条）。没文号就没法在报告里精确指名，只能写标题加日期，被专家追问时不好答。
- **时效只有 3.9% 是确定的**。66,851 条写的是「未见废止记录」——意思是全库正文都读过、没有一份说它失效。这跟「现行有效」是两件事，界面上不能混。
- **法律条文原文一份没有**。人大网被 WAF 拦死，要执行 JS 换会话。所以规划最常引的《城乡规划法》正文不在库，只能给名录。

【决策】为什么不先把法律正文啃下来：一部法只服务一个方向，而把地方正文补上来服务所有方向。等内网离线包跑通再回头啃人大网。

## 1.2 他们怎么说的

10 月跟三位规划师聊过，三句话我都记着：

> **张工（主创，工作 12 年）**：「我不是找不到文件，我是不知道哪份还算数。2016 年的办法和 2023 年的办法都在搜索结果第一页，我引哪个？」

> **张工**：「上次报审，专家问我一句『你引的这条废止了你知道吗』，我当场没话讲。回来查了半小时才发现是 2019 年被替换了。」

> **小李（工作 3 年）**：「你们这种工具最怕给我一堆差不多的条文，我还得自己挑。我要的是它直接告诉我能不能干、卡在哪一条。」

> **王总（审核岗）**：他原话比较短——「我只看两件事：结论有没有依据，依据是不是还有效。」

这四句基本定了产品的形状：**要给立场，要给条号，要标时效，不要给一堆候选让人自己挑。**

## 1.3 为什么现在做

三个时间点撞到一起了：

1. **11 月中旬院里有个老城更新项目要报审**，张工答应拿它先试一次。这是唯一能拿到真实使用数据的机会，错过了就得等下一个项目。
2. **数据刚好具备条件**。条文索引 10-25 从 2,202 份涨到 4,144 份，「引到条」这件事第一次成立。再早两周，工具只能给标题。
3. **上海那批正文有时效压力**。源端 3.6% 已标失效，放着不管，过两个月用起来更容易引错。

反过来，不做的代价也说清楚：现在三位规划师还在用 v3 那个四屏界面，每人每周大概问两三次，问完还是得自己回原文核。**能用，但省不了最后那一步。**

## 1.4 老系统的欠账

`catalog.db` 是 2024 年那版采集脚本演进来的，几笔账现在还在还：

- `items` 主键叫 `key` 不叫 `id`。写 `WHERE id=?` 直接报 `no such column`，我踩过三次。
- 去重键是「有文号用文号、没文号用折叠标题」，折叠规则是硬编码正则。改它等于重刷全库，所以一直没敢动。
- 正文落盘路径并存过两条：`data/fulltext/<key>.txt` 和 `data/fulltext/<key前2位>/<key>.txt`。索引只读后者。前一条是我自己写错的，6 份文件已迁回，但以后加采集器必须调 `local_full.key_of / ft_path`，不能自己拼。
- 广州接口的元数据字段全带前缀，`_gz_zcwjk_gzgfxwj_file_status` 这种。我照文档写 `file_status`，`.get()` 不报错，跑完发现失效标记 0 份、文号全空。⚠️ 接 JSON 接口必须先打字段快照再写映射。

# 2. 目标与衡量指标

## 2.1 业务目标

只列能测的。测不了的放 2.3，不往这里凑。

| 指标 | 现状 | 目标 | 底线 | 实在不行 |
|---|---|---|---|---|
| 张工能直接拿去改稿的报告比例 | 没试过，估 0 | 60% | 40% | 25% 也先上线，但报告页必须显著标核验覆盖率 |
| 一份专题依据梳理的耗时（含人工筛选） | 没测，张工说「半天到一天」 | 30 分钟 | 45 分钟 | 1 小时内就接受 |
| 引用可追溯率（报告里每条引用都能在本次检索结果里反查到） | 100%（旧库 8 部语料） | 99% | 95% | 90%，低于 90% 不许发 |
| 真编造率（凭空造法名 / 条号） | 0（同上） | ≤ 0.5% | ≤ 2% | 2% 是死线，不能松 |
| 单次出报告耗时 | 17—60 秒 | ≤ 30 秒 | 90 秒 | 90 秒以上必须有进度提示 |
| 能答的城市数 | 4 | 5（补齐广州） | 4 | 4 也发，广州方向在界面上标「仅目录」 |

**「实在不行」这一列是给自己留的退路，不是可以随便用的。** 用哪一档要在上线评估会上说明理由，写进变更记录。

## 2.2 效果指标

- 核验 C1—C5 五项：判据缺失时必须标「未核」，不许默认通过。这条没有底线，一破整个产品就是假的。
- 覆盖诚实度：1,000 次查询里，把「未抓取」渲染成「0 条结果」的次数必须是 0。全项目唯一的 100% 门槛。

## 2.3 不设目标的

- 作者信任度：没有真实用户，问卷发不出去。
- 报告被打回的引用条数：要等报审结束才知道。
- 独立完成率：现在 0 人。

这三项在拿到第一个真实用户前，任何场合都标「自测」，不许对外说成效果。
