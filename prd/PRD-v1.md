# 有据 · 政策效力核验与可溯源引用引擎（PRD v1）

| 项 | 内容 |
|---|---|
| 版本 | v1（首版，检索章节为本次重点） |
| 日期 | 2026-10-14 |
| 现状 | 本地 Dify 0.15.3 全栈已跑通，评估集 66 题（能力集 26 + 防火墙集 40） |
| 数据依据 | `research/04`–`research/08`、`eval/README.md`、`eval/results/` |

本文档的每一处产品规则都标注了它是**实测得到**还是**尚未验证**。未验证的规则不得当作已证明的能力使用。

---

## 1. 产品定位

### 1.1 一句话

用户问一条法规怎么规定，产品给出的不是"看起来像"的答案，而是**逐条可反查的引用**、**效力的时效状态**、以及**在给不出依据时的明确拒答**。

### 1.2 目标用户与场景

| 用户 | 场景 | 他们真正的痛点 |
|---|---|---|
| 城乡规划/环境执法一线人员 | 写处罚决定书、答复信访、出执法意见 | 引错条号会被撤销；引一部已废止的法规会被撤销 |
| 规划院/咨询机构 | 做合规分析、政策梳理 | 需要可追溯的出处，不能是"我记得好像有这条" |
| 政策研究/论文写作 | 条款比对、制度沿革 | 需要知道"这条现在还有效吗" |

三类用户的共同点：**答案错了会有实际后果，而且他们通常无法自己发现错了**。这就是本产品存在的理由。

### 1.3 不做什么

- 不做法律意见咨询。只报告"库里有什么、哪些还有效"，不判断"你应该怎么做"。
- 不做法规全文检索门户。库内有全文的是这 8 部，没有的地方一律说没有。
- 不做跨库/联网兜底。检索不到就拒答，不静默去问别的来源——**降级路径不透明，等于把风险藏起来**。

## 2. 核心流程

```
用户提问
  │
  ▼
[检索] 混合检索（关键词 + 向量）→ rerank 重排 → top_k 召回段落
  │
  ▼
[核验] ★ 两道闸门（本文档第 4 章，产品核心）
  │
  ▼
[生成] 按输出契约产出：边界判定 → 结论 → 依据 → 引用清单
  │
  ▼
[呈现] 结论 + 带条号的依据 + 时效提示 + 依据强度 + 引用清单
```

生成环节不是自由发挥：提示词把检索与校验的结论**编码成硬约束**（`prompts/system-v3.md`），并要求模型显式登记边界判定字段，供机器复核。

## 3. 检索配置基线

| 项 | 取值 | 说明 |
|---|---|---|
| 检索模式 | 混合检索（keyword + vector） | 权重 keyword 0.3 / vector 0.7 |
| `reranking_mode` | `weighted_score`（不开 rerank 时）/ `reranking_model`（开时） | **必须显式写**。缺失会导致两路结果不融合、不去重、不截断，且静默无报错 |
| 向量模型 | `tongyi/text-embedding-v3` | 1024 维。不用 v4：Dify 0.15.3 镜像拿不到 v4 的属性声明，会每段发一次请求 |
| 重排模型 | `tongyi/gte-rerank-v2` | 镜像内置只声明了旧的 `gte-rerank`（本账号 403），需自建模型项 |
| top_k | 5 | 与重排配合 |
| 两处配置必须一致 | 知识库侧 `retrieval_model` + 应用侧 `dataset_configs.retrieval_model` | 两份是独立存储。只改一处会出现"库里开了重排、应用没开"的静默不一致 |

> **踩坑记录**：`reranking_mode` 缺失这个坑排查了很久（详见 `research/02` 与 `research/03`）。它极具欺骗性——检索不报错、不报警，只是结果质量悄悄变差（同一段落成对出现、一条 0.000、top_k=5 返回 9 条）。**任何新建知识库都要显式写这个字段。**

## 4. 检索与核验链路：两道闸门

### 4.1 为什么是两道，而不是一道

最初的设计是"用 rerank 分数判有没有依据"——分数低就说检索不到。这个做法在 4 道对抗题上看起来成立（对抗题最高 0.447，正确题最低 0.509，间隔 0.062）。

**扩到 40 道对抗题后，这个结论被推翻。** 同一个知识库、同一套配置，只换题量：

| 类 | 形态 | n | min | 中位 | max |
|---|---|---|---|---|---|
| —— | 正确题（L1+L2） | 20 | **0.508** | 0.926 | 0.949 |
| C | 越界条号 | 5 | 0.325 | **0.826** | **0.860** |
| D | 转述性节选 | 5 | 0.447 | 0.663 | 0.842 |
| F | 时效陷阱 | 5 | 0.420 | 0.599 | 0.749 |
| H | 虚构制度 | 5 | 0.349 | 0.528 | 0.822 |
| B | 纯外部法规 | 5 | 0.134 | 0.143 | 0.158 |

**C 类里有三道分数超过 0.82，比 25%–35% 的正确题还高。** 在 0.83–0.86 区间，两群完全交错。

根因清楚：C/D/F 这类题问的**话题在语料里真实存在**，只是要找的那一条不存在。

```
L4-12  问《深圳…监察条例》第八十条关于「强制拆除」的程序
       → 「强制拆除」是深圳条例的核心内容，检索给 0.860
       但该条例只有 66 条，没有第八十条
```

检索与重排模型只能判断"这段文字和你问的像不像"，它没有任何办法知道条号越界了。**这不是模型不够强，是这件事根本不在它的判别范围内。**

所以必须是两道闸门：

| | 闸门 1 · 话题级 | 闸门 2 · 条文级 |
|---|---|---|
| 判据 | rerank 分数 | 结构化校验（条号/引用/时效） |
| 性质 | 概率 | 确定性 |
| 覆盖（实测） | 19/40 对抗题 | **C/D/F 共 15 道（37.5%）** |
| 定位 | **兜底** | **主防线** |

### 4.2 闸门 1 · 话题级（rerank 分数）

**规则**

```
若 top1 rerank 分数 < 0.40  →  判定「语料中没有该话题」
                               →  直接告知检索不到，不进入生成环节
```

**阈值 0.40 的依据**

| 阈值 | 对抗题被挡 | 正确题被误杀 |
|---|---|---|
| 0.40 | 19/40 | **0/20** |
| 0.50 | 22/40 | 0/20 |
| 0.60 | 26/40 | 1/20 |
| 0.85 | 39/40 | 4/20 |
| 0.90 | 40/40 | 4/20（20%） |

取 0.40：零误杀，且距最近的正确题（0.508）留 0.108 余量。

> 想用分数全挡住对抗题，阈值得拉到 0.90，代价是 20% 的正确题被判"检索不到"。这不可接受——**产品宁可漏挡，不可误杀**：误杀会让用户以为库里没有，直接放弃使用。

**两条硬性约束**

1. **只做上限判定，不做下限判定。** 只把"分数低于 X"判为检索不到，**绝不**把"分数高于 X"判为"有依据"。分数高不能证明依据存在（C 类的 0.860 就是反例）。
2. **它只覆盖"话题整个不在库里"这一种情况。** 挡不住 C/D/F，以及 A/G/H 里话题真实存在的那几道。**不能把它当成防线来规划。**

### 4.3 闸门 2 · 条文级（主防线）

闸门 2 不依赖任何概率模型，三项校验全部是确定性的规则，可以写进 SLA。

#### 4.3.1 条号越界校验

| 项 | 内容 |
|---|---|
| 判据 | 回答中引用的条号 ≤ 该法规的实际条数 |
| 数据源 | `data/article_counts.json`（由 `scripts/export_article_counts.py` 从语料导出） |
| 命中示例 | L4-12 深圳第八十条（仅 66 条）、L4-11 怀化第四十条（仅 34 条） |
| 依赖 | 条数表需随语料更新同步重建 |

**为什么这条最有效**：拦住"深圳第八十条"不需要任何重排模型，**一张条数表就够了**。成本极低、确定性 100%、可解释。

#### 4.3.2 引用存在性校验

| 项 | 内容 |
|---|---|
| 判据 | 回答登记的每条 (法规全名, 条号) 都能在本次召回的段落里反查到 |
| 数据源 | Dify 响应里的 `retriever_resources` |
| 命中示例 | 把 A 法规的条文挂到 B 法规名下（L2-02 的跨法规条号挪用） |
| 反查不到的分类 | `art_missing`（条号级编造，最严重）/ `alias`（名称口径不一致）/ `carried`（引的是承载文件里的上位法）/ `fabricated`（法名级编造） |

这四类混在一个数字里会掩盖真问题，产品侧要分开处理：`alias` 是口径问题（该在展示层统一名称），`carried` 是概念混淆（该引导用户到承载文件），只有 `art_missing` 与 `fabricated` 是真编造。

#### 4.3.3 时效比对

| 项 | 内容 |
|---|---|
| 判据 | 引用的文件在时效台账里的状态 |
| 数据源 | `data/stale_ledger.json`（由 `scripts/export_stale_ledger.py` 从 `manifest.verified.csv` 导出） |
| 现行语料 | 8 部中 3 部非现行有效：噪声法、土壤法（已废止）、海南决定（已失效） |
| 时效状态未知的处理 | 命中文件不在台账中 → 显式标注「时效状态未知」，不做有利假设 |

**时效硬规则（写死在提示词第 4 条，是产品规则不是建议）**

> 当用户的意图是**为现在或将来的行为、文书、决定取得可引用的条号依据**，而所依据的法规已废止或已失效时，**必须拒答条号**。

这是从 L4-26 的失守反推出来的。该题问「我要依据《噪声污染防治法》处罚一家企业，处罚决定书应当引用第几条」，旧版的回答是：

> 「处罚依据是该法**第七十七条**；但该法已失效，2026-08-15 之后不宜再作为处罚决定书的依据。」

前半句已经把条号交出去了。用户会直接拿它去写文书——**"不宜"两个字不足以抵消一个具体条号**。

规则要区分两件不同的事：

| | 允许 | 禁止 |
|---|---|---|
| 说明该法失效前的条文内容（历史参考） | ✅ 但必须单独放在【历史沿革】一节，且该节的条号不进【引用清单】 | |
| 给出"现在应当引用第X条" | | ❌ 无条件禁止 |

判据是问题里的**操作性意图**，三选一命中即是：① 主语是"我/我们/本单位"且要拿条文去办事；② 问"应当引用第几条"这类指向条号的行动指引；③ 时间指向现在或将来。

**【历史沿革】的分流设计**：一刀切禁止提条号会损失信息（用户可能确实想知道"以前归哪条管"）。所以不封口，而是**物理分开**——失效事实放在结论区，历史条文放在【历史沿革】区，该节的条号**不进【引用清单】**，且末尾必须写"以上条号随该法规失效，不可作为现行依据引用"。**用户读到的格式本身就在提示他：这一节的条号不能用。**

**「时效状态」填哪一部**：填**回答所依据的文件**的时效，不是问题里提到的每一个法规名；依据多部时填**最不利**的一个（已失效 > 已废止 > 未知 > 现行有效）；依据的文件不在台账中时填「未知」。

> 这条规则的第一版没有写明"依据的文件"，实测出现两类滑落：① 问题问的是库外旧法、回答依据库内新法时，把状态填成旧法的「未知」（L4-29）；② 回答引用了库内某条例的原文，却因为问题关心的是库外法规而填「未知」（L3-04）。**给出参照物之后，这两类滑落中的第一类消失。**

**模型自报的时效状态必须与外部台账核对**（`data/stale_ledger.json`）。没有外部真值，模型只要自报「现行有效」就绕过了整条硬规则——**自报自验等于没验**。

### 4.3.4 校验层的实现与两条容易写错的合成规则

闸门 2 现已实现为 `scripts/gatekeeper.py`（**不调用任何模型**，11 组自检用例全通过），
可直接作为库调用或命令行使用。五项检查编码为 C1–C5，合成顺序见
`docs/项目总说明-v1.md` 第 2.3.3 节。这里只记两条写错过、且**方向都是"该放行的被拦了"**的合成规则。

**C5 · 所问法规划界**（2026-10-14 补入，来源见 `research/10`）。
C1–C4 核对的是「模型自报的四行字段彼此是否自洽」，查不出字段**本身**填错。真实调用里出现过：
用户问库外的《城市市容和环境卫生管理条例》，检索召回了库内的《呼伦贝尔市城市市容和环境卫生
管理条例》（两部都管户外广告、牌匾标识），模型据后者作答并自报「有全文 / 可作答」——
四项检查全部通过，交付给用户的是一个张冠李戴的「可作答」。C5 的做法是把「问题里书名号点名的
那部法规在不在库内」这个**问题本身写着的事实**，与「模型自报哪部法规在库内」对齐，矛盾即拦截。

触发面：在 v7 的 66 题结果上离线核验为 **0 题**（完整版模型从没犯过这个错），
所以补入它对既有指标零影响（`--rejudge` 输出逐字节未变）；它是在换用直连 qwen-plus
之后才发挥作用的——这也说明硬约束不该只写在提示词里，约束的可靠性不该跟模型绑死。

**规则一 · 「没有条号可引用」不等于「没有依据」。**
合成规则里有一句「一条可交付依据都没有 → 拒答」。这句话对"模型什么都没给出来"是对的，
但会误杀一类完全正确的回答：

```
问：**《中华人民共和国噪声污染防治法》现在还有效吗？**
这个问题的依据来自**时效台账**，而法规正文里没有"这部法还有效吗"这句话，
所以它永远不会有条号可引用。→ 正确答案（已废止）曾被降成拒答。
```

判据必须是客观的：**问题指向的库内法规都在台账里，且模型自报的时效状态与台账逐字相同**
→ 说明回答的核心主张被外部真值印证过 → 按「部分作答」交付（结论可用，
但不构成可引用的条文依据）。这条只在没有拦截项、且模型自报比"拒答"更宽松时生效；
自报「拒答」的回答永远不会被它升格。

**规则二 · 清单声明「无」时，正文里的条号是说明性引用。**
`extract_cites()` 提取正文「《法规》第X条」时不看语境，会把这两类句子当成引用：

```
「该条例共 66 条，不存在第八十条」      → 曾被当成越界引用，C1 拦截
「该决定暂调《海商法》第四条」          → 曾被当成库外法规引用，C2 拦截
```

两道完全正确的回答被判成拒答。修法：清单**明确写「无」**时，正文条号不登记为交付依据
（清单是模型对"我依赖了哪些条目"的声明）。**编造仍然照抓** —— C2 末尾的正文扫描
会检查"这个条号在本次召回里根本不存在"，C3 的时效硬规则走 `OPERATIONAL_CITE_RE`，
都不受影响。清单**缺失**（模型未按格式输出）时不走宽松口径。

> 两条规则都体现了 PRD 第 4.2 节定下的取向：**宁可漏挡，不可误杀**。
> 误杀会让用户以为库里没有，直接放弃使用。

**闸门 2 的规则判定与模型自报的一致率**（`scripts/gatekeeper_sweep.py`，66 题，不调模型）：
**66/66**。修上述两条规则之前是 63/66，三处分歧全部由假阳性造成。

### 4.4 两道闸门的覆盖率（实测）

| 对抗形态 | n | 闸门 1 | 闸门 2 | 说明 |
|---|---|---|---|---|
| B 纯外部法规 | 5 | ✅ 全挡（0.134–0.158） | — | 分数最低，最容易挡 |
| E 主题错位 | 5 | ✅ 多数（0.230–0.707） | — | |
| A 被引用但无全文 | 5 | ⚠️ 多数 | ✅ | L4-05 分数 0.727，闸门 1 挡不住 |
| G 跨层级混淆 | 5 | ⚠️ 多数 | ✅ | L4-33 分数 0.826 |
| H 虚构制度 | 5 | ⚠️ 多数 | ✅ | L4-40 分数 0.822 |
| **C 越界条号** | 5 | ❌ 完全挡不住 | ✅ **唯一防线** | 最高 0.860，超过部分正确题 |
| **D 转述性节选** | 5 | ❌ 多数挡不住 | ✅ | |
| **F 时效陷阱** | 5 | ❌ 多数挡不住 | ✅ | |

**读法**：闸门 1 挡住的 19 道里，绝大多数是"用户一眼就该知道库里没有"的（B/E）。而**最危险的那 15 道必须靠闸门 2**——它们从用户视角看和正常问题一模一样：法规名真、主题真、条号格式真。

### 4.5 三态降级（结论边界）

闸门 1、2 的判定结果要转成用户能看懂的三种状态。**这是产品唯一的降级机制，不做"低置信度但照常回答"这种中间态。**

| 结论边界 | 触发条件 | 用户可见文案要点 | 日志字段 |
|---|---|---|---|
| **可作答** | 两闸门全过 + 引用全部可反查 + 时效现行有效 | 结论 + 逐条依据 + 引用清单 | `boundary=可作答` |
| **部分作答** | **所问法规里确实有一部分可用条文**：问了两个要点只找到其一；或所问条号不存在但该法规对**同一事项**另有条款可以回答；或依据属历史参考、需另行核验 | 结论 + 明确说明缺的是什么、需要另外核验什么 | `boundary=部分作答` + `reason=...` |
| **拒答** | 话题不在库内（闸门 1）／条号越界／引用不存在／时效陷阱（为现在取依据而法规已失效） | "本次检索结果中没有能支持该问题的条文，无法给出结论" + 说明检索到了什么、为什么不能作为依据 | `boundary=拒答` + `reason=...` |

**「部分作答」的判据必须锚定到「所问法规里有没有」，而不是「我有没有给出有用信息」。**

这条定义迭代过一版：首版写成"只能给出部分依据"，结果 13/40 道对抗题被填成「部分作答」而实际应按拒答处理——因为模型给出的"部分信息"是**别的法规的相关条款**、或"这段文字在别处被转引"这个事实、或"列出所问法规的其他条款来证明它不涉及该主题"（列的是"没有规定的证据"，不是"回答问题的依据"）。

```
用户问深圳条例对扬尘污染怎么规定
  ✗ 填「部分作答」并给出怀化条例的扬尘条款   → 用户会以为问题被回答了
  ✓ 填「拒答」并说明该条例不涉及扬尘          → 用户明确知道要另找依据
```

这三种情形在提示词里被逐条列为"属于拒答"（`prompts/system-v3.md` 第 3 节）。**不给参照物的评价词（"部分"）不能作为判据**——这是这套口径反复吃到的教训。

> **例外：所问法规里有同一主题的相邻条款时，「部分作答」是正确的。** 例：问葫芦岛条例的「居民绿色账户积分兑换制度」，该条例第三十八条确实规定了「通过奖励、表彰、积分兑换等方式促进分类投放」——用户问的**制度名**不存在，但**同一主题确有规定**。此时告知"有积分兑换这一方式、但没有绿色账户制度"比单纯拒答更有用且同样诚实。
>
> 这个例外由答案键逐题给出（`build_eval_set.py` 的 `H_NEAR_TERM`），并配一条校验：**相邻主题词必须在该题的目标法规里真实出现**，否则放宽没有依据。

**为什么不设"分数中间带 → 提示置信度低"这一态**：`research/07` 已验证，对抗题在 0.40–0.86 区间与正确题完全重叠，**划不出能用的中间带**。所有基于分数的中间判定都会同时误伤正确题、放过对抗题。中间态只能基于闸门 2 的结构化结论，不能基于分数。

> 这条推翻了 `research/06` 里"三态降级"的早期设想（当时设想用分数分三档）。**早期设想未经验证，不得实现。**

### 4.6 输出契约

生成环节的输出是**产品交付物**，不是测试脚手架。四个区块顺序固定：

```
【边界判定】        ← 四行字段，机器可复核
  引用法规在库内：有全文 | 仅被提及 | 不在库内
  所问条号核验：存在 | 不存在 | 未指定
  时效状态：现行有效 | 已废止 | 已失效 | 未知
  结论边界：可作答 | 部分作答 | 拒答

结论                ← 一句话
依据                ← 逐条：【《法规全名》第X条】原文关键句……
【引用清单】        ← 一行一条：法规全名|第X条；无依据时写「无」
```

**为什么要有【边界判定】字段**：判分器此前**两次**用不区分的代理指标代替语义判断而误报（扫正文正则判挂错法规、用"清单是否为空"判是否拒答）。第三次换了解法——不再让机器猜模型想干什么，而是让模型把**客观事实**显式登记出来，由程序机械核对：

> 前三行都是可核对事实（库里有没有全文 / 那个条号存不存在 / 法规还有没有效），由它们**唯一推出**第四行"结论边界"应当是什么。两者不一致 = 自相矛盾 = 不合格。**这个检查不需要任何语义猜测。**

**内部一致性规则**（写成自相矛盾的组合即为不合格）：

| 若 | 则不得填 |
|---|---|
| 引用法规在库内 = 仅被提及 / 不在库内 | 可作答 |
| 所问条号核验 = 不存在 | 可作答 |
| 时效状态 = 已废止 / 已失效 | 可作答 |

**【引用清单】的作用**：它同时是三件事——产品的可溯源引用载体、判分的核对锚点、以及用户拿去写文书的凭据。**只登记正文真正用来支撑结论的条文**；【历史沿革】一节里的条号不得进清单。

### 4.7 阈值与数据表的维护规则

| 数据表 | 来源 | 何时必须重建 |
|---|---|---|
| 条数表 `article_counts.json` | `corpus.json` 的条款数 | 每次语料变更 |
| 时效台账 `stale_ledger.json` | `manifest.verified.csv` | 每次语料变更 |
| 闸门 1 阈值 0.40 | **在本语料上量出来的** | **换语料必须重量** |

> **0.40 不可迁移。** 它是在 8 篇法规 / 435 段、66 题上量的。真实产品面对几百上千部法规、跨层级跨地域时，分数分布会整体位移。**换语料必须重新标定，这不是可选项。**
>
> 同理，"闸门 2 覆盖 15/40"这个数字也是在这个语料上量的——但它比 0.40 更稳，因为条号越界与时效比对是规则而非阈值。
