## 〇、一页结论

**基线（v1）不是「勉强能用」，是「L3 层基本失效」：6 道时效题只答对 2 道，而且错得最严重的那道

|---|---|---|---|

## 一、评估集与判分口径

见 `eval/README.md`。这里只强调三点：

1. **四层不是一条水平线**：L1 是及格线，L4 是产品能不能被信赖的分界。
   L1 拿 100% 不值得高兴，L3/L4 才是要看的地方。
2. **判据词取自「判分规则」列的『』引号，检索判据与答案判据分开**。
   混用会让 L3 整层 recall 从 100% 被压成 17%（详见 `eval/README.md` 第三节）。
3. **答案层判分靠应用强制输出的【引用清单】**，不靠扫正文 —— 扫正文的误报率是 3/4，
   因为拒答时本来就要点名那部不存在的法规。清单方案误报 0。

### 2.1 最关键的一条：L3-01 答「有效」

```
Q  《中华人民共和国噪声污染防治法》现在还有效吗？
A  结论：**有效**。该法自 2022 年 6 月 5 日起施行，本次检索结果中没有任何显示其已被废止或失效的内容。
   依据：
   - 【《中华人民共和国噪声污染防治法》第九十条】「本法自2022年6月5日起施行。《中华人民共和国环境噪声污染防治法》同时废止。」
     （该条文说明本法的施行日期，并明确被废止的是此前的《中华人民共和国环境噪声污染防治法》，而非本法本身。）
```

模型**推理过程完全正确、引用完全准确、结论完全错误**。这不是幻觉 —— 它老实地说
「检索结果中没有任何显示其已被废止的内容」，而这话是真的：噪声法的废止事实存在于
台账的
元数据里（废止日期 2026-08-15，废止依据《生态环境法典》），**法条正文里一个字都没有**。

同类：L3-03（问土壤污染防治法还能不能引用）答「**可以**」，同样错误。

**这条是整轮评估最值钱的产出。** 它证明了两件事：

- 「不编造」和「判时效」是两个独立能力，前者做到了不等于后者也做到了；
- **时效事实如果只落在元数据里而不进上下文，检索型系统在结构上就不可能答对。**
  这不是提示词写得不好，是信息没有被送进模型的视野。产品必须有一条不依赖检索的
  结构化事实通道。

### 2.2 L3-05：一次教科书级的跨法规串台

```
Q  《呼伦贝尔市城市市容和环境卫生管理条例》的施行日期是哪一天？
A  本次检索结果中同时出现两个不同的施行日期，无法确定唯一答案。
   - 【《呼伦贝尔市城市市容和环境卫生管理条例》第四十八条】「本条例自2022年5月1日起施行。」
   - 【《呼伦贝尔市城市市容和环境卫生管理条例》第六十六条】「本条例自2014年3月1日起施行。」
```

正确答案是 **2017-03-01**（该条例第五十条）。它引的两条：

- **呼伦贝尔只有 50 条**，第四十八条是罚则、第六十六条根本不存在；
- 2022-05-01 是**葫芦岛**条例的施行日期（葫芦岛第四十八条），
  2014-03-01 是**深圳**条例的施行日期（深圳第六十六条）——
  这两部法规恰好都在同一批召回结果里。

所以这是「把甲法规的条文挂到乙法规名下」，**语言上完全通顺、引用格式完全合法、人眼基本抓不住**。
它被自动判分抓到了，靠的是「条号必须能在召回段落里反查到」这条判据。

### 2.3 L2-02：同一答案里两处编造，自动判分只抓到一处

```
Q  怀化市对散装、流体物料运输途中造成遗撒的，城市规划区内和规划区外的处罚主体有何不同？
A  ...
   - 【《怀化市扬尘污染防治条例》第三十二条】「在城市道路上运输煤炭、垃圾、渣土…应当采取密闭…」
   - （补充说明）本次检索结果中另有第四十七条第（四）项，规定「…带泥运行的，责令改正，处200元以上500元以下罚款」
```

两处都不成立：

- 它引的「第三十二条」原文其实是**呼伦贝尔第三十二条**（怀化第三十二条是处分条款）；
- 怀化只有 34 条，**第四十七条不存在**。

自动判分抓到了第一处（清单登记了 `怀化|第三十二条`，条号在该文档召回段落里查不到）。
第二处**没抓到** —— 语料里确实有「第四十七条」这个字符串（在呼伦贝尔的段落里），
所以「条号是否出现在召回文本中」这条判据无法识别主体归错。这一条是人工核验出来的。

→ 判分盲区记录在 `eval/README.md` 第五节。**知道自己的自动指标漏了什么，比指标多高更重要。**

## 三、v2：把时效台账注入提示词

### 3.1 为什么改这里

L3-01/L3-03 的失败指出一个结构性缺陷：**时效是结构化事实，却被当成了检索内容。**
把 8 份文件的效力位阶、时效性、施行/失效日期、失效原因写进系统提示词
（`prompts/system-v2.md` 第一节），并明确它是「唯一权威时效口径」，
同时点破那个陷阱：

> 法条正文里写的「自 XXXX 年 X 月 X 日起施行」只是施行日期，**不能据此推断该法仍有效**。

### 3.2 结果：实质正确率 2/6 → 6/6，但指标打架了

**L3 判据词命中 40% → 80%，时效提示 17% → 67%，账台注入是有效的。**

```
Q  《中华人民共和国噪声污染防治法》现在还有效吗？
A  ⚠ 时效提示：《中华人民共和国噪声污染防治法》已于 2026-08-15 失效（《中华人民共和国生态环境法典》2026-08-15 施行），
   以下内容仅作历史参考。
   结论：该法现已失效，不再有效。
```

L3-05 也答对了（2017-03-01），并且**主动指出**它召回到的两处施行日期表述「与台账登记不一致、
存在明显异常，不宜作为施行日期的依据」—— 模型自己识别出了上一轮骗过它的串台内容。

### 3.3 但真编造率从 7% 涨到 13%，逐条拆开看

4 条里有 2 条是**误报**：

```
L2-08 [fabricated] 全国人大常委会关于授权国务院在中国（海南）自由贸易试验区暂时调整适用有关法律规定的决定|无条号
L3-02 [fabricated] 同上|无
```

原因：台账里我写的是法规**正式全称**，而知识库里的文档名叫「**海南决定**」。
模型按台账的名称写引用清单，反查时自然对不上。
—— 这是**命名口径不一致**，不是编造。但它是个真问题：**引用可追溯这一层会被名字口径全线击穿。**

另 2 条里：

- `L3-05` 答对了，但把两条它自己判定为「不宜作为依据」的条文仍登记进引用清单 → 清单登记的忠实性问题
- `L2-02` 的老问题（第三十二条串台）依旧

### 3.4 这一轮的结论

**指标变差 ≠ 做得更差。** v2 修好了 L3（最严重的失效），同时把两个此前被遮掩的工程缺陷
顶到台面上：文档命名口径、清单登记忠实性。如果只看「真编造 7% → 13%」就回退 v2 改动，
就会把真正重要的修复一起扔掉。**分层看指标、必要时人工核验，是这一步唯一正确的读法。**

## 四、v3：语料规范化——文档用正式全称，每段自带法规名

### 4.1 改了两处

缺陷都是实测出来的，不是猜的：

**缺陷 1 · 切分段没有身份。** 原入库文本是「标题一行 + 每个第X条一行」，
Dify 分段标识符设为换行后，**每个条文段里只剩条号、没有法规名**。
基线里模型多次说「该段文字未标明所属法规名称」「检索结果中的条文均出自一部**名称未显示**的
地方性法规」—— 然后开始靠猜。L3-05 的串台就是这么发生的。

**缺陷 2 · 文档名与法规全称不一致。** 「海南决定.txt」vs 正式全称；「噪声污染防治法.txt」
vs《中华人民共和国噪声污染防治法》。引用反查因此全线误报。

改法（`scripts/build_kb_text_v2.py`）：

```
文件名  = 法规正式全称
每段前缀 = 《法规正式全称》第X条
表格型文件（海南决定）无条号，前缀退化为 《全称》〔授权目录第N项〕
```

### 4.2 检索层：recall@1 从 77% 到 92%

```

政策法规语料库    合计      26     77%     96%    100%
政策法规语料库v2  合计      26     92%    100%    100%
```

拆开看更清楚：v2 库里 **L1 @1 92%、L2 @1 88%、L3 @1 100%，而且全部题目的命中都在前 3 位**。
给每段带上法规名之后，检索不仅没被同法规内的重复词稀释，反而更稳了 ——
这个副作用是必须要实测的，凭感觉会得出相反结论。

## 五、三轮迭代的可迁移结论

**1. 「元数据里的法规」和「库里有全文的法规」必须在系统里显式分开。**
产品里有一处不经意的设计会致命：因为台账/元数据里出现了《生态环境法典》，模型就会
认为它在库里。语料本身帮不了你 —— 怀化第一条、葫芦岛第一条都把法典写进了「制定依据」。
必须显式编码「被引用 ≠ 在库」。

**2. 时效是结构化事实，不能放在检索通道里。**
检索是「按相似度找回相关文本」，时效是「某个对象的一个字段」。
把字段塞进检索，就必然出现 v1 那种「推理正确、引用准确、结论全错」的回答。
台账必须在每次请求里无条件进入上下文，不参与召回竞争。

**3. 切分段的引用归属要自带，不能靠元数据。**
只要切分段的正文里没有法规名，模型判归属就只能靠猜，而猜错的输出在语言上完全合格。
这属于「不测就发现不了」的缺陷 —— 它在任何肉眼抽查里都表现为一段通顺的好回答。

**4. 让模型输出机器可读的引用清单，同时满足产品与评测两个需求。**
「可溯源引用」是产品的核心交付物，而它的载体恰好就是评测需要的判分依据。
这是本轮唯一一处产品需求和测试需求天然重合的地方，应该继续往这个方向设计。

**5. 相似度不能作为「有没有依据」的判据 —— 而且把系统调好之后，这个结论更强了。**
修复检索配置（`research/03`）之后，最能骗过检索的对抗题 top1 相似度反而更高
（0.739，比 81% 的正确题还高）。所以「显式引用存在性检查 + 条号越界校验」不是优化项，是唯一可行路径。

## 六、还没解决的

| 事项 | 状态 | 说明 |
|---|---|---|
| 引文级比对 | 未做 | 清单级只能保证「法规+条号存在」，保证不了「引述文字与原文一致」。v1 的 L3-06 就引了真实存在的第四十三条但文字超出原文 |
| 跨法规条号挪用的自动识别 | 未做 | L2-02 的「第四十七条」是人工核验发现的；需要「条号 → 所属文档」的联合判据 |
| L4-01 判据词未命中 | 观察项 | L4 层的『』判据词偏长（'条号不存在/超出条例条数范围'），L4-01 答「无法给出条文原文和条号」意思对但词面不符。属判分器措辞问题，不影响结论 |
| L1/L2 的「时效提示」误报 | 观察项 | v3 里 L1 25%、L2 12% 的答案带时效声明，读了两条是模型保守加上的「该条例时效状态需核实」。台账已给结论，说明提示词里还可以再压一句 |
