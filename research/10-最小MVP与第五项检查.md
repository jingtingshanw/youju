# 10 · 最小 MVP，与换模型暴露出来的第五项检查

日期：2026-10-14
产物：`mvp/server.py`、`mvp/index.html`、`mvp/README.md`，以及 `gatekeeper.py` 的 C5

---

## 1. 为什么要做这一个 MVP

到 `research/09` 为止，这套东西已经能跑：Dify 0.15.3（10 个容器）负责检索与生成，
`scripts/gatekeeper.py` 负责校验，`scripts/ask.py` 是命令行入口，`demo/index.html` 是演示页。

但它有一个不好用的地方：**换一台机器就跑不起来**。要装 Docker、拉起 10 个容器、建知识库、
建应用、配 10 个模型的凭据。给谁看都得先花两小时装环境。

而产品的核心主张其实很短——「模型给的条号，机器能逐条核对；核不过就别给结论」。
验证这个主张不需要向量检索，也不需要 Dify。所以把它剥出来，做成一个不依赖任何
外部服务的最小版本，是很直白的一步。

`mvp/` 的定位就是：**能拷走、能当场跑起来看效果**。

---

## 2. 形态决策：换掉检索层，判定层一行不改

MVP 与完整版的差别只有一处：

| | 完整版 | MVP |
|---|---|---|
| 检索 | 向量召回 + rerank | 本地 BM25 |
| 生成 | Dify 应用 | 直连 OpenAI 兼容接口 |
| 校验 | `scripts/gatekeeper.py` | **同一份代码** |
| 提示词 | `prompts/system-v3.md` | **同一份文件** |

实现上，`mvp/server.py` 把模型输出包装成 Dify 的形状，交给 `scripts/ask.py` 里那个在
66 题评估上验证过的 `analyze()`：

```python
resp = {"answer": raw,
        "metadata": {"retriever_resources": [
            {"document_name": c["law"], "content": f"《{c['law']}》{c['art']}　{c['text']}"}
            for c in hits]}}
rec = askmod.analyze(question, resp)
```

**不写第二套判定实现**，理由是项目里已经吃过一次同源分歧的苦：
`eval_run_app.py` 与 `gatekeeper.py` 曾各自实现名称归一与条号解析，
于是同一道题在「评测」和「上线」两处得到不同结论。判定层只能有一份。

## 3. 检索层的三次修正

MVP 唯一退化的部件就是检索。它是用实测逼出来的，改了三轮。

### 3.1 法规名拼进文档

打分对象是「一条一款」的文本。第一版只用条文正文建索引，于是「怀化市……几日内清扫完毕」
这类问题里，条文正文根本没有「怀化」二字，法规路由完全靠不住。

把**法规全称也拼进每条的 gram 集合**后，「怀化」这两个字会为怀化条例的每一条贡献分数——
等于做了一次免费的法规路由。另外，问题里用书名号或全称点名的法规，其条款整体 ×1.6。

### 3.2 打分公式：`Σ idf / sqrt(len)` → BM25

第一版用「idf 求和再除以长度的平方根」。L1-01（问怀化扬尘的监督管理部门）**排在第一位的是
第七条，不是正确答案第五条**：

- 第五条约 500 字，含「实施统一监督管理」，命中 12 个 query gram；
- 第七条约 60 字，只命中 8 个 gram，但短得多。

`/sqrt(len)` 把长文档惩罚得过狠。换成标准 BM25（k1=1.2, b=0.75）之后，长度归一改成
相对平均长度，第五条那几条**词频高**的 gram（「扬尘」「污染防治」在条内反复出现）
可以靠 tf 饱和把分数拉回来。

改完 L1 从 0/9 变成 9/9。

### 3.3 一个整份文件在检索层不存在

`--probe` 第一版报告「416 条款 / **7 部法规**」——而语料是 8 部。

原因是《全国人大常委会关于授权国务院在中国（海南）自由贸易试验区暂时调整适用有关法律
规定的决定》没有「第X条」这种体例，它的正文按「〔授权目录第N项〕」组织：

```
《决定名》〔授权目录第1项〕 1 ｜ 《中华人民共和国土地管理法》 第三十五条第一款 ……
```

切分正则只认 `《法规名》第X条`，于是**整份文件在检索层凭空消失**，L2-08
（问海南自贸区的土地征收审批权）必错，而且错得没有提示——模型会拿库里其他法规的内容去凑。

补一条兜底正则（`BLOCK_LINE_RE`，认 `〔…〕` 标记）后变成 419 条款 / 8 部法规。
`--probe` 现在会拿语料条数与 manifest 对账，把这类「文件级消失」直接报出来。

**顺带修掉一次度量错误**：最初用「判据词整串是否出现在召回文本里」衡量召回，
结果 L2-04、L2-05 被判失败——而语料原文写的是「应当要求**予以**改正」
「公告应当张贴在**拟拆除违法建筑物…设施的**显著位置」，判据词是简写。检索明明是对的，
差点因此去动 BM25 参数。改成「含答案的那一条有没有进 top-k」之后就没有这种假阴性了。

## 4. 换模型暴露出来的第五类失败

### 4.1 现象

MVP 用 `qwen-plus` 直连。跑对抗题 L4-05（问库外的《城市市容和环境卫生管理条例》对户外广告
的规定）时，结果是这样的：

```
判定 可作答（model｜模型自报 可作答）
引用 《呼伦贝尔市城市市容和环境卫生管理条例》第十七条=ok、第十九条=ok、第二十一条=ok …
```

模型把**库内另一部主题相近的法规**（呼伦贝尔条例也管户外广告、牌匾标识）当成了用户问的那部，
自报「引用法规在库内：有全文」，结论「可作答」。C1–C4 全部通过。

对照完整版：同一道题在 Dify 链路上，模型自报「不在库内 / 拒答」，判定正确。

### 4.2 为什么 C1–C4 拦不住

C1–C4 检查的都是**「模型自报的四行字段彼此是否自洽」**：

- C4 会说：「你填了『仅被提及』却填『可作答』，这两个不兼容」；
- 但如果模型填的是「有全文」，四行是自洽的 —— C4 无从开口。

**查自洽查不出填错。** 这是【边界判定】字段这个解法本身的边界：
它把「让程序猜模型想干什么」换成了「让模型登记事实，程序核对」，
可如果登记的事实本身就是假的，程序仍然只能照单全收。

### 4.3 解法：把「问题里写着的事实」拉进来对齐

「用户点名的是哪部法规」这件事，**问题本身就写着**，不需要模型来告诉我们。
于是：

```
问题里用书名号点名的法规 ──match_law──► 库内没有它的全文
                                        ＋
                              模型自报「引用法规在库内：有全文」
                                        ↓
                                    矛盾 → 拦截
```

两个都是客观事实，中间不需要任何语义判断。与最初用【引用清单】替掉正文正则、
用【边界判定】替掉拒答 marker 是同一个解法：**能核对就不要猜**。

实现为 C5「所问法规划界」（`BLOCK` 级，触发即拒答），并在提交前确认了简称匹配的行为：

| 输入 | 结果 |
|---|---|
| 噪声污染防治法（简称） | → 中华人民共和国噪声污染防治法 ✓ 不误报 |
| 城市市容和环境卫生管理条例（库外） | → None ✓ |
| 环境噪声污染防治法（库外旧法） | → None ✓（**不会**误撞库内的噪声法，这个坑在 `research/08` 里修过） |

### 4.4 影响评估：0 题触发

补进 `gatekeeper.py` 之后，先在完整版的 66 题结果上做离线核算：

- 「问题点名库外法规 + 自报有全文」→ **0 题**（完整版模型从没犯过这个错）；
- 「问题点名库外法规」共 23 题，模型自报全部是「仅被提及」或「不在库内」，都是正确的。

所以加 C5 对既有指标零影响，可以在 `--rejudge` 上逐字节验证：

```
66 题各项指标与基线逐字节一致
规则判定与模型自报仍然 66/66 一致
闸门 2 自检 11/11
```

**它的价值恰恰在换模型之后才显现**——这正是「不该把硬约束只写在提示词里」的实证：
约束的可靠性不该跟模型绑死。C5 现在同时是闸门 2 的第五项检查、
以及一条自检用例（「问库外法规、答成库内另一部 → 拦截」）。

## 5. 前端与接口上踩的两个坑

两个都是「只有真的打开页面才会发现」的类型，记下来是因为它们暴露的是验证方式的漏洞。

**一 · `self.path in ("/", "/index.html")`**
给页面加了 `?q=问题`（打开链接就自动提问，方便把一次问答发出去）之后，
截图回来的页面内容是 `{"error":"not found"}` —— `self.path` 是含查询串的原始值，
`/?q=…` 不等于 `/`，直接落到 404。用 `urlparse(self.path).path` 取路径再比对。

**二 · `level` 的大小写**
`gatekeeper.py` 里 `BLOCK = "block"`（小写）。前端按大写匹配：

```js
const LV = {BLOCK:"block", WARN:"warn", INFO:"info"};   // LV["block"] === undefined
```

结果**最该被看见的那个标签「拦截」落回了灰色的「记录」**——页面上完全看不出是哪一项
把结论拦下来的。改成 `String(c.level).toLowerCase()` 之后恢复正常。

两个坑都不是逻辑错误，而是「约定在传递过程中丢了」：一个丢在 URL 解析，
一个丢在大小写。所以凡是跨语言/跨文件传枚举值的地方，都在代码里留了注释说明取值。

## 6. 结论

- **MVP 的关键指标**：检索 top-8 召回 L1+L2 **15/15**（top-3 为 14/15）；闸门 2 自检 **11/11**；
  五类真实问答（可作答／部分作答／拒答／条号越界／问库外法规）判定全部正确。
- **对完整版零影响**：66 题指标逐字节未变。
- **形态**：`mvp/` 两个文件 + `scripts/` 三个模块 + `prompts/system-v3.md` + `data/` 四份数据，
  约 400 KB，零第三方依赖，`python mvp/server.py` 一条命令起来。

仍然没解决的：

1. **校验层仍未被强制接入应用链路**（PRD 第 6 节待办 1）。现在靠「业务系统只允许调外层服务」
   这个调用约定，约定可以被绕过。
2. **C5 只覆盖了一类「自报字段填错」**。其它类型（例如模型把库内法规 A 的内容说成法规 B 的，
   而问题里两部都没点名）仍然漏过。要覆盖它需要另一条客观判据，目前没有。
3. **时效台账仍是人工维护的**，且提示词里的台账段落还是手写（PRD 待办 2）。
