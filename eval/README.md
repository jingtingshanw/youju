# 评估集设计说明

日期：2026-10-14　文件：`eval/golden-set.csv`（66 条）　生成器：`scripts/build_eval_set.py`

---

## 一、两个用途，分开成两张表

```
用途        名称      分层      条数   考什么                     样本量由什么决定
──────────  ────────  ────────  ─────  ────────────────────────  ──────────────────
答得对不对  能力集    L1 基础     12   单点事实检索               业务分布（40%）
                      L2 推理      8   要拼两处以上信息 / 读表格   业务分布（25%）
                      L3 边界      6   时效 / 废止 / 引用≠全文     业务分布（20%）
──────────  ────────  ────────  ─────  ────────────────────────  ──────────────────
该不该答    防火墙集  L4 对抗     40   库里根本没有，敢不敢说不知道  分布需要（每类形态 5 道）
```

**为什么 L4 不遵守 15% 的占比。**

L1–L3 和 L4 的用途不同。L1–L3 考「答得对不对」，样本量要按业务分布设计——基础事实问得最多，边界情况问得最少。L4 考「该不该答」，它的用途是**标定拒答阈值**，需要的是把分数分布打实：每一类形态都要有足够样本，样本量由「分布需要」决定，不由「业务频率」决定。

混在一个占比里，就会用「业务上少见的题不该多出」这种理由，把标定阈值最需要的样本压掉。所以现在分开成两张表，报告里也分开。

（这条修正是 2026-10-14 做的，见 `research/07`。此前 L4 只有 4 道，与 L1–L3 按 40/25/20/15 配比。）

## 二、L1 是及格线，L4 才是分界

四层不是一条水平线。L1 的 100% 不值得高兴——它只证明「库能用」。真正决定产品能不能被信赖的是 L3（时效处理）和 L4（不编造）。

## 三、题目来源：每一条都锚定在真实条款上

出题不是凭想象写的。`build_eval_set.py` 在生成 CSV 时**强制校验**两件事，任一不过就报错：

### 校验 1 · 来源条款必须真实存在

「来源」列里的条款必须能在 `data/corpus.json` 里反查到，否则报错退出。

这条校验不是形式主义。L4 的越界条号题如果出题时把条号写成库里存在的，题目就会从「对抗题」变成「正常题」，整层的意义就没了。

### 校验 2 · 结构断言（2026-10-14 新增）

每道 L4 题除了文本，还挂一条断言，验证**这道题在结构上真的成立**：

```
law_absent        该法规名在语料全文里出现 0 次            → B 纯外部 / G 跨层级
law_referenced    该法规名在语料里出现过（被引用）          → A 被引用但无全文
art_out_of_range  该条号 > 该法规实际条数（真的越界）       → C 越界条号
topic_absent      该主题词在该法规全文里 0 次出现           → E 主题错位 / H 虚构制度
law_expired       该法规在时效台账里是废止/失效状态         → F 时效陷阱
excerpt_in        该节选关键词确实在承载文件里              → D 转述性节选
```

它上线第一次跑就抓到了 3 条写错的题：

```
[x] L4-36 断言失败：虚构术语『专项资金』在 ['土壤污染防治法'] 中出现，题目不成立
[x] L4-38 断言失败：虚构术语『奖励』在 [5 部法规] 中出现，题目不成立
[x] L4-39 断言失败：虚构术语『门票』在 ['昌吉…天山天池…条例'] 中出现
```

L4-39 尤其说明问题：我本以为风景名胜区条例里不会有「门票」，结果它有（第二十一条禁止行为里的「逃票、违规销售门票」）——换成更精确的「门票价格」才成立。

**40 道题靠人肉检查一定会漏，断言让这个失效模式不可用。**

### 校验 3 · 期望边界答案键（2026-10-14 新增）

`golden-set.csv` 新增「期望边界」列，取值与 `prompts/system-v3.md` 的枚举一致：`可作答 / 部分作答 / 拒答`。

它回答的是「**这道题的正确答案，在【边界判定】第四行应当填什么**」。按对抗形态给键（见 `build_eval_set.py` 的 `BOUNDARY_BY_FORM`）：

```
A/B/D/E/G/H  拒答              话题整个不在库里，只能拒答
C            拒答|部分作答      指出条号不存在，可附替代条款
F            拒答              为现在取可引用的条号，而法规已失效 → 必须拒答条号
```

**为什么需要它**：时效硬规则要求「为现在或将来的行为取依据、所依据法规已废止时必须拒答条号」。判分器怎么知道某道题属不属于这种情形？只能从答案键读。让判分器去猜题目意图，就是第三次犯「用代理指标代替语义判断」的错。

L1–L3 不设期望（格式为 `—`）：它们是能力题，正确答案是正常作答，不对其做边界判定检查。

## 四、「判分规则」列里的引号约定（跑分器能自动判分的前提）

```
『…』  判据词。会被 scripts/eval_run.py / eval_run_app.py 抽出来做机器判分。
       · L1/L2：判据词必须能在**召回的条文正文**里找到 —— 检索层判据
       · L3/L4：判据词必须能在**最终回答**里找到 —— 答案层判据
「…」  说明、反例、干扰项，不参与自动判分，只给人看。
```

**这条约定是踩坑之后加的。** 第一版把所有引号内容都当检索判据，结果：

- `L2-03` 因为写了「若答成『第二十四条的职责』即判错」，那个**干扰项**被当成必须命中的词 → 判为未命中
- `L3-01` 因为『已废止』这个**结论词**不在条文正文里 → 判为未命中

两条其实都召回了正确文档。L3 整层 recall 因此从 100% 被压到 17%，看起来像是「时效类问题检索不出来」，实际是判分器把两种不同性质的字符串混用了。

**检索判据和答案判据必须分开**，这是设计这条约定时唯一要记住的事。

## 五、L4 的 8 类形态（每类 5 道）

每类对应一种「不可能有依据」的**成因**，而不是一种问法：

| 类 | 形态 | 成因 | 例 | 分数能不能挡 |
|---|---|---|---|---|
| A | 被引用但库内无全文 | 法规名真实出现在库内制定依据里，但库里只有名字 | 《生态环境法典》第 215 条 | 部分能 |
| B | 纯外部法规 | 法规名在库内一次都没出现 | 《上海市生活垃圾管理条例》 | **能** |
| C | 越界条号 | 真法规 + 真主题 + 假条号 | 《深圳…监察条例》第八十条（仅 66 条） | **不能** |
| D | 转述性节选 | 库内有片段，但它是嵌在别处的「被调整对象」 | 《土地管理法》第四十六条第一款原文 | **不能** |
| E | 主题错位 | 真法规 + 该法规根本不涉及的主题 | 《深圳…监察条例》里的扬尘规定 | 多数能 |
| F | 时效陷阱 | 问已废止法规「现在怎么执行」 | 「依据噪声法处罚企业，引用第几条」 | **不能** |
| G | 跨层级混淆 | 问国家/省级规定，库内只有市/州级 | 《风景名胜区条例》对天山天池的要求 | 部分能 |
| H | 虚构制度 | 措辞合法，但库里没这套制度 | 怀化条例的「扬尘专项资金申请流程」 | 部分能 |

`research/07` 把 8 类按**机制**重排了一次，得到更干净的一刀：**话题在语料里是否存在**。B/E 大部分在「不存在」一侧（分数 0.13–0.35，分数挡得住），C/D/F 全部在「存在」一侧（分数 0.42–0.86，分数挡不住）。定产品规则要用后者。详见该报告第五节。

## 六、自动判分口径

两档跑分器，判的东西不同。

### 检索层 `scripts/eval_run.py`

- `recall@1/@3/@5`：期望来源文档（+ L1/L2 的判据词）是否落在前 k 条
- 指标 3：对抗题 top1 相似度 vs 正确题 top1 分布的分位对比 —— **本轮的翻转结论就出自这里**

### 答案层 `scripts/eval_run_app.py`

主口径来自应用最后一行强制输出的 **【引用清单】**（见 `prompts/system-v3.md`），v3 起另有 **【边界判定】** 四行字段：

| 指标 | 含义 | 性质 |
|---|---|---|
| 引用可追溯率 | 清单里每条 (法规名, 条号) 能否在本次召回段落里反查到 | 硬指标 |
| 无依据引用率 | 反查不到的条目（幻觉） | 硬指标 |
| 真编造 | 清单反查不到 + 正文无据条号 + 跨法规挪用 | 硬指标 |
| **L4 边界处理正确率** | 识别边界 且 无自相矛盾 且 无时效违规 且 命中答案键 | **硬指标（v3 起的主指标）** |
| 清单合规率 | 模型有没有按格式输出清单 | 硬指标 |
| 边界字段合规率 | 有没有按枚举填出【边界判定】四行 | 硬指标 |
| 判据词命中率 | 回答有没有答到点上（**只在 L1+L2 统计**） | 辅助 |
| 时效提示率 | L3 层是否给出时效状态声明 | 辅助 |
| **引文存疑** | 引述文字在召回段落里找不到 | **报告性，不判罚** |

> **L4 的主指标从「拒答正确率」改成了「边界处理正确率」**（2026-10-14）。旧口径只看"模型有没有拒答"，而 A/C/D/F/G 这类题的正解本来就是「指出问题 + 给出部分可用依据」，不该一律拒答——上一轮把 5 道完全正确的回答判成了失守。新口径分四项，缺一项就说明「嘴上认了、手上没认」。
>
> 同时保留「字面拒答（结论边界=拒答）」作为细分指标，因为它回答的是另一个问题：模型有没有明确说"没有依据"。

#### 为什么答案层判分要靠「引用清单」而不是扫正文

第一版判分器直接正则扫正文里的《法规名》，结果 **4 条完全正确的拒答回答里有 3 条被误判成「挂错法规」**——因为拒答时本来就要点名那部不存在的法规来说它不存在。

试过两轮改进都不成立：整句否定判定 → 误报 3/4；±28 字窗口 + 条号共现 → 误报 2/4。根因是**正文里「提到某法规」和「把某条内容挂到该法规名下」在用词上分不开**，任何正则都是在猜。

改成让模型**显式登记它实际依赖的条目**之后，判分从猜测变成了核对：误报 0，口径统一。而且这个清单本身是产品要交付的东西（可溯源引用的载体），不是为测试临时加的——测试需求正好和产品需求重合，这是这个方案唯一站得住的理由。

#### 判据词命中率为什么只在 L1+L2 统计

它在 L3/L4 上**系统性地骗人**：
- L4 的正确回答本来就该是拒答，不去命中任何答案键——把它的 0%/50% 读成缺陷，会去「修」一个不存在的问题；
- L3 问的是「还有效吗」，正确措辞和出题时写的答案键几乎不可能逐字对上（实测两条完全正确的回答都答出了「检索结果中没有该法典全文，无法给出」，因为和预设的『库中无法典全文』差几个字，被判未命中）。

把一个不适用的指标填成 0% 比不填更糟。所以 L3/L4 一律显示 `—`。

### 边界判定字段：第三次踩同一个坑之后的解法（2026-10-14）

**同一个坑踩了三次**，每次都是「拿一个不区分的代理指标代替语义判断」：

| 次序 | 代理指标 | 后果 |
|---|---|---|
| 1 | 扫正文正则判「挂错法规」 | 4 条正确拒答里 3 条误报 → 改用【引用清单】 |
| 2 | 用「清单是否为空」判「是否拒答」 | 6 条里 5 条误报 → 改用边界声明扫描 |
| 3 | 用「回答里有没有负面词」判「识别没识别边界」 | 把 L4-26 判成「已拒答」（正文含「已失效」二字），掩盖了真实失守 |

第三次的解法与前两次不同：**不再让判分器猜模型想干什么，而是让模型把客观事实显式登记出来，由程序机械核对。**

`prompts/system-v3.md` 要求模型在回答最前面输出四行：

```
【边界判定】
引用法规在库内：有全文 | 仅被提及 | 不在库内
所问条号核验：存在 | 不存在 | 未指定
时效状态：现行有效 | 已废止 | 已失效 | 未知
结论边界：可作答 | 部分作答 | 拒答
```

前三行都是**可核对的事实**，由它们可以**唯一推出**第四行应当是什么。判分器做两件不依赖任何语义猜测的事：

1. **内部一致性检查**：`仅被提及/不在库内` 或 `条号不存在` 或 `时效已废止/失效` ⇒ 结论边界**不得**是「可作答」。不一致即判不合格。
2. **对照答案键**：第四行必须落在 `golden-set.csv` 的「期望边界」里。

**外部真值**：`data/stale_ledger.json`（从 `manifest.verified.csv` 导出，`scripts/export_stale_ledger.py`）。模型自报的「时效状态」要与台账比对——**没有外部真值，模型只要自报「现行有效」就绕过了时效硬规则，自报自验等于没验。**

**三态 `expect_ok`**：`True` 命中 / `False` 不符 / `None` 无法核对。旧回答（v2 及更早）没有该字段，该维度**不参与**判定——否则旧配置会显示 0/40，新旧对照会失真。

**向后兼容**：字段缺失时，拒答判定回落到原有的 marker 扫描。所以 `--rejudge` 旧结果仍然可用。

#### 两次口径修正（均由首轮实测反馈而来）

**修正 1 · 枚举定义不够锐利**（首轮 66 题跑出 L4 只有 27/40）

13 道题全部填「部分作答」而答案键期望「拒答」。逐条读原文后确认：**行为全对、标签不同**。

```
L4-21  问《深圳…监察条例》对扬尘污染怎么规定
       答：该条例规范的是规划土地监察，扬尘不在其调整范围；库内另有怀化条例，
           但适用范围是怀化市，不能作为本问题的依据
       → 结论完全正确（它自己避开了"别的法规有相关规定"这个陷阱）
       → 却填了「部分作答」，因为"我给出了一些有用信息"
L4-16  问《土地管理法》某款原文
       答：库内无该法全文，该款只被海南决定的授权目录转引，无法以现行条文身份提供
       → 清单=无，【历史沿革】节用得非常规范 → 行为上就是拒答
       → 却填「部分作答」，因为"我指出了它在哪里被转引"
```

根因：「部分作答」的定义里**没有说明"部分"是相对于谁的部分**——模型理解成"我给了部分有用信息"，答案键理解成"用户问的那部法规里有部分可用内容"。

修法（改提示词，不改答案键）：把判据锚定在「**所问法规里**有没有回答这个问题所必需的条文」，并明确列出三种**属于拒答却容易被填成部分作答**的情形：①所问法规没有该内容但你给了别的相关法规；②你给的只是"它在别处被转引/被提及"这个事实；③你列出该法规的其他条款来**证明**它不涉及该主题。**重跑后这 13 道全部改判为「拒答」。**

**修正 2 · 法规名子串匹配**（时效自报错 3 条 → 1 条）

`short in query` 让「《中华人民共和国**环境**噪声污染防治法》（旧法）」命中了库内的「噪声污染防治法」（新法）——**旧法被读成新法**。原报 3 条，其中 L3-06、L4-29 是误报：它们填「未知」本来是对的（用户问的旧法不在台账里，回答也没依据库内文件）。

改用 `query_laws()`：**只认书名号里的名字，且要求与库内全称精确对应**。修后只剩 L3-04 一条，而它是**真问题**——它引用了怀化条例第一条的原文作为依据，按新规则「时效状态」该填怀化的"现行有效"，却填了"未知"。

> 这是「长名包含短名」这个坑的**第二次**出现（第一次在 `_law_hits`，当时用 `len(hits)==1` 兜住）。两次都说明：法规名的匹配必须**精确**，不能靠子串。

#### 一个模式：同一根源的第 4 次

| 次序 | 形态 | 表现 |
|---|---|---|
| 1 | 判分器猜意图 | 扫正文正则判挂错法规 → 误报 3/4 |
| 2 | 判分器猜意图 | 用「清单是否为空」判是否拒答 → 误报 5/6 |
| 3 | 判分器猜意图 | 用「正文有没有负面词」判识别没识别边界 → **掩盖真失守** |
| 4 | **枚举定义不够锐利** | 「部分作答」无参照物 → 模型与答案键对同一行为给出不同标签，13/40 |

前三次是"机器猜人"，第 4 次是"人和机器对同一个词的理解不同"。**共同的根源：判断标准里含有需要解释的成分。**

所以这套口径里凡是要紧的地方，判据都必须是**可核对的客观事实**（库里有没有全文 / 条号存不存在 / 法规还有没有效 / 文献里有没有这个词），而不是需要解释的评价词。

#### 第 5 次：同一个根源出现在产品校验层

判分口径收敛之后，同样的错在产品校验层（闸门 2，`scripts/gatekeeper.py`）又出现了一次 ——
形态是「**正文里出现了条号，就说明引用了这个条号**」。它不看语境，于是把两类句子当成引用：

```
L4-12  「该条例共 66 条，不存在第八十条」    → 被当成越界引用，C1 拦截
L3-02  「该决定暂调《海商法》第四条」        → 被当成库外法规引用，C2 拦截
```

**两道完全正确的回答被判成拒答。** 另有一处同源的假阳性：「一条可交付依据都没有 → 拒答」
把「《噪声污染防治法》还有效吗」这类**依据来自时效台账、本来就没有条号可引用**的
正确回答也误杀了（L3-01）。

三处修法与验收：
- 清单**明确写「无」**时，正文里的条号按**说明性引用**处理，不登记为交付依据；
  编造仍由 C2 的正文扫描与 C3 的时效硬规则照抓。
- 「没有条号」与「没有依据」分开判：**问题指向的库内法规都在台账里、且模型自报时效状态
  与台账逐字相同** → 按「部分作答」交付。
- 验收：`scripts/gatekeeper_sweep.py` 在 66 题上把**规则判定**与**模型自报**对照，
  修前三处分歧，修后 **66/66 一致**。

**这一节记的是同一句话的第 5 次**：判断标准里只要含有需要解释的成分
（"是否算引用""是否算有依据"），就一定会错。详见 `research/09`。

#### 第 6 次：换模型之后，模型自报的字段本身就是错的

前五次的根源是同一个：判据里含了需要解释的成分。第 6 次的形态不同 ——
**判据本身是对的，但它核对的那个"事实"是模型报给它的**。

做 `mvp/` 时把生成层从 Dify 换成直连 qwen-plus，同一道题的表现变了：

```
L4-05  问库外的《城市市容和环境卫生管理条例》对户外广告、牌匾标识的规定
       Dify 版：自报「不在库内 / 拒答」                              → 正确
       MVP 版：自报「有全文 / 可作答」，依据是库内另一部
               《呼伦贝尔市城市市容和环境卫生管理条例》              → 张冠李戴
```

**C1–C4 全部通过**。因为 C4 查的是「四行字段彼此是否自洽」，而模型填的「有全文」
让四行恰好自洽了 —— 查自洽查不出填错，这是【边界判定】字段这个解法本身的边界。

修法：补第五项检查 **C5 所问法规划界**，把「问题里书名号点名的那部法规在不在库内」
这个**问题本身写着的事实**，与「模型自报哪部法规在库内」对齐。两个都是客观的，
中间不需要语义判断 —— 与最初用【引用清单】替掉正文正则、用【边界判定】替掉拒答 marker
是同一个解法。

触发面：在 v7 的 66 题上离线核验为 **0 题**（完整版模型从没犯过这个错），
所以补入它对既有指标零影响（`--rejudge` 逐字节未变，规则判定仍 66/66 一致）。
它只在换模型之后才发挥作用 —— 这也说明硬约束不该只写在提示词里。详见 `research/10`。

## 七、判分盲区（2026-10-14：两个都已修复）
### 盲区一 · 跨法规主体归错 → 已修复，进硬指标

原判据「条号是否出现在任意召回段落里」抓不到 L2-02：它正文写了「本次检索结果中另有第四十七条第（四）项」，怀化只有 34 条——但「第四十七条」确实出现在同一批召回的**呼伦贝尔**段落里。

新逻辑 `prose_cross_doc`：逐行扫描，维护「当前讨论主体」= 最近一个只含唯一法规名的行；某行的条号不在当前主体的召回段落里、却存在于**别的**法规段落里 → 记「跨法规挪用」。

最后那个条件是刻意的：它把「主体归错」和「条号根本不存在」分开，后者归 `prose_unbacked` 管，两件事不重复计数。

### 盲区二 · 引文级比对 → 已实现，但**三批数据上零真阳性**

原判据只保证「法规 + 条号存在」，不保证「引述的文字与原文一致」。

新逻辑 `quote_unbacked_check` 分两步：

1. **按条号定位**：从召回段落里解析出「第X条 → 该条所在段落」，引述只在**该条号对应的段落**里找。这一步是抓到「条号挂错」的关键——只搜全部段落的话，别的条文的内容也会被当作「有依据」。
2. 配对用 **12 字滑动窗口**，容忍引述时的轻微改写（模型常做「对于市…」→「对市…」这类压缩）。

#### ⚠ 一处自我更正（2026-10-14）

本文档上一版把这个盲区的实例记为「v1 的 L3-06：登记的是真实存在的第四十三条，但引述的文字超出了该条原文」。

**这个说法是错的。** 回头核对 v1 和 v4 两批回答的原文：L3-06 把「夜间」的定义挂在 **第八十八条** 名下（该条确实是定义条款），把禁止性规定挂在第四十三条、罚则挂在第七十七条——**每一条的条号与引述内容都对得上，回答完全正确**。

所以真实情况是：**这个盲区在目前三批实测数据（v1 30 题 / v4 30 题 / v5 66 题）上都没有出现过真阳性。** 指标保留，作为语料扩大后的防线；但在现有语料上它没有战绩可展示。

上一版之所以写错：当时是用旧的「扫正文正则」判分器看到一条告警，没有回到回答原文去核对条号归属。**告警不等于问题**——这个教训在「跨法规主体归错」那一节也重复出现过一次（L2-02 那条倒是真的）。

**为什么不进 `hard_fab`**：模型合法的概括、省略（「…」）、跨条合并都会触发它。误报会导向去「修」一个不存在的问题。所以它是人工复核的线索，不是判罚项。
