# 发布与接入：GitHub / 云服务器 / 百炼 / 魔笔

> 文件名还叫「魔笔接入说明」是历史原因，内容已经扩到全部四种发布形态。
> 只关心某一节的话：GitHub → 九；上云 → 八；百炼插件 → 二；魔笔 → 三。

目标形态：**百炼做模型与编排，魔笔做界面，本地服务做证据层。**

服务本身不产生任何智能，它提供的是百炼给不了的东西：34,634 份带条号索引的政策正文、
67,541 条地方目录、178,386 条条文级索引、逐条核验过的引注。所以发布的关键不是
「把提示词搬上去」，而是**让百炼/魔笔能调到这三个接口**。

## 零、先想清楚「传到哪」——四种形态，只有一个适合这个项目

| 形态 | 你得到什么 | 代价 | 判断 |
|---|---|---|---|
| **GitHub 仓库** | 代码和文档公开可见，可被 clone | 数据不进库（2.8 GB），要挂 Release | ✅ **做这个**，求职展示的底座 |
| **一台云服务器跑起来** | 一个真的能用的网址 | 一年几百块 + 域名 + 备案 | ✅ **做这个**，这才是「发布」 |
| 百炼知识库（RAG） | 百炼里能建应用、发布 | **丢掉 C1—C5 核验、时效台账、条文级索引** | ❌ 等于把项目的价值层删掉换一个通用 RAG |
| 百炼自定义插件 | 别人的 Agent 能调你的检索 | **插件超时 5 秒**，报告类接口全部挂不上 | ⚠️ 只能挂检索，不能挂报告 |

**核心事实：百炼自定义插件的超时上限是 5 秒**（官方 FAQ 明确写「超时限制为 5 秒」）。
实测对照：

| 接口 | 实测耗时 | 能不能挂 5 秒的插件 |
|---|---|---|
| `/v1/health` | 0.003 s | ✅ |
| `/v1/coverage` | 1.06 s | ✅ |
| `/v1/gather`（只查库） | 约 1 s | ✅ |
| `/v1/plan` | 2—5 s | ⚠️ 临界 |
| `/v1/gather`（开联网） | 20—40 s | ❌ |
| `/v1/write` | 19—27 s（五题实测） | ❌ |

所以百炼插件能承载的是「检索 + 统计」，承载不了五段报告。**五段报告必须由你自己的
服务出、自己的界面展示**，百炼做不了这件事——这不是配置问题，是超时写死的。

真想上云，走第八节（云服务器）。想给别人的 Agent 用，把 `gather` 挂成插件就够了。

## 一、为什么是三个接口，不是一个

```
POST /v1/plan     问题 → 取证方向        约 2—5 秒
POST /v1/gather   方向 → 候选文件清单    库内 1 秒；开联网 20—40 秒
POST /v1/write    选中的文件 → 五段报告  17—60 秒
```

中间那一步（gather → write）**必须留给人**。

这不是偷懒。`gather` 返回的是 40—90 条候选，每条带「有没有正文、多少字、
是不是源端已标失效」。哪几条能当依据、哪几条只是线索，是这个产品最核心的判断，
交给模型自动挑就把产品做成了普通 RAG——而普通 RAG 恰恰是这个项目要解决的东西。

所以：
- 做「一句话问答」的轻应用 → 百炼里串三个工具，中间自动选
- 做「给规划师用的工具」 → 魔笔里三段页面，中间一屏候选清单让人勾

## 二、百炼侧：注册成自定义插件

百炼的「自定义插件」支持导入 OpenAPI 3.0 描述。

1. 把 `app/openapi.json` 里的 `servers` 改成你的公网地址
2. 控制台 → 插件 → 创建 → 导入 OpenAPI → 上传这个文件
3. 鉴权方式选「API Key」，位置选 Header，名字 `X-PV-Token`

导入后会得到 7 个可挂载的工具（`plan` / `gather` / `write` / `coverage` / `health` /
`jobs` / `jobsGet`）。**智能体里只勾 `plan`、`gather`、`coverage` 三个。**
`write` 挂上也调不通（5 秒超时），`jobs` 那两个挂了反而会让模型把 `running` 字符串
当成结果写进回复。报告在自己服务上出，百炼只负责"帮我找到文件"。

### 关键：百炼的工具超时等不了 write

**官方 FAQ 写的是「超时限制为 5 秒」。** 实测 `write` 19—27 秒，差四倍。
超时后**服务端已经跑完、结果丢了、token 也花了**，日志里还看不出是超时。

异步版本救不了这个问题——插件只调一次，模型拿不到 `job_id` 就不会再去调 `poll`；
就算挂上两个工具让模型自己轮询，5 秒内也只能问一次，拿到的是 `running`，
模型会把这个字符串当成答案写进回复。

所以：**`write` 不要挂成插件。** 挂 `plan` 和 `gather`，报告在自己服务上出。

异步接口留着是给魔笔和自建前端用的（轮询是它们的事，不是模型的事）：

```
POST /v1/jobs   {"op":"write", "q":..., "plan":..., "picked":[...]}
  → {"ok":true, "job_id":"jeb4c0db66e2542a9"}      ← 0.08 秒返回

GET  /v1/jobs/jeb4c0db66e2542a9
  → {"state":"running", "ms":8000}                  ← 每 2 秒问一次
  → {"state":"done", "ms":16777, "result":{...}}     ← result 与同步接口返回一致
```

`op` 取 `plan` / `gather` / `write`，其余参数与同步接口完全相同。
任务落 `data/app.db` 的 `job` 表，不在进程内存里——服务重启后 `job_id` 仍然查得到。
结果保留 1 天。进程被 kill 时停在 `running` 的任务，会在下次启动时改判 `interrupted`，
让轮询方拿到明确失败，而不是无限等待。

## 三、魔笔侧：OpenAPI 当数据源

魔笔的「数据源 → HTTP」可以导入同一份 `openapi.json`，每个 operationId 变成一个可
绑定的方法（`plan` / `gather` / `write` / `jobsStart` / `jobsGet` / `coverage`）。

### 页面结构（一个页面三个状态，不要做三个页面）

```
状态 A  输入
        一个输入框 + 检索范围三选一（只用知识库 / 库优先联网补漏 / 只用联网）
        → jobsStart {op:"plan", q}
        → 拿到 plan 后立刻 jobsStart {op:"gather", plan, scope}
        两次都是异步，进度条按 state 轮询

状态 B  候选清单
        按 plan.tasks 分组，每组一栏
        每行：勾选框 + 标题 + 标签（形态 / 正文字数 / 来源 / 时效）
        → 底部一个「生成报告」按钮，把勾中的条目组成 picked
        → jobsStart {op:"write", q, plan, picked}

状态 C  报告
        直接把 result.answer 当 markdown 渲染（五段结构：判断 / 依据 / 路径 / 缺口 / 下一步）
        顶部挂 result.verify.strength（可核 / 部分可核 / 需修正）
```

### 字段绑定表

`gather` 每条候选的关键字段，界面上一行要显示这些：

| 字段 | 含义 | 界面怎么用 |
| --- | --- | --- |
| `title` | 文件名 | 主文本 |
| `shape` | 形态：法律 / 条例 / 规章 / 办法 / 规定 / 规划 / 批复 / 通知 | 标签，颜色区分硬软 |
| `chars` | 正文正文字数 | `0` 显示「仅目录」，`<800` 显示「仅公告」 |
| `has_body` | 有没有正文 | 决定能不能勾去 write |
| `where` | `catalog` 库内 / `web` 联网现抓 | 来源标记 |
| `eff_hint` | `repealed` 表示源端标了失效 | 红色警示，且 write 会拿它当依据 |
| `score` | 排序分 | 只用于排序，不显示 |
| `bucket` | `strong` 正题命中 / `related` 沾边 | 灰显 related |

每个 task 上还有两个字段必须显示，它们是这个产品的诚实性所在：

- `n_usable`：**能引出条文**的条数（正文字数 ≥ 800）。`total` 是 19 而 `n_usable` 是 0
  时，列表再长也一条都用不上。
- `note`：这一栏为什么空、为什么不可用。为空字符串表示一切正常。

### 检索范围 `scope` 三档的取舍

| 值 | 行为 | 耗时 | 什么时候用 |
| --- | --- | --- | --- |
| `kb` | 只查本地库 | 约 1 秒 | 默认。南京、江苏、国家级问题够用 |
| `both` | 库优先，某方向有正文不足 3 份才联网补 | 10—40 秒 | 库外城市（广州等） |
| `web` | 完全不查库，只现抓政府站 | 20—40 秒 | 想验证库里没有的东西 |

`both` 不是「全方向都联网」——8 个方向各抓一轮要一分多钟，库内够用的方向再抓纯属浪费。

## 四、首页那几个数字不要写死

魔笔首页如果要显示「已收录多少份」，从 `GET /v1/coverage` 取，别在页面里写常量。
写死的数字一定会过期，而且过期后没人知道它过期了。

```json
{"fulltext": {"docs": 34634, "blocks": 300454, "articles": 178386,
              "by_region": {"上海市": 8903, "国家": 18608, "福建省": 2594,
                            "江苏省": 1585, "南京市": 1581, "昭通市": 1325}},
 "catalog": {"items": 67541, "regions": 1493},
 "efficacy": {"no_signal": 31937, "in_force": 1397, "repealed": 856,
              "expired": 343, "superseded": 81, "pending": 20}}
```

`efficacy` 那几个数尤其值得展示：`no_signal` 占 92%，意味着「全库里没有一份文件
点名废止它，原文也没写有效期」——这是我们能给出的最强时效保证，也只到这个程度。
`expired` 343 份是「有效期写到某天、已经过了」，这类**没有任何文件宣布它废**，
靠文件名和废止关系永远查不出来。

## 五、上线前必须补的四件事

### 1. 鉴权（已实现，默认关闭）

`.env` 里加一行就打开：

```
PV_TOKEN=一串足够长的随机字符
```

打开后 `/v1/*` 全部要带 `X-PV-Token` 或 `Authorization: Bearer`，
只有 `/v1/health` 免校验（给探活用）。

**不开的后果很直接**：`/v1/write` 一次跑 3200 token 的撰写，公网裸奔被人刷，
额度当天见底。

### 2. HTTPS（必须，不要省）

反代到本机，不要直接暴露服务端口：

```
nginx:  https://your-domain  →  proxy_pass http://127.0.0.1:8848
```

服务默认只监听 `127.0.0.1`，`PV_BIND` 可以改，但**不建议改**——
绕过反代就等于绕过 HTTPS 和限流。

魔笔和百炼都要求 https 回调地址（百炼的插件域名还要求在 ICP 备案的白名单里）。

### 3. 限流

服务本身没做限流。至少在最外层加一个：

```
limit_req_zone $binary_remote_addr zone=pv:10m rate=6r/m;
```

`write` 一次 17—60 秒、3200 token，一分钟 6 次已经是单机上限了。

### 4. 任务已经落库了（原来这是个坑）

`/v1/jobs` 的任务现在存在 `data/app.db` 的 `job` 表，不在进程内存里。
重启不丢、跨实例能读、被 kill 的僵尸任务会在启动时改判 `interrupted`。

**只剩一个限制**：`job` 表每天清一次（`_JOB_KEEP=86400`）。
一个用户一天跑不完 8,640 个任务，够了；真要长期留档，加个 `INSERT INTO archive SELECT` 即可。

## 八、上云：从「本地能跑」到「有个网址」

这一步是把 `DEPLOY.md` 的十节压成三句。完整版看那份。

### 机器选多大

| 项 | 建议 | 依据 |
|---|---|---|
| 规格 | 2 核 4 GB | 检索实测 52—190 ms，2 核够；`write` 是等模型，不吃 CPU |
| 磁盘 | 40 GB SSD 起 | 数据 2.8 GB + 系统 + 发布包解压临时占用 |
| 带宽 | 1—3 Mbps 够 | 返回的是文本（一份报告 4—5 KB），不传文件 |
| 系统 | Ubuntu 22.04 / Debian 12 | `DEPLOY.md` 的 systemd 和 Caddy 配置按这个写的 |

阿里云轻量应用服务器、ECS 都可以。**不要用函数计算 FC**：`kb.db` 是 2.26 GB 的本地
SQLite，FC 的临时存储上限和冷启动都不适合，而且每次冷启动要重新拉数据。

### 备案是硬卡点

用中国大陆的机器 + 域名对外提供 HTTPS，**必须 ICP 备案**，没备案域名解析过去也访问不了。
两条绕法：

1. 先用 `http://<公网IP>:8848` 直接访问，不绑域名 —— 能做演示，但百炼/魔笔的
   插件和回调都要求 HTTPS，挂不上。
2. 买中国香港或新加坡节点，免备案 —— 能绑域名上 HTTPS，但国内访问延迟 100—200 ms。

**只有「给别人的 Agent 调」这个场景才强制要求备案 + 域名。** 自己用、截图、录演示视频，
公网 IP 直连就够。

### 四步

```bash
# ① 本地打包含（先过自检，不过不产出）
python scripts/make_release.py

# ② 传上去
scp dist/pv-code-*.tar.gz dist/pv-data-*.tar.gz root@<ip>:/srv/

# ③ 机器上解开
cd /srv && tar -xzf pv-code-*.tar.gz && cd policy-verify-engine
tar -xzf ../pv-data-*.tar.gz
cp .env.example .env && vim .env        # 填一家模型 key + 设 PV_TOKEN
python3 scripts/selftest.py             # 必须 30/30

# ④ 起服务（systemd 和 Caddy 的配置在 DEPLOY.md 第五、六节）
sudo systemctl enable --now youju
curl https://<域名>/v1/health
```

**`.env` 放哪都行**：代码按「项目根 → 上一级 → 上两级」的顺序找第一个存在的。
以前的版本写死上两级，本地对、`/srv` 就变成读 `/.env`——症状是启动一切正常、
一调模型就报「没有可用的模型通道」。已经改了。

### 推

```bash
cd policy-verify-engine

# 用 HTTPS（简单，需要 PAT）
git remote add origin https://github.com/<你的用户名>/youju.git
git push -u origin main

# 或者用 SSH（配一次管很久）
ssh-keygen -t ed25519 -C "you@example.com"        # 一路回车

git push -u origin main
```

HTTPS 推送会要密码——**不是你的 GitHub 登录密码**，是 Personal Access Token：
GitHub → Settings → Developer settings → Personal access tokens → Tokens (classic) →
Generate new token → 勾 `repo` → 复制那串 `ghp_...`，密码位置粘贴它。

### 两个当场就会撞的坑

**1. 仓库名不要叫 `-`。** 建仓库时名字随便敲一个横线，得到的是
`github.com/用户名/-`。看着能用，实际上：

- clone 下来的目录叫 `-`，`cd -` 是 shell 的「回到上一个目录」，进不去，
  人会以为权限有问题
- 简历、README、任何 Markdown 链接里 `github.com/用户名/-` 都像断链
- 一堆工具处理这个路径会挂

改名在仓库 Settings → Repository name，GitHub 对旧地址做 301 重定向，
已有的 clone 和 remote 不会断（必要时 `git remote set-url` 一次）。

**2. 本地分支默认叫 `master`，GitHub 新仓库默认是 `main`。**
`git init` 时如果没指定，推送会得到「远端没有 main 分支」或推上去一个 master、
页面上看不到东西。先对齐：

```bash
git branch -m master main        # 本地改名
git push -u origin main
```

`dist/pv-data-20261026.tar.gz` 拖进附件区。

### 网络：代理要单独配给 git

`git push` 走的是 `github.com:443` 的 git 协议，浏览器能开网页不代表 git 能推。
这台机器上实测：网页 200，但 git 直接推是

```
fatal: unable to access '...': CONNECT tunnel failed, response 502
```

配一次就好（只写本仓库，不改全局）：

```bash
git config http.proxy http://127.0.0.1:9674
```

代理端口因客户端而异：Clash 系列常见 7890 / 7897，v2rayN 是 10809，
本机 mihomo 是 9674（用 `Get-NetTCPConnection -State Listen -OwningProcess <pid>`
查进程占了哪些端口）。换机器、换端口之后要重新配。

**排查顺序**：先 `curl -x http://127.0.0.1:<端口> -o /dev/null -w "%{http_code}" https://github.com`，
拿到 200 再谈 git；拿不到就是端口用错了或者代理没开规则。

### 推送失败的两个真实原因

**1. 包里有大文件 → HTTP 408。** 第一次推 14.4 MB 报 `RPC failed; HTTP 408`。
先怀疑网络，实际是 `eval/results/emb-v4-cache.json` 一个文件 9.7 MB，
占总体积三分之二。移出后 git 对象库从 14.4 MB 降到 1.40 MB，一次推成功。

**判断方法**：`git ls-tree -r -l HEAD | sort -k4 -n | tail -5` 看最大的几个对象。
超过 1 MB 的"数据文件"基本都是不该进仓库的。

**2. 分支名对不上。** 本地 `master`、远端 `main`，推上去页面上什么都没有。
`git branch -m master main` 一次解决。
