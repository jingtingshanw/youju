有据 · 优化方向（v1）

状态（2026-10-20）：本文写于 10-19，当时的背景是「省级 12/31、目录 1.9 万条」。

一天后库扩到「省级 21/31、地方目录 65,111 条、国家级全文 18,608 份」，但**本文的核心判断没有变，

而且被数据验证了**：目录层的误杀率确实可接受（0.5%），「276 → 3」的差额确实一半是重复。

现状数字见 [../prd/PRD-v4.md](../prd/PRD-v4.md) 与 data/catalog/export/覆盖报告.md。

依据：四份外部评估文档（市场评估 / 竞品增补 / C5 案例复盘 / 决策复盘）+ 2026-10-19 收录率审计实测

结论一句话：接受「把入口从检索翻到核验」，不接受「先访谈再写代码」，也不接受把目录层说成「降级」。

另外：四份文档反复提的那笔账（276 → 3），我核完了，结论和它们预期的都不一样。

0. 先说做了什么，再说判断

四份文档里有三条指向同一个动作：「276 条源端命中只收录 3 条」这件事没核，而它决定目录层能不能用。 我把它做成了可复跑的脚本而不是人工抽 20 条——因为人工抽一次，下次源站改版还得再抽一次。

**scripts/catalog/audit_source.py**，零依赖，每个站点都能跑：

python scripts/catalog/audit_source.py --source yingtan --topic 城市更新 --pages 23

0.1 核出来的数（鹰潭 × 城市更新，2026-10-19）

项数说明
源端自报命中276 条这个数不可信，见下
实际扫描到287 条自报 276，实际能翻出 287，多 11 条
去重后212 条75 条是重复（26%）：同一份文件挂多个栏目、被多次转载
其中真·本主题政策文件3 份与库里一致
被判「像文件却不是文件」14 条须人工过一遍
其中确认误杀1 条《支持城市更新的规划与土地政策指引（2023版）》印发
主题外的真文件43 条规划管理 / 土地管理 / 生态环境 / 财政资金——不是误杀
新闻、公示、报告、解读222 条应当剔除

误杀率 ≈ 0.5%（1 / 212）。

0.2 这个结果推翻了两件事

第一，目录层不该砍，但「不能漏」这个承诺必须撤。

0.5% 的误杀率意味着目录层是可用的。但 26% 的重复率意味着「源端命中 276 条」这句话本身就是假的—— 276 是命中条数，不是文件数。四份文档里的「276 → 3，收录率 1%」这个说法，分子分母都站不住。

这件事属于「状态诚实率」：不只是「没抓到要说没抓到」，数字的定义也要诚实。 以后报告里只能写「源端 287 条，去重 212 条，其中本主题文件 4 份」。

第二，两类误杀不是随机噪声，是可分类的 bug。

误杀形态例子根因
标题尾部粘文号…政府和社会资本合作新机制的通知国办函〔2023〕115号末尾是「号」，endswith("通知") 落空
转载形态「《X》印发」《支持城市更新的规划与土地政策指引（2023版）》印发末尾是「印发」，不是文件后缀

还有第三类，四份文档都没提，是我这次撞出来的：

问题例子后果
跨源去重失效同一份文件，国家级源带文号叫「关于印发《指引》的通知」，鹰潭站转载叫「《指引》印发」存成两条，一条挂「国家」、一条挂「鹰潭市」，同一份文件在两个行政层级各算一次

第三个最危险：它不会报错，只会让清单重复、条数虚高、效力状态分裂（一条有文号一条没有）。 修法是加第四条合并路径——用书名号里的文件名去撞，因为转载几乎一定保留原文件名。

三处都修了，自检从 26 项加到 30 项，全通过。

修完重抓，那条被误杀的《支持城市更新的规划与土地政策指引（2023版）》收进来了—— 但它没有变成一条新记录，而是并进了国家级源那条 自然资办发〔2023〕47号，sources 变成 govcn_bm,yingtan。这恰好说明一件事：

单源误杀 ≠ 全库漏收。 一份文件从 5 个源进来，丢掉 1 个源不影响它存在。

真正危险的是「只有这一个源有」的文件——地方性文件大多属于这一类。

所以误杀率这个指标要分两半看：国家级文件误杀几乎无害（多源兜底），地方级文件误杀是真损失。 这次那 1 条正好是国家级，实际损失为 0。但下一次不会这么巧，所以两个 bug 还是必须修。

0.3 剩下 13 条「像文件却不是文件」的，我认为判得对

它们是政府采购类公告、法治政府工作报告、机构职能表、征求意见稿、年度政府工作报告。 我自己给了一条新规矩：政府工作报告与规划纲要单列一类，不进政策清单——它们是可引用的背景材料，不是政策依据。混进来会让「这个方向有哪些文件」变糊。

1. 四份文档我接受的部分

建议我的判断它改变了哪个动作
全文零竞品分析，是唯一的结构性缺失接受，且是最重要的一条把竞品章节插进 PRD（见 §5）
FR-04 全稿自查从 P1 提到 P0接受，理由比文档给的更强见 §2.1
核验层（C1–C5）是唯一不可替代资产接受所有资源向判定层倾斜
「276 → 3」必须核接受已完成，见 §0
「未测」是待偿债务，不是中性状态接受每个「未测」后面必须跟负责人和日期
商业数据库导出物入库有数据库权风险接受补进 PRD §10.1

关于 FR-04，我要把理由说得更硬一点：

C1–C5 这五项检查，设计时的输入形态就是「一批引用」，而不是「一个自然语言问题」。 C1 要条号、C2 要引文、C3 要文件名、C4 要全称、C5 要「用户点名了哪部」—— 这五样东西在一份稿子里天然齐备，在一个提问里往往只有一两样。把它排在 P1，等于让引擎空转。

2. 我不同意 / 要修正的六处

2.1 「核验台」的核心前提没验，却被当成结论

整份翻转建立在一个假设上：送审被打回，常常是因为引用错。

四份文档自己承认没问过（访谈第 1 问就是「上一次送审被打回是因为什么」）。如果主因是方案与甲方意图不符、投资估算超限、指标算错，那引用核验解决的是低频问题，翻转就落空。

问题不在于这个假设大概率错——它可能对。问题在于它是假设，却被写成了结论，然后用结论去重排全部优先级。这和它们批评我的那个错误是同一类：在未验证的假设上加码。

替代动作：不做「先访谈再重构」，做「一天做一个能演示的核验，带着它去问」。见 §2.4。

2.2 翻转会让闸门从 5 项退到 3.5 项，这笔账没人算

这是四份文档最实质的遗漏。入口一换，五项检查的可用性全变：

检查查提问场景查稿件场景变化
C1 条号越界需要条数表需要解析过全文才有条数表依赖变重
C2 引文查不到需要原文同上依赖变重
C3 时效违规台账 8 部用户带来的文件通常不写效力状态，而省级源与 flk 都是 blocked大概率只能标「未核」
C4 名称错配可用可用（可从文件自身推）不变
C5 所问法规划界靠问题里的书名号稿件场景没有「问题」直接失效

所以翻转的实质不是「同一套能力换个场景」，是砍掉一项、弱化一项、另两项依赖变重。

必须写进新边界：核验台对外只承诺四项——存在性、条号、引文真实性、名称一致性；时效一律标「未核」，除非台账里有。 不写这条，就是拿 8 部法规的台账去承诺 320 万篇的时效——正是我在 PRD §7.5 里自己禁掉的那种事。

2.3 目录层不是「降到 P1」，是从产品功能里删掉

文档说 FR-01 → P1。我认为这个说法不够狠，也不够准。

只要它还挂在功能列表上，就还欠一句「这个方向的文件都在这」。而你做不到——省级 blocked、地市逐站适配。一个永远兑现不了的承诺，比没有这个功能更伤。

但只要不承诺「全」，它的输出立刻变成别的东西：候选池。装配专题库要它（该抓哪些文件），漏引检测要它（该引没引哪些）。这两件事都不需要「全」，只需要「足够好的候选」。

动作：撤销 FR-01 的对外承诺，保留全部代码，改写成 FR-02 的第 1 步「筛候选」。

这一改同时消掉两件麻烦：不用再解释省级为什么缺（它不是产品功能），目录层也不必背「不能漏」的 KPI。

2.4 「先访谈再写代码」太慢，而且访谈需要道具

文档说「在拿到外部反馈之前，不要再写代码」。我同意它的靶子（别在未验证的假设上加码），不同意它划的线。

线应该划在验证性代码和产品性代码之间：

类型例子该不该做
验证性代码200 行的「贴一条引用 → 出结论」页面该做，一天
产品性代码全稿自查完整版、埋点、导出、多用户不该做，等反馈

理由很实际：访谈质量取决于你手里有没有东西。 问「你会不会用这个工具」，答案永远是会；把三条核验结果摆在桌上问「这三条错的，你们现在怎么发现」，才有信息量。

三份文档都指望「3 个规划师访谈」来定方向，但没说访谈需要道具。道具就那 200 行。

2.5 漏引候选不需要向量检索

文档说漏引候选必须上向量（Ollama + bge-m3）。我不同意，至少第一步不需要。

漏引候选的本质是筛选 + 排序，不是语义发现：

候选 = 同地域链 ∩ 主题标签命中 ∩ 效力级别不高于稿件所需
排序 = BM25 词面分（标题 + 文号）

这些字段目录层全都有（region / topics / admin_level / title）。先不做向量，用 20 条人工看排序够不够；不够再上。省掉一个运行时依赖，也省掉「为什么本地要跑 Ollama」这个解释成本。

2.6 竞品对比的框架错了（这条最要紧）

四份文档的叙事是：你打不过 320 万篇，所以换战场。

这个框架的问题是，它接受了对方定义的战场，然后承认自己在那个战场上输了。而实际上：

北大法宝 / 威科 / 法信有据
回答的问题有哪些文件你引的这一条站不站得住
判据覆盖判定
赢的条件数据量规则完备
8 部 vs 320 万篇致命不进这个比较

这两个是不同的任务，不是一个任务的两种做法。 覆盖比不过，判定根本不需要覆盖。

这个改动的实际后果有两层：

  • 对内：你不会因为「库小」焦虑，也不会为了补库去啃那些啃不动的源。
  • 对外（尤其求职）：说「我选错了战场」，面试官会想「你下次还会选错」；说「检索和校验是两个任务，我选的是判定」，面试官会想「这人分得清」。

同一件事，两种叙述，专业判断力的评价完全不同。 而后者是准确的那个。

3. 修正后的路线：一个引擎，三个出口

                    ┌──────────────────────────┐
                    │  判定引擎（已有，不动）    │
                    │  C1–C5 + 判型 + 状态诚实  │
                    └────────────┬─────────────┘
                                 │
          ┌──────────────────────┼──────────────────────┐
          ▼                      ▼                      ▼
   ① 贴引用 → 出结论        ② 全稿 → 出自查报告      ③ 目录 → 出候选
      （演示 / 验证用）        （产品形态 / 有交付物）    （内部工序 / 不承诺）
      1 天可做                 1–2 周                  已在维护

三条出口共用同一份判定代码。这正是 PRD 里那条「判定层只能有一份实现」的延伸—— 出口可以有三个，判定只能有一份。

优先级：① → ② → ③ 维持现状。

4. 下一步（按「信息量 ÷ 成本」排序）

#动作成本停止判据状态
1收录率审计 + 三个 bug半天—✅ 已完成
2200 行演示：贴引用 → C1/C2/C4，时效标「未核」1 天跑不通说明判定层没解耦待做
33 名规划师访谈（带演示）2 周内少于 2 人认「送审前核验」是痛点 → 转作品集待做
4C2 升级为三级判定（逐字 / 归一后 / 未命中）3 天归一后命中率 < 80% → 说明比对算法要重做待做
530 题外部标注（2 名规划师）2 周引用可追溯率 < 95% → 判定层重做待做
6全稿自查 MVP + 报告导出1–2 周—待做

第 4 项要补一句设计：C2 不能做成二值判断。引用经常是概括、省略、跨条合并，二值判断会把大量正常引用判成「查不到」，误报率一高，整个产品就没人用了。 所以是三级：逐字命中 / 归一后命中 / 未命中，只有第三级才算问题，第二级在报告里标注「概括引用，建议核对原文」。

5. 与 PRD 的关系：暂不出 v4

理由：方向还没被外部验证，改 PRD 就是第三次返工。

现在只做两件不改方向的事：

  1. 插入 §0.3 竞品分析（纯增量，不随方向变化而失效）
  2. 关闭风险 R3（收录率已实测），补三条新风险（跨源重复、C3 在稿件场景失效、C5 不适用）
  3. §0.3.7 的「定位修订」标为待决策，不替换 §1.1 的定位

等访谈和演示有回音，再出 v4。那时候改定位才有依据。

6. 这四份文档共享的两个盲区

盲区一：都假设「引用错」是高频痛点，没人去验。 三份文档（市场评估 / 竞品增补 / 决策复盘）都把翻转建在这个前提上，而验证它的那一步（访谈第 1 问）在同一份文档里被列为「下一步」。结论先于证据。

盲区二：都假设翻转不损失能力。 没有一份算过 C3 和 C5 在稿件场景下的可用性。它们把「五项检查」当成一个整体搬过去，而实际上搬过去的只有三个半。

还有一件更微妙的事：竞品增补、C5 案例复盘、决策复盘这三份看起来是三种独立材料，其实是同一个视角在同一天写的，互相引用。读起来像三重印证，其实是一重。 如果哪天把它们当「三个来源的意见」往外说，会被追问穿。 它们真正的用途是：竞品那个当 PRD 章节用，C5 那个当面试材料用，决策复盘那个当「被问到最大问题」的答法用——各归各位，不要叠加成「多方评估」。

7. 一句话总结

四份文档最有力的一条是「竞品分析缺失」，最没根据的一条是「先访谈再写代码」，最危险的一条是「翻转不损失能力」。

我做的选择是：接受翻转的方向，但把它降级成待验证的假设；先把欠的账还了（已还），再用一天做一个能演示的东西去验它。
