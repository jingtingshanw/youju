卷首 · 一页速览

0.1 它做什么

用户问一条法规怎么规定，系统给出逐条可反查的引用、明确的效力状态（这部法还有没有效）、 以及在给不出依据时明确说给不出来。

它面向的场合有一个共同点：答案错了会有实际后果，而提问的人通常自己发现不了。 执法一线写处罚决定书、咨询机构做合规分析、研究者做条款比对，都属于这一类。

它不做三件事：

不做原因
不给法律意见只报告「库里有什么、哪些还有效」，不判断「你应该怎么做」
不做法规全文门户库内只有这 8 部；没有的地方一律说没有
不联网兜底检索不到就直说，静默去问别的来源等于把风险藏起来

0.2 从发现到交付：四段链路

真实的工作是从「有哪些文件」开始的
  │
  ▼  ⓪ 发现   按「地域 × 主题」把清单拉出来：本地 / 省 / 国家三级 + 跨领域
  │           ★ 目录层（2026-10 接入）：只存名单，不存全文
  │           输出：有什么、各是什么效力、哪一级是空的
  │
  ▼  ① 检索   把其中真正要引的 20–50 份全文入库 → 混合检索（关键词 + 向量）→ 重排序
  │
  ▼  ② 核验   ★ 两道闸门
  │           闸门 1（话题级）：检索分数过低 → 判定"库里没有这个话题"
  │           闸门 2（条文级）：条号越界 / 引用查不到 / 引用了已废止法规 → 拦截
  │
  ▼  ③ 交付   结论 + 逐条依据 + 时效状态 + 引用清单 + 结论强度

第 ⓪ 段是后补的，也是被使用者当面纠正过一次的地方。最初的版本把「文件已经在我手上」 当成前提，直接做检索——而真实场景里，规划师接一个项目的第一件事是弄清这个话题在三级 政府各有哪些文件（例如江西鹰潭的城市更新：鹰潭市的、江西省的、国务院与部委的，可能还要 带历史文化保护）。这一步没做，「库是空的」就等于「这个产品没用」。 目录层怎么解决、解决到什么程度，见 2.9。

第 ② 段是本项目与「普通 RAG 问答」的差别所在，也是投入最大的一步。 闸门 2 是一段不调用任何模型的确定性程序：它只做加减和字符串比对，因此结论可解释到 「第几条第几项不通过」，也可以写进服务承诺。

0.3 三种交付强度

每一次回答，最终都会落到三种强度之一。这是产品唯一的降级机制， 没有「置信度偏低但照常回答」这种中间状态。

强度什么时候给用户看到什么
可作答引用的每一条都能在本次检索结果里反查到，且所依据的法规现行有效结论 + 逐条依据 + 引用清单
部分作答依据可用但只能算参考（例如所问法规里只有部分条文相关、或只依据了已失效法规做历史说明）结论 + 明确写出缺什么、还要另外核验什么
拒答条号越界 / 引用查不到 / 为现在取依据而法规已失效 / 库里没有这个话题「本次检索结果中没有能支持该问题的条文」+ 说明检索到了什么、为什么不能作为依据

0.4 能信到什么程度

实测达到的（66 道题，其中 40 道是刻意设计的"库里不可能有答案"的对抗题）：

指标实测
引用可追溯（清单里每条都能在检索结果里反查到）100%
真编造（凭空造法名或条号）0%
引用已废止法规的条号当现行依据（时效违规）0 条
对抗题边界处理正确率40/40
边界判定字段合规率100%
产品校验层的规则判定与模型自报一致66/66
产品校验层的规则自检（不调模型）11/11

不能信的：

  • 库外法规的全文。8 部以外的法规一律没有全文，问它们只会得到「库里没有」。

    • 2026-10 接入目录层后，这种情况至少能给出名单（有哪些文件、什么效力级别、链接在哪）， 但「名单上有」不等于「能逐条引用」——要引用仍然得先把那份文件入库（见 2.9）。

  • 法律意见。它报告事实和效力状态，不给行动建议。
  • 语料规模。全部结论都建立在 8 部法规上。所有阈值都是在这个规模上量的，

    • 换语料必须重新标定（详见 2.9 与 3.6）。

  • 目录的完整性。目录层按源抓取，源抓不到的地方就是空的，而且空的会被明确标出来。

    • 当前省级（江西）与全国法规库（flk）都抓不到，靠人工清单补，而人工清单还是空的。

  • 未接业务系统。目前只能在本地运行，没有接入任何真实业务流程。
  • 没有真实用户验证。66 道题是自造的，出题人、判分人、被考核对象共用同一套假设。

    • 它能证明「实现与预期一致」，不能证明「真实场景里有人需要它」。

第一部分 · 给没有技术背景的读者

1.1 它解决什么问题

想象两个真实场景。

场景一：条号写错。 某地要引用《深圳经济特区规划土地监察条例》里关于强制拆除程序的规 定。这部条例里「强制拆除」确实是核心内容，所以任何检索工具都会把相关段落排在最前面。 但这部条例一共只有 66 条，而用户印象里是"第八十条"。

一个普通的问答系统会顺着用户的说法，把检索到的内容整理成"第八十条规定的程序是……"。 用户拿去写文书，被撤销。

本系统在这里做的事情很具体：查一张表，发现这部条例只有 66 条，于是明确告诉用户 「该条例不存在第八十条」，并说明它检索到了什么、用户可以往哪个方向继续找。

场景二：引用了已经废止的法规。 某企业夜间施工要处罚，执法人员想引用《中华人民共和国 噪声污染防治法》的罚则条款。这部法已经在 2026-08-15 被《中华人民共和国生态环境法典》取代。

一个普通的问答系统会答「处罚依据是该法第七十七条；但该法已失效，不宜再作为处罚决定书的 依据。」——前半句已经把条号交出去了，执法人员会直接拿后面那半句忽略掉。

本系统的规则是硬的：当用户要拿条文去办现在或将来的事、而这部法已经废止时， 必须拒绝给出条号，只回答「不存在可引用的现行依据」。 如果用户确实想知道这部法失效前是怎么规定的，信息会放在单独一节【历史沿革】里， 并且这一节的条号不会进入引用清单——排版本身就在提醒用户：这一节的条号不能用。

1.3 一条结果怎么读

以网页版为例，一次问答会给出这些内容：

判定徽章           可作答 / 部分作答 / 拒答，以及"由规则判定"还是"由模型自报"
                   ── 两者不一致时会说明采纳了哪一方，以及为什么
结论               一句话
依据（逐条核对）    每一条都标 ✓ 或 ✗，并写明依据来自引用清单还是正文
相关文件时效        问题涉及或回答引用的法规，各自现行有效 / 已废止 / 已失效
引用清单            法规全名 + 条号，一行一条。这是可以拿去核对、可以写进文书的凭据
模型自报的边界判定  模型自己登记的四个事实（下面 1.4 会解释为什么要有它）
五项确定性校验      条号越界 / 引用存在性 / 时效比对 / 边界判定一致性 / 所问法规划界，
                   各自标出「拦截 / 提示 / 通过」
判定理由            一句话说清这次为什么给出这个强度
原始回答            折叠起来，需要时可以展开看未经加工的完整输出

读法：先看判定徽章知道这次能用到什么程度，再看依据里有没有 ✗，最后需要写进文书时 用引用清单。

1.4 术语速查（大白话）

词大白话
切分段（chunk）把一篇长法规切成一段一段，方便按语义查找。8 部法规被切成 419 个条款（Dify 知识库侧另切成 435 段）
向量检索把文字转成一串数字，意思相近的段落数字也相近，于是能"按意思找"而不只是"按关键词找"
重排序（rerank）第一轮找出几十个候选后，用一个更精细的模型重新打分排序。本项目的实测结论是：它的价值在发现"这个话题库里根本没有"，而不在把答案排得更准
条号越界引用了某部法规里不存在的条款号。例：一部 66 条的条例被引用了"第80条"
时效台账一张表，记录每部法规现在还有没有效、失效日期、失效原因。它是外部真值：模型自己说"这部法有效"不作数，要跟这张表对
引用清单回答末尾的一小块结构化内容，逐行写「法规全名\第X条」，只登记真正用来支撑结论的条文
边界判定回答开头的一段固定格式：模型先登记四个客观事实（库里有没有全文、所问条号在不在、这部法还有效吗、结论边界该是哪档），程序再核对这四行自不自洽
幻觉模型一本正经地编出不存在的内容。本项目把「编造」限定为可核对的两类：清单里的引用在检索结果里查不到、正文里出现的条号在检索结果里根本不存在
闸门在回答交付给用户之前设的检查点。本项目有两道，一道看检索分数，一道做条文级校验
RAG「先检索资料、再让模型照着资料回答」这套做法的统称。本项目是 RAG 的一个特化版本，加了两道闸门和一套评测

2.3 两道闸门（本项目的核心设计）

系统在答案出口处设两道彼此独立的闸门：闸门 1 判「问题是否落在知识库范围内」（话题级）， 闸门 2 逐条核对「模型自报的引用是否属实、彼此是否自洽」（条文级）。两道都过才算交付。 下面先说为什么一道不够，再分别说每一道怎么判，最后说明闸门 2 目前挡得住什么、挡不住什么。

2.3.1 为什么必须是两道

最初的设计只有一道：用重排序的分数判断"有没有依据"——分数低就说检索不到。

这个做法在 4 道对抗题上看起来完全成立：对抗题最高 0.447，正确题最低 0.509， 中间有 0.062 的空档，一条阈值就能分开。

把对抗题从 4 道扩到 40 道之后，这个结论被推翻了。 同一个知识库、同一套配置， 只换题量：

形态n最低分中位最高分
正确题（L1+L2）200.5080.9260.949
C 越界条号50.3250.8260.860
D 转述性节选50.4470.6630.842
F 时效陷阱50.4200.5990.749
H 虚构制度50.3490.5280.822
G 跨层级混淆50.1690.2390.826
A 被引用但库内无全文50.1610.1960.727

B 纯外部法规50.1340.1430.158

C 类里有三道分数超过 0.82，比 25%–35% 的正确题还高。在 0.83–0.86 这个区间， 两群完全交错，划不出任何一条能用的分数线。

原因很清楚：C / D / F 这类题问的话题在语料里真实存在，只是要找的那一条不存在。

L4-12  问《深圳…监察条例》第八十条关于「强制拆除」的程序
       → 「强制拆除」是这部条例的核心内容，检索给 0.860
       但该条例只有 66 条，没有第八十条

检索和重排序模型能判断的只有"这段文字和你问的像不像"。它没有任何办法知道条号越界了。 这是能力范围之外的事，与模型强弱无关。

所以产品结构必须是两道闸门：

闸门 1 · 话题级闸门 2 · 条文级
判据重排序分数结构化校验（条号 / 引用出处 / 时效）
性质概率确定性
覆盖（实测）19/40 对抗题C/D/F 共 15 道（37.5%）
定位兜底主防线

读法：闸门 1 挡住的 19 道里，绝大多数是"用户一看就知道库里没有"的 B / E 类。 而最危险的那 15 道必须靠闸门 2——它们从用户视角看和正常问题一模一样： 法规名是真的、主题是真的、条号格式也是真的。

2.3.2 闸门 1 · 话题级

若 第一条重排序分数 < 0.40  →  判定「语料中没有该话题」，直接告知检索不到

阈值 0.40 的依据（实测扫描）：

阈值挡住对抗题误杀正确题
0.4019/400/20
0.5022/400/20
0.6026/401/20
0.8539/404/20
0.9040/404/20（20%）

取 0.40：零误杀，且距最近的正确题（0.508）留 0.108 余量。

想用分数挡住全部对抗题，阈值得拉到 0.90，代价是 20% 的正确题被判"检索不到"。 这不可接受——产品宁可漏挡，不可误杀：误杀会让用户以为库里没有，直接放弃使用。

两条硬性约束：

  1. 只做上限判定，不做下限判定。 只把"分数低于 X"判为检索不到，

    2. 绝不把"分数高于 X"判为"有依据"。分数高不能证明依据存在（C 类的 0.860 就是反例）。

  2. 它只覆盖"话题整个不在库里"这一种情况。 挡不住 C/D/F，也挡不住 A/G/H 里

    3. 话题真实存在的那几道。不能把它当成防线来规划预算。

2.3.3 闸门 2 · 条文级（主防线）

闸门 2 是一段确定性程序（scripts/gatekeeper.py），不调用任何模型。 它拿三样东西：问题、候选回答、本次召回的段落。然后做四项检查。

编号检查判据数据来源级别
C1条号越界引用的条号 ≤ 该法规实际条数article_counts.json拦截
C2引用存在性登记的每条（法规, 条号）能在本次召回段落里反查到本次召回的段落拦截
C3时效比对已失效法规有没有被当成可引用的现行依据stale_ledger.json拦截 / 提示
C4边界判定一致性模型自报的前三行事实能不能推出第四行结论回答自身拦截 / 提示
C5所问法规划界问题点名了库外法规，却被答成库内另一部问题本身 ＋ 回答的「引用法规在库内」行拦截

C1–C4 与 C5 的分工：前四项核对的是「模型自报的四行字段彼此是否自洽」， C5 核对的是「自报的字段是否属实」。

查自洽查不出填错——这是【边界判定】这个解法本身的边界：它把「让程序猜模型想干什么」 换成了「让模型登记事实、程序核对」，但如果登记的事实本身就是假的，程序只能照单全收。 C5 补的就是这个洞的一角。

C1 为什么最有效：拦住"深圳第八十条"不需要任何重排模型，一张条数表就够了。 成本极低、确定性 100%、可解释到"该法规共 66 条，不存在第八十条"。

C3 为什么分两档：

  • 用户要拿条号去办事 + 法规已失效 + 回答给了条号 → 拦截（L4-26 就是这一类）
  • 回答只是照实说明"该法已废止、以下仅作历史参考" → 提示

    • （信息有用且诚实，只是不能作为现行依据 → 判为「部分作答」）

C4 的特别之处：前三行都是可核对的事实，由它们可以唯一推出第四行应该是什么。 两者不一致就是自相矛盾，而这个检查不需要任何语义判断。

C5 是怎么被发现的（值得单独讲）：它不在最初的规格里。做 MVP、换成 qwen-plus 直连之后，问库外的《城市市容和环境卫生管理条例》，模型拿库内的 《呼伦贝尔市城市市容和环境卫生管理条例》作答——两部都管户外广告和牌匾标识—— 并自报「引用法规在库内：有全文」。C1–C4 全部通过，交付出去的是一个张冠李戴的 「可作答」。用户会以为拿到的是自己问的那部法规的条文。

C5 的判据是：把「问题本身就写着的事实」拉进来对齐。

问题里用书名号点名的法规 ──match_law──► 库内没有它的全文
                                          ＋
                                模型自报「引用法规在库内：有全文」
                                          ↓
                                      矛盾 → 拦截

两个都是客观事实，中间不需要任何语义判断——与「用【引用清单】替掉正文正则」、 「用【边界判定】替掉拒答 marker」是同一个解法：能核对就不要猜。

它的价值恰恰在换模型之后才显现。在原来的 Dify 链路上，模型从没犯过这个错， 所以在完整版 66 题上离线核算的结果是 0 题触发、各项指标逐字节未变。 补进去零回归，但它证明了「硬约束不该只写在提示词里」——约束的可靠性不该跟模型绑死。

合成最终结论的顺序（前三步都不看模型自报值）：

① 有拦截项                          → 拒答（给了不该给的东西）
② 有一条可用依据也拿不出来，但也确实不是拒答 → 见下面这段
③ 只依赖了失效法规的条文              → 部分作答（有用，但只能算历史参考）
④ 有提示项                          → 部分作答
⑤ 以上都没有，再看模型自报值          → 只用来往更保守的方向调整

第 ② 步值得单独说。它的原始写法是「一条可交付依据都没有 → 拒答」。这句话对 "模型什么都没给出来"是对的，但会误杀一类完全正确的回答：

问：《中华人民共和国噪声污染防治法》现在还有效吗？

这个问题的依据来自时效台账。法规正文里根本没有"这部法还有效吗"这句话，

所以它永远不会有条号可以引用。「没有条号」被读成了「没有依据」，

正确的回答（已废止）被降成了拒答。

修法用的是完全客观的判据：问题指向的库内法规都在台账里，且模型自报的时效状态与台账 逐字相同——满足就说明回答的核心主张被外部真值印证过了。这条修正一口气修掉了 3 道 被误判的题（L3-01 / L3-02 / L4-12），并且不放弃否决权：它只在没有拦截项、 且模型自报比"拒答"更宽松时生效，自报「拒答」的回答永远不会被它升格。

2.3.4 闸门 2 现在的定位与缺口的边界

已经做到的：闸门 2 是一段可以独立运行的代码，有 11 组不调用模型的规则用例， 可以接在命令行、两个网页、或任何后端后面，输出带完整校证明细的结论强度。 MVP 已经证明它可以脱离 Dify 独立工作。

还没做到的（这是当前最大的结构缺口）：闸门 2 还没有被强制接进交付链路里。 如果绕过 ask.py / mvp/server.py 直接调 Dify 的应用接口，拿到的是未经校验的原始输出。

为什么这个缺口存在：Dify 0.15.3 的应用链路本身不支持插入自定义校验代码。 正确的接法是在应用外面包一层服务，业务系统只允许调这一层。本项目已经给了三个例子 （ask.py / serve_demo.py / mvp/server.py），但它们都只是"约定"，不是"强制" ——约定可以被绕过。

风险描述：换模型、调温度、绕过外层服务直调应用接口，都会让提示词里的四条硬约束失效， 而闸门 2 只有在被调用时才起作用。评测脚本能事后发现，但发现不了"当下正在发生的错误交付"。

C5 的局限要一起写清楚：它只覆盖「问题点名了库外法规」这一种自报字段填错。 如果模型把库内法规 A 的内容说成法规 B 的，而问题里两部都没点名——这种情况仍然漏过。 要覆盖它需要另一条客观判据，目前没有。

2.4 提示词工程：v1 → v2 → v3

提示词是产品规格的一部分，不是"给模型的建议"。三个版本的演进如下。

版本加了什么为什么加
v1输出格式：结论 / 依据 / 【引用清单】让判分从"正则猜正文"变成"核对模型登记的条目"
v2【语料时效台账】表 + 时效标注要求效力状态不在法条正文里，必须由外部提供
v3【边界判定】四行字段 + 时效硬规则 + 【历史沿革】分流见下

v3 的四条硬约束

1. 引用存在性    回答里出现的每一部法规名、每一个条号都必须能在本次检索结果里找到
2. 时效标注      命中已废止/已失效文件时，必须先声明并说明失效原因
3. 条号越界      引用的条号必须在所引法规的条数范围内
4. 时效硬规则    为用户"现在或将来的行为/文书"取条号依据、而所依据法规已废止/失效时，
                 **必须拒答条号**

第 4 条是从 L4-26 的失守反推出来的，也是四条里最容易犯的一条。它需要区分两件事：

允许禁止
说明该法失效前的条文（历史参考）允许，但必须单独放在【历史沿革】一节，且该节的条号不进引用清单
给出"现在应当引用第X条"无条件禁止

判据是问题里的操作性意图，命中任一即是： ① 主语是"我/我们/本单位"且要拿条文去办事； ② 问"应当引用第几条"这类指向条号的行动指引；③ 时间指向现在或将来。

【历史沿革】的分流设计：一刀切禁止提条号会损失信息（用户可能确实想知道 "以前归哪条管"）。所以采取物理分开的做法——失效事实放在结论区，历史条文放在 【历史沿革】区，该节的条号不进引用清单，且末尾必须写"以上条号随该法规失效， 不可作为现行依据引用"。用户读到的格式本身就在提示他：这一节的条号不能用。

【边界判定】四行字段：第三次踩同一个坑之后的解法

这个字段是 v3 的核心，值得单独讲清楚它的来由。

同一个坑踩了三次，每次都是"拿一个不区分的代理指标代替语义判断"：

次序代理指标后果
1扫正文正则，判断"有没有把内容挂错法规"4 条正确拒答里 3 条误报 → 改用【引用清单】
2用"引用清单是否为空"判断"是不是拒答"6 条里 5 条误报 → 改用负面措辞扫描
3用"回答里有没有负面词"判断"有没有识别边界"把 L4-26 判成"已拒答"（正文含「已失效」二字），掩盖了真实失守

第三次换了解法：让模型把客观事实显式登记出来，由程序机械核对。

【边界判定】
引用法规在库内：有全文 | 仅被提及 | 不在库内
所问条号核验：存在 | 不存在 | 未指定
时效状态：现行有效 | 已废止 | 已失效 | 未知
结论边界：可作答 | 部分作答 | 拒答

四行里前三行都是可核对的事实（库里有没有全文 / 那个条号存不存在 / 法规还有没有效）， 由它们可以唯一推出第四行。两者不一致 = 自相矛盾 = 不合格， 这个检查不需要任何语义猜测。

内部一致性规则（写成自相矛盾的组合即为不合格回答）：

若则不得填
引用法规在库内 = 仅被提及 / 不在库内可作答
所问条号核验 = 不存在可作答
时效状态 = 已废止 / 已失效可作答

输出契约

四个区块顺序固定，它是产品交付物，同时是判分器的核对锚点：

【边界判定】        ← 四行字段，机器可复核
结论                ← 一句话
依据                ← 逐条：【《法规全名》第X条】原文关键句……
【引用清单】        ← 一行一条：法规全名|第X条；无依据时写「无」

【引用清单】的作用：它同时是三件事——产品的可溯源引用载体、判分的核对锚点、 用户拿去写文书的凭据。只登记正文真正用来支撑结论的条文；【历史沿革】一节里的条号不得进清单。

强度触发条件用户可见文案要点日志字段

「部分作答」的判据必须锚定到「所问法规里有没有」

这条定义迭代过一版，过程值得记录。

首版写成"只能给出部分依据"。结果 13 道对抗题全部被填成「部分作答」，而按答案键应该 是「拒答」。逐条读原文后确认：行为全对、标签不同。

L4-21  问《深圳…监察条例》对扬尘污染怎么规定
       答：该条例规范的是规划土地监察，扬尘不在其调整范围；库内另有怀化条例，
           但适用范围是怀化市，不能作为本问题的依据
       → 结论完全正确（它自己避开了"别的法规有相关规定"这个陷阱）
       → 却填了「部分作答」，理由是"我给出了一些有用信息"

根因：「部分作答」的定义里没有说明"部分"是相对于谁的部分——模型理解成 "我给了部分有用信息"，答案键理解成"用户问的那部法规里有部分可用内容"。

修法是把判据锚定在「所问法规里有没有回答这个问题所必需的条文」， 并明确列出三种属于拒答却容易被填成部分作答的情形：

  1. 所问法规里没有该内容，但你给出了"其他相关法规"的条款；
  2. 你给出的只是"这段文字在别处被转引 / 该法规名只在制定依据里被提及"这个事实；
  3. 你为了证明所问法规不涉及该主题，而列出了该法规的其他条款

    4. （列的是"没有规定的证据"，不是"回答问题的依据"）。

重跑后这 13 道全部改判为「拒答」。

唯一一处例外：所问法规里有同一主题的相邻条款时，「部分作答」是正确的。 例：问葫芦岛条例的「居民绿色账户积分兑换制度」，该条例第三十八条确实规定了 「通过奖励、表彰、积分兑换等方式促进分类投放」——用户问的制度名不存在， 但同一主题确有规定。此时告知"有积分兑换这一方式、但没有绿色账户制度" 比单纯拒答更有用且同样诚实。这个例外由答案键逐题给出，并配一条校验： 相邻主题词必须在该题的目标法规里真实出现，否则放宽没有依据。

为什么不设"分数中间带 → 提示置信度低"这一态

因为实测证明划不出来。对抗题在 0.40–0.86 区间与正确题完全重叠， 任何基于分数的中间判定都会同时误伤正确题、放过对抗题。 中间态只能基于闸门 2 的结构化结论，不能基于分数。

早期文档里曾设想"用分数分三档"，那个设想未经验证，已作废。

2.6 评测体系

评测分成两张表管理：一张管答得对不对（能力集），一张管该不该答（防火墙集）。 两者的样本量由不同依据决定，合并看会掩盖问题。下面先说两张表的分工， 再说对抗形态、出题器的结构断言，以及加检查项时必须遵守的回归纪律。

两个用途，分开成两张表

用途        名称      分层      条数   考什么                       样本量由什么决定
──────────  ────────  ────────  ─────  ──────────────────────────  ──────────────────
答得对不对  能力集    L1 基础     12   单点事实检索                 业务分布（40%）
                      L2 推理      8   要拼两处以上信息 / 读表格     业务分布（25%）
                      L3 边界      6   时效 / 废止 / 引用≠全文       业务分布（20%）

出题器的结构断言（最值得复制的一条机制）

40 道题靠人肉检查一定会漏，所以每道 L4 题除了文本还挂一条断言， 验证这道题在结构上真的成立：

law_absent        该法规名在语料全文里出现 0 次            → B 纯外部 / G 跨层级
law_referenced    该法规名在语料里出现过（被引用）          → A 被引用但无全文
art_out_of_range  该条号 > 该法规实际条数（真的越界）       → C 越界条号
topic_absent      该主题词在该法规全文里 0 次出现           → E 主题错位 / H 虚构制度
law_expired       该法规在时效台账里是废止/失效状态         → F 时效陷阱
excerpt_in        该节选关键词确实在承载文件里              → D 转述性节选

它上线第一次跑就抓到了 3 道写错的题：

[x] L4-36 断言失败：虚构术语『专项资金』在 ['土壤污染防治法'] 中出现，题目不成立
[x] L4-38 断言失败：虚构术语『奖励』在 [5 部法规] 中出现，题目不成立
[x] L4-39 断言失败：虚构术语『门票』在 ['昌吉…天山天池…条例'] 中出现

L4-39 尤其说明问题：出题时以为风景名胜区条例里不会有「门票」，结果它有 （第二十一条禁止行为里的「逃票、违规销售门票」）——换成更精确的「门票价格」才成立。

「期望边界」答案键

golden-set.csv 有一列「期望边界」，取值与提示词的枚举一致。 它回答的是"这道题的正确答案，在【边界判定】第四行应当填什么"：

A/B/D/E/G/H  拒答              话题整个不在库里，只能拒答
C            拒答|部分作答      指出条号不存在，可附替代条款
F            拒答              为现在取可引用的条号，而法规已失效 → 必须拒答条号

为什么需要它：时效硬规则要求"为现在或将来的行为取依据、所依据法规已废止时必须拒答条号"。 判分器怎么知道某道题属不属于这种情形？只能从答案键读。 让判分器去猜题目意图，就是第四次犯"用代理指标代替语义判断"的错。

加检查项时的回归纪律（C5 的做法）

C5 是本项目里唯一一次「在已有结论之后新增检查项」，做法值得固化成规矩：

  1. 先做影响评估，再改代码。 在完整版 66 题的结果上离线核算，只问两个问题：

    2. 「新判据会触发几题」「触发的那几题期望边界是什么」。C5 的结果是 0 题触发——因为完整版链路上模型从没犯过这个错。

  2. 零触发才敢直接补。 如果它触发了一批题，那就已经超出"补一个检查"的范围，属于"换一套判据"，

    3. 必须按 3.4 的三轮对照重做，并保留旧口径的结果做对照。

  3. 补完必须逐字节验证不变。 --rejudge 的输出与基线 diff 为空，才算通过。

这三条合起来是一句话：加防线不能顺手改判据。 一次改动同时改了判据又加了防线， 指标一变就无法判断变化来自哪一处。

2.7 十一条关键工程结论

每一条都可以单独拿出来讲，且都有实测支撑。

1. 一条阈值分不开对抗题，因为分不开的原因在"话题存在与否"，不在"有没有依据"。 对抗题分两类：话题整个不在库里（分数 0.13–0.35，分数挡得住）、 话题存在但那条条文不存在（分数 0.42–0.86，分数挡不住）。 按机制分类才能定产品规则。

2. 重排序的价值在检索层，不在答案层。 端到端四轮迭代里，重排对硬指标（引用可追溯、真编造）没有增量； 它的真实增量是检索层那个闸门。手册里"重排序"的定位要从"可选精度优化"改成"安全阀"。

3. 拦住"条号越界"不需要模型，一张条数表就够。 这是整个项目性价比最高的一条：零模型成本、确定性 100%、可解释到具体条数。

4. 判分器的判据必须是可核对的客观事实，不能是需要解释的评价词。 这个错误在本项目里出现了 4 次：扫正文正则判"挂错法规"（误报 3/4）、 用"清单是否为空"判"是否拒答"（误报 5/6）、用"正文有没有负面词"判"识别没识别边界" （掩盖真实失守）、以及"部分作答"没有参照物（13/40 标签分歧）。 前三类是"机器猜人"，第四类是"人和机器对同一个词的理解不同"。

5. 让模型登记客观事实，比让程序猜模型意图可靠。 【边界判定】四行字段的解法。前三行是事实、第四行是判断，事实能唯一推出判断， 于是"自相矛盾"变成一件可以机械检查的事。

6. 模型和判分器必须用同一套底层实现。 同一个"把法规名对上号"的需求在评测脚本和产品校验层各写一遍，会出现两份实现、 两套边界情况、两个地方改 bug。这两处必须给出完全一致的结论，否则 "评测通过了、上线出问题"就是必然。本项目已把这些函数收敛到 legalkit.py。

7. 代理指标的适用域必须写清楚，不适用的地方宁可空着。 「判据词命中率」在 L3/L4 上系统性地骗人：L4 的正确回答本来就该是拒答，不去命中任何 答案键；L3 问的是"还有效吗"，正确措辞和答案键几乎不可能逐字对上。 把一个不适用的指标填成 0% 比不填更糟——会被当成缺陷去"修"。

8. 误杀比漏挡更伤产品。 这条决定了两个设计：闸门 1 选 0.40 而不是 0.90；以及闸门 2 不能把 "没有条号可引用"直接当成"没有依据"。误杀会让用户以为库里没有，直接放弃使用。

9. 硬约束不该只写在提示词里。 提示词里的约束是"模型自觉"，换模型、调温度都会失效。C5 的发现过程是这条的实证： 在 Dify 链路上 66 题一次没犯的错，换成 qwen-plus 直连第一次跑就犯了， 而它恰好落在原有四项检查的能力范围之外（C1–C4 查自洽，查不出填错）。 把约束从提示词搬进规则层，是唯一能让它不依赖模型的路径。

10.「没抓到」和「没有」必须在界面上长得不一样。 这是做目录层时唯一不能妥协的一条。市级抓到 3 份、省级一条也没抓到， 如果界面只显示这 3 行，用户会合理地得出「省级没有相关文件」——而真相是接口解析不了。 兜底型工具制造这种错觉，害处大于它挡住的风险。落到实现上就是六个状态词 （ok / empty / blocked / unavailable / error / skipped）加一段必须出现的 「未覆盖部分」。一个用来兜底的东西，宁可显得笨，不能显得全。

11. 收窄需求能换来更漂亮的指标，代价是产品不管用。 这一条是被人当面纠正之后才承认的。最初把「库里这 8 部法规够不够用」当成可接受的前提， 据此把产品定义成纯核查器——指标很好看（引用可追溯 100%、对抗题 40/40）， 但真实工作流的第一段（这个方向有哪些文件）被删掉了，产品在第一步就等于零。 遇到"数据不够全"的质疑时，先问缺的是哪一段工作流，再决定是收窄范围还是补数据。 把范围划小永远是最省事的答案，也最容易答错。

2.8 目录层：把「库里没有」变成「名单上有」

2.8.1 这一层是使用者逼出来的

这个项目最初的假设是「文件已经在我手上，我来核验引用属不属实」。真实场景不是这样。 一个规划师接江西鹰潭的城市更新项目，第一件事是弄清这个话题在三级政府各有哪些文件：

  • 鹰潭市本级：城市更新专项规划、年度计划、棚改攻坚方案……
  • 江西省：省政府与住建厅的实施意见、技术导则、专项资金办法……
  • 国家：国务院的《城市更新"十五五"规划》、部委的配套措施……
  • 跨领域：这个项目还要碰历史建筑与文物，那是另外一套文件

如果知识库里没有这些，产品在这一步就等于零。这一条是当面被指出来的： 我原先的处理方式是把需求收窄成「只做核查」，先把范围划死——那等于把工作流的第一段 （发现有哪些文件）从任务里删掉了。收窄能换来一个更漂亮的指标，代价是产品不管用。

但反过来的「把全量法规都入库」也不成立：一个省市每年新增政策文件几十到上百份， 全国范围是几万份量级，且逐年增删。这不是「再补一点语料」能解决的。

2.8.2 拆成两层，因为两类字段的可得性不一样

目录层（2026-10 新增）全文层（原有）
存什么名称 / 发文机关 / 文号 / 效力级别 / 发布与失效日 / 地域 / 主题 / 链接逐条正文
目标接近穷举——不能漏按需精读——不能错
一次规模一个地域 × 一个主题 = 几份到几十份20–50 份
更新节奏每天可刷，抓一次十几秒立项时定一次，随语料重建
验收判据覆盖度：三级各自覆盖到了吗五项确定性校验：条号越界 / 引用存在性 / 时效 / 边界一致 / 所问法规划界
失败的后果漏了一份，用户以为「没有」错引一条，用户拿去写文书

为什么不全量入库，还有第二条理由，而且更硬：覆盖 80% 比覆盖 3% 更危险。 库里越全，用户越不会另外去查，漏掉的那部分就越难被发现。而这个产品的定位是兜底—— 兜底的东西一旦给出「已经查全了」的错觉，它带来的风险会超过它挡住的风险。 目录层正是为这件事设计的：它说的话始终是两段式，「这些是我查到的」加「这些是我没查到的」。

2.8.3 状态词表：整个目录层唯一不能妥协的地方

每个源跑完必须落一个状态，只有六种取值：

状态含义界面
ok抓到了，且命中主题已覆盖
empty抓到了，但里面没有命中主题的文件已查无
blocked源端拒绝或需要人工干预（反爬、验证、要登录）未覆盖（受阻）
unavailable源端没有可用的接口（前端渲染、纯 JS 应用）未覆盖（无接口）
error请求失败或解析崩溃未覆盖（出错）
skipped本次没跑这一类源（如人工清单未填）跳过

「没抓到」和「没有」必须在界面上长得不一样。 这条是整个设计的地基。 反例很具体：市级抓到 3 份、省级一条也没抓到。如果只打印一张清单，用户看到 3 行， 会认为「省级没有相关文件」——而真相是江西省政府的检索接口解析不了。 在一个用来兜底的工具里，这个差别是致命的，所以它是六个状态词，不是一个布尔值。

2.8.6 推断出来的字段必须带依据

没有一个源会直接给出「效力级别」和「地域」这两个字段。它们靠推断，而推断会错， 所以每个值都带一个来源标注：文号 / 时效台账 / 来源库 / 来源站点 / 标题 / 无法判定。 合并多源时，同一份文件的 doc_type 只有在新依据的可信度高于旧依据时才允许覆盖， 并且值和依据必须一起换——只换值不换依据，会出现「规范性文件（依据：无法判定）」 这种自相矛盾的记录（实测出现过一次）。

两个真事，都是实测撞出来的：

  • 《李强主持召开国务院常务会议……审议通过《古树名木保护条例（草案）》》被判定成

    • 地方性法规——因为标题里有「条例」。

  • 《鹰潭市中心城区城市更新专项规划（2026-2035年）》反过来被判成不是文件，

    • 直接从清单里消失——因为标题末尾是「）」。

同一个判定函数，两个方向都会错。修法是同一条：判定前先剥掉标题末尾的括注， 括号里的内容不参与判断。这条改动之后才敢说清单里的类型是可用的。

2.8.9 它给问答层带来什么，没带来什么

带来了一条此前没有的能力：漏引候选清单。 稿子引了 M 份文件，目录上有 N 份，那 N−M 份自动成为「该不该引」的候选。 这是对我此前一个过度断言的修正——我说过「漏引查不出」，有了目录层之后， 漏引里最粗的一类（整份文件没被提到）是能查出来的；仍然查不出的是更细的一类 （提到了这份文件，但该引的条文没引）。

没带来全文。 目录层只回答「有哪些」，不回答「第几条规定了什么」。 要逐条引用，仍然得把那份文件转成入库文本走原有链路。

没带来目录本身的完整性。 抓不到的源仍然是空的，只能靠人工清单补， 而人工清单当前是空的。这条在 2.9 里作为风险登记着。

2.8.10 明确不做的事

  1. 不抓全文。 抓下来要解析、清洗、判版本，成本比目录层高一个量级；而且「该抓哪几份」

    2. 正好该由人来定——那正是第 ⓪ 段的产出，也是这个人的专业判断所在。

  2. 不判效力。 它只报「台账怎么说」和「无证据」。效力认定需要法制部门的正式口径，

    3. 工具给不了；给了就是替它背书。

  3. 不猜。 推不出的字段留空并写「无法判定」，不用站点归属去填空。这一条在实测里

    4. 返工过两次（见 2.8.6），两次都是因为「先填上一个看起来合理的值」比留空省事。

  4. 不追求单源覆盖。 任何一个源都可能改版、下线、反爬。三层里只要有一层是 ok 的，

    5. 清单就还有用；缺的那一层会被明确说出来。这是分布式抓取唯一诚实的设计方式。

为什么答案层判分要靠【引用清单】而不是扫正文： 第一版判分器直接正则扫正文里的《法规名》，结果 4 条完全正确的拒答回答里有 3 条被误判成 "挂错法规"——因为拒答时本来就要点名那部不存在的法规来说它不存在。 试过两轮改进（整句否定判定 → 误报 3/4；±28 字窗口 + 条号共现 → 误报 2/4）都不成立。 根因是正文里"提到某法规"和"把某条内容挂到该法规名下"在用词上分不开，任何正则都是在猜。

改成让模型显式登记它实际依赖的条目之后，判分从猜测变成了核对：误报 0、口径统一。 而且这个清单本身就是产品要交付的东西（可溯源引用的载体），不是为测试临时加的。

为什么判据词命中率只在 L1+L2 统计：它在 L3/L4 上系统性地骗人（见 2.7 第 7 条）。

L4 的主指标从「拒答正确率」改成「边界处理正确率」： 旧口径只看"模型有没有拒答"，而 A/C/D/F/G 这类题的正解本来就是 「指出问题 + 给出部分可用依据」，不该一律拒答——上一轮把 5 道完全正确的回答判成了失守。 新口径分四项，缺一项就说明"嘴上认了、手上没认"。 同时保留「字面拒答（结论边界=拒答）」作为细分指标，它回答的是另一个问题： 模型有没有明确说"没有依据"。

3.5 判分口径的演进与踩过的坑

判分口径改过多次，每一次都是因为前一次的代理指标在实测中失效。下面按发生顺序列出， 包含判断错的那几次，以及最后是怎么改对的。

三次"用代理指标代替语义判断"

次序代理指标后果修法
1扫正文正则判"挂错法规"4 条正确拒答误报 3 条改用【引用清单】
2用"清单是否为空"判"是否拒答"6 条里 5 条误报改用负面边界声明扫描

第 4 次：枚举定义不够锐利

13 道对抗题全填「部分作答」而答案键期望「拒答」。这是人和机器对同一个词理解不同： "部分"没有参照物。修法是把判据锚定到「所问法规里有没有」，并列出三种属于拒答的情形。 重跑后 13 道全部改判。

四次共同根源：判断标准里含有需要解释的成分。 所以现在凡是要紧的判据，都必须是可核对的客观事实 （库里有没有全文 / 条号存不存在 / 法规还有没有效 / 文献里有没有这个词）。

次序位置表现

闸门 2 的两个假阳性（2026-10-14 修）

假阳性 1 · "没有条号可引用"被当成"没有依据"

问「《噪声污染防治法》现在还有效吗？」——这个问题的依据来自时效台账， 法规正文里根本没有"还有效吗"这句话，所以永远不会有条号可引用。 合成规则里那句"一条可交付依据都没有 → 拒答"把它误杀了， 正确答案（已废止）被降成拒答。涉及 L3-01、L3-02。

修法：用完全客观的判据识别——问题指向的库内法规都在台账里， 且模型自报的时效状态与台账逐字相同。满足就说明回答的核心主张被外部真值印证过了， 按「部分作答」交付。这条只在没有拦截项、且模型自报比"拒答"更宽松时生效。

假阳性 2 · 正文兜底路径缺了否定语境过滤

extract_cites() 提取正文里的「《法规》第X条」时不看语境，于是把两类句子当成了引用：

L4-12  「该条例共 66 条，不存在第八十条」        → 被当成越界引用，C1 拦截
L3-02  「该决定暂调《海商法》第四条」            → 被当成库外法规引用，C2 拦截

两道完全正确的回答被判成拒答。

修法：清单明确写「无」时，正文里的条号按说明性引用处理，不登记为交付依据。 理由是清单是模型对"我依赖了哪些条目"的声明，它声明无依据时， 正文里出现的条号是在解释、不是在交付。 编造仍然照抓：C2 末尾的正文扫描会检查"这个条号在本次召回里根本不存在"， C3 的时效硬规则走 OPERATIONAL_CITE_RE，都不受影响。 清单缺失（模型没按格式输出）时不走这条宽松口径——它连契约都没遵守，不值得给宽松待遇。

正则的「区块结束」定义（标题写法变化引发的故障）

BOUNDARY_BLOCK_RE 和 HISTORY_BLOCK_RE 初版用 (?=\n\s*【|\Z) 判断区块结束。 模型把标题写成 ### 【引用清单】 时（"### "不是空白字符），这个前瞻匹配不上， 区块会一路吃到文末。实测造成两处真实故障：

  • _first_paragraph 把【引用清单】的内容当成了结论（用户看到的结论是一串条号）；
  • 【历史沿革】区块吞掉它后面的整个结论区 → 时效硬规则的操作性指引检查漏检。

第二处更危险，因为它是"该拦的没拦住，而且不报错"。

修法是 _SEC_END：把 markdown 井号前缀纳入判定，**并给「结论」加否定前瞻 结论(?!边界) —— 否则字段行「结论边界**：可作答」也满足"行首是结论"， 区块会在第二行就被截断，四个字段全丢。

同一天它又坏了一次，根因相同：模型把标题写成 ### 2. 结论（带序号前缀）。 _SEC_END 允许 #{1,6}\s*，但不允许后面的 2. ，于是【边界判定】块一路吃掉 「结论」和「依据」两节——用户看到的结论是空的。修法是在标题词前加 (?:\d+\.\s*)?。

两次都是"模型写法变了、正则没跟上"，两次的症状都是"区块吃多了、静默"。 规律是：只要区块边界靠"标题长什么样"来判定，模型换个写法就会失效。 彻底的解法是让输出契约带固定标记（本项目已固定 【】 全角括号， 但模型仍会自行加 markdown 井号和序号），或者改用输出 schema 而不是正则。 目前取的是"把常见前缀都枚举进来"这个折中，代价是每见到一种新写法就要补一次。

第 5 次：查自洽查不出填错

前四次都是「判据里含需要解释的成分」。第 5 次不同，它是解法本身的能力边界：

C1–C4 核对的是「模型自报的四行字段彼此是否自洽」。模型把库内的 《呼伦贝尔市城市市容和环境卫生管理条例》当成用户问的《城市市容和环境卫生管理条例》， 自报「引用法规在库内：有全文」——四行自洽，C1–C4 无从开口。

修法是 C5，把「问题里点名的法规在不在库内」这个问题本身就写着的事实拉进来对齐。 详见 2.3.3。

这次的教训与前四次不同：前四次是"判据不客观"，这次是"客观判据覆盖不全"。 前者靠换判据解决，后者只能靠不断补充互相独立的客观事实来源。

一处自我更正
