# 目录层（catalog）—— 回答「这个方向有哪些文件」

> **先分清两个目录**：这里是「用户问一个方向，我现查」这一层——按需抓、带覆盖度、带状态词表。
> 要把库一次性铺满（1.8 万份全文、6.5 万条地方目录），看 [`../harvest/README.md`](../harvest/README.md)。
> 两者共用 `data/catalog.db` 和 `CatalogItem` 模型，但**用途和代价完全不同**：
> 这里一次查询十几秒到两分钟，那边一轮全量约两小时。

## 它解决什么

接到一个新项目（比如鹰潭的城市更新专项），第一步是**发现**：这个方向上有哪些
文件——市里的、省里的、国家的，可能还要跨到历史文化保护。

这一步的判据是**不能漏**，所以它需要覆盖度；而它真正要的东西是**清单**，
不是每份文件的全文。

全文库回答不了这个问句：文件本身不知道自己存在。所以单开一层，只存
**可以穷举的字段**：

| 字段 | 说明 |
|---|---|
| 名称 / 发文机关 / 文号 | 从源端直接取，或从标题里抽 |
| 效力级别 | 文号优先（`国发〔2026〕12号` → 国务院文件），无文号才看标题后缀 |
| 地域 | 标题与机关里出现的省市名；判不出就记来源库/来源站点 |
| 主题 | 按词表打多标签（城市更新 × 历史文化保护会同时命中） |
| 施行 / 失效日期 | 源端提供则用，否则空着 |
| **效力状态** | 现行有效 / 已废止 / 已失效 / **未知** |
| 来源 / 来源类型 / 原链接 | 每条都能追回原页面 |

字段能穷举、全文不能——这是它能在几千条量级做到接近全、又能每天刷新的原因。

## 怎么跑

```bash
# 出清单（首次真抓，之后读缓存）
python scripts/catalog/crawl.py --region 鹰潭 --topic 城市更新

# 忽略缓存重新抓；--pages 强行翻更多页
python scripts/catalog/crawl.py --region 鹰潭 --topic 城市更新 --refresh --pages 23

# 只看某一级/某个源（调试用）；--all 连新闻稿一起看
python scripts/catalog/crawl.py --region 鹰潭 --topic 城市更新 --refresh --only yingtan --all

# 机器可读
python scripts/catalog/crawl.py --region 鹰潭 --topic 城市更新 --json

# 库里的家底 / 各源最后一次的状态
python scripts/catalog/crawl.py --stats
python scripts/catalog/crawl.py --sources

# 省市级抓不到时，人工补一份清单进去
python scripts/catalog/crawl.py --import data/catalog/江西省城市更新清单.csv

# 自检（不联网，30 项）
python scripts/catalog/crawl.py --selftest
```

配套的 HTTP 接口（已接进 `mvp/server.py`）：

```
GET /api/catalog?region=鹰潭&topic=城市更新[&keyword=][&refresh=1]
GET /api/catalog/sources
```

前端在 `mvp/index.html` 顶部的「政策清单」面板，服务和页面一起起来就能用。

## 输出怎么读：状态词表

这是这一层最要紧的设计——**「没抓到」永远不会伪装成「没有」**：

| 状态 | 含义 | 该怎么办 |
|---|---|---|
| `ok` | 抓到了，且命中主题 | — |
| `empty` | 源可访问，扫了 N 条，没有该主题的文件 | 正常，说明该源确实没有 |
| `blocked` | 页面取到了但解析不出条目（前端渲染 / 规则不匹配） | 人工补，或为该站写适配器 |
| `unavailable` | 已知该源不提供可用机器接口 | 人工补 |
| `error` | 网络或解析失败（带原因） | 重试；持续失败说明接口变了 |
| `skipped` | 本次未参与（如人工清单还是空表头） | — |

覆盖度按三级汇总，`missing` / `partial` 一定显式打印，末尾还有一段
「未覆盖的部分（这些不是「没有文件」，是「这次没查到」）」。

**为什么不把抓不到的源直接删掉**：删掉之后报告只会少一行，用户不会注意到
省级是空的，反而更容易误以为「已经查全了」。

## 已实测的源（2026-10-19）

| 源 | 层级 | 形态 | 结果 |
|---|---|---|---|
| `govcn_gw` 国务院政策文件库 | 国家 | JSON 接口 `sousuo.www.gov.cn/search-gov/data` | ✅ 稳定 |
| `govcn_bm` 国务院部门文件库 | 国家 | 同上，`type=bwyzcwjk` | ✅ 稳定 |
| `yingtan` 鹰潭市政府站内检索 | 市级 | 大汉版通 `jsearchfront/interfaces/cateSearch.do`，返回 `{result:[html], total}` | ✅ 城市更新命中 276 条，收录 3 份文件 |
| `yingtan_col` 鹰潭政府文件栏目 | 市级 | 栏目页服务端渲染，条目带 `title` 与 `/art/YYYY/M/D/` | ✅ 可抓（该栏目本身无城市更新文件） |
| `flk_npc` 国家法律法规数据库 | 国家 | Vue SPA；前端 bundle 里挖出 17 个接口路径 | ✗ 显式 **blocked**（接口在、没解开） |
| `jiangxi_prov` 江西省政府文件 | 省级 | TRS search5，列表与检索均前端渲染 | ✗ 显式 blocked |
| `manual` 人工清单 | — | CSV / JSONL | ✅ 表头见 `data/catalog/manual.csv.example` |

`flk` 那一条的实测记录（2026-10-19 两轮）：
- 第一轮：`/law-search/download/excel` 真实存在，但 `/law-search/search`、`/list`、
  `/query` 等候选端点全返回 Spring 的 404；直接 POST `/api/` 被 nginx 拦成 405。
- 第二轮：下载前端 bundle（1.3 MB）后提取出 **17 个真实路径**，其中
  `law-search/search/list` 是列表检索、`law-search/search/flfgDetails` 是单部详情
  （含效力状态）。但 `search/list` 只收 POST，最小参数体返回
  `{"msg":"系统异常","code":500}`，且首页带 `law-search/index/captchaImage` 风控。
- 所以状态从 `unavailable` 改判 **`blocked`**：需要的是人工逆向，不是换源。
  今天能用的路径仍是官方导出后 `--import`。

### 批量能翻多深（2026-10-20 更新）

| 池子 | 源端总量 | 翻到底的代价 |
|---|---|---|
| 国务院政策文件库 | 6,222 条 | 311 页 ≈ 4 分钟 |
| 国务院部门文件库 | 12,806 条 | 640 页 ≈ 8.5 分钟 |
| 两者合计（去重后入库） | **18,916 条**（源端自报 19,028，差 0.6% 为翻页期间新文件插入的偏移） | 约 10 分钟 |
| 「城市更新」主题子集 | 3,197 条 | 2 分 19 秒（实跑，收录 21 份国家文件） |

`--pages` 直接给大值即可深翻（实测 p=70 仍正常返回 20 条，没有封顶）。

**关于「不要把全量目录当全文库用」**（2026-10-19 的原判断，现修正）：
1.9 万份全文已经进库了，但它走的是**独立检索链路**（`data/kb.db` + `/api/kb`），
只给原文片段和链接，**不做五项核验**。核验（C1 条数越界、C3 时效）仍只覆盖 8 部法规——
因为这两项要的「条数表」和「时效台账」不是抓全文就有的，得逐份确认。所以正确的说法是：

> 全文可以全量进库做检索，但**核验能力必须跟着装配走**，不能跟着抓取走。

这也是为什么 `docs/项目总说明-v3.md` 把「装配」列成唯一 P0 阻塞项。

## 加一个省市

不用改代码。在 `scripts/catalog/sites.json` 里加一条：

```json
{
  "name": "nanchang",
  "type": "jsearch",
  "label": "南昌市人民政府（站内检索）",
  "region": "南昌市",
  "base": "https://www.nc.gov.cn",
  "websiteid": "<站号>",
  "endpoint": "/jsearchfront/interfaces/cateSearch.do",
  "pages": 20,
  "interval": 0.3
}
```

同时在 `regions` 里补一条链路，让「查南昌」能自动带上江西省和国家：

```json
"南昌市": { "aliases": ["南昌", "南昌市"], "chain": ["南昌市", "江西省", "国家"] }
```

**站号怎么找**：打开该站任一页面，在站内搜索框搜一次，看网络面板里
`cateSearch.do?websiteid=` 后面那串数字；多数地级市就是行政区划码补零
（鹰潭 360600 → `360600000000000`）。

如果站点不是大汉版通（比如江西省级是 TRS），先用 `type: "note"` 把它登记成
`blocked` 并写明原因，再决定是写适配器还是走人工清单。

## 与问答层的关系

两层各管一段，不要混：

- **清单**回答「有哪些文件」，判据是**不能漏** → 靠覆盖度
- **问答**回答「这一条怎么规定」，判据是**不能错** → 靠闸门 2 的五项校验

清单是问答的前置：先把范围框出来，再逐条问。目录层里 `status` 为「未核」的条目
说明**没有证据**支持它有效或废止——这是刻意的，不给有利假设。想让它变成
「已废止」，就补 `data/stale_ledger.json`，`--align-ledger` 会把结论同步过去。

## 不做的事

- **不抓全文**。要全文就是另一层的事（`data/corpus/` + 检索 + 闸门 2）。目录层
  只回答「有没有、叫什么、还有效吗」。
- **不假装权威**。所有推断字段都带 `*_src`（文号 / 标题 / 来源库 / 来源站点 /
  无法判定），UI 上把依据显示出来，用的人才知道该信几分。
- **不承诺覆盖全国**。链条只对配置里有的地域成立；没配的会明确告诉你
  「省市两级本次没有配置源」，而不是悄悄只返国家级结果。
