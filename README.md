# 有据

**模型给答案，规则层核对答案。核不过的降级或拒答。**

面向规划行业的政策依据引擎。问一个政策问题，或贴一段自己写的稿子：系统从 34,634 份
政策正文里找依据，让模型作答，再用一层**不调用模型**的确定性规则逐条核对——条号是否越界、
引文是否真实、文件是否已失效、法名是否错配、所问法规划界。核不过就不给结论，
或者降级成「部分作答」并注明哪一段没核过。

它存在的理由只有一句：**编造的条号和真实的条号，在界面上长得一模一样。**

![有据的首页](docs/screenshots/01-home.png)

---

## 它解决的是什么问题

规划院做一份专题，光找依据就要四到八小时。中间有三种时间是被白白扔掉的：

**找了很久没找到。** 政策散在住建、自然资源、发改、生态环境十几个口径里，市县两级的
规范性文件经常只在某个栏目挂过一次，搜索引擎抓不到。

**找了半天才发现没有。** 搜到的标题相关，点进去是「批后公布」的图则，正文是 CAD 图，
没有一条可引的条文。

**找到了但已经废了。** 文末写「有效期至 2025 年 12 月 31 日」，到期自动失效，
没有任何文件宣布它废止。你引了它，审稿人一查，整段作废。

前两条靠扩库解决，第三条靠**台账**解决。这个项目三条都做了，但第三件是重点——
前两件别人也在做，第三件几乎没人做，因为它的答案不在任何一篇文章里，
要逐份去读文末那一行小字。

## 它和普通 RAG 的区别

**核验层不调用模型。** C1—C5 五道判定全是确定性规则：条文号在你引的那份文件里存不存在、
引文和原文的字符相似度够不够、这份文件在台账里是什么状态、你写的法名和你引的条文是否属于
同一部法、你的结论方向和原文的立场是否一致。同一份输入跑一百次，结论完全一样，断网可跑。

**库外的文件如实标成库外。** 库里没有的城市不会拿别的城市的文件顶上。报告里写明
「本次检索范围内没有 XX 市的对应文件」，而不是给你一份邻市的、看起来很像的依据。

**失效是六态，不是三态。** 见下节。

## 时效台账：六态里最值钱的是 `expired`

| 状态 | 份数 | 含义 |
|---|---:|---|
| `no_signal` | 31,937 | 全库正文比过，没有废止记录，原文也没写有效期 |
| `in_force` | 1,397 | 原文写了有效期，还没到 |
| `repealed` | 856 | 已废止，有文件点名 |
| **`expired`** | **343** | **有效期已届满，到期自动失效** |
| `superseded` | 81 | 同名法规有新版 |
| `pending` | 20 | 还没到施行日 |

`expired` 这一列是最值钱的。原来只判「有没有别的文件说它失效」，这一问在规范性文件上会漏掉
一整类——文末一句「有效期至 2025 年 12 月 31 日」，到期自动失效，没有任何文件宣布它废。
343 份 `expired` 里有 330 份在旧台账里标的是 `no_signal`，界面显示「未见废止记录」，
**等于在暗示它还能用**。最近一份到期是 2026-10-23，三天前。

`pending` 也有用：20 份里《市场监督管理所条例》11 月 1 日才施行，现在引是提前引。

## 实际操作

### 一、拆解方向，看它缺什么

问题进来先拆成几个取证方向，每个方向标出层级（本地法规 / 本地规划 / 本地政策 / 省级法规）、
关键词、地域，以及「库里有多少份」。

![拆解方向](docs/screenshots/02-plan.png)

### 二、筛文件，失效的会被标出来

这一屏是整个系统的重点：

![依据清单](docs/screenshots/03-sources.png)

- 候选 107 份，默认勾了 22 份，其中 20 份有正文可引原文。勾选可以逐个改。
- 第三分组里，《南京市国有土地上房屋征收与补偿办法》（政府令第318号，2017）是现行的，
  勾着；它上面那份 2012 年的同名通知标着**已废止 2012-06-01**，没勾。
  **同一件事的两个版本躺在同一屏里，旧的那个被标红了。** 没有这一列的话，
  两份文件的标题都叫「南京市国有土地上房屋征收与补偿办法」，你只能靠发文年份自己猜哪份算数。
- 第四分组「老门西所在历史文化街区保护规划」标着「其中 0 份有正文可引」，
  还写了原因：这批文件只有批后公布和图则公告，正文是图件，抽不出条文，
  **能证明规划已批复，不能引条款**。

「只有目录」和「有正文」是两个不同的东西，界面从不混着说。

### 三、出五段报告

五段结构固定：问题界定 / 依据梳理 / 判断 / 办理路径 / 风险提示。
依据段每一条都必须带原文引文，格式是「说明句 → 原文：「逐字照抄」→【《文件》第X条】」，
引文缺失的会写「条款过长未摘」，不许空着。

![报告正文](docs/screenshots/04-report.png)

### 四、核验结果摊开给你看

报告下面就是核验面板。C1 到 C5 各自通过几条、拦下几条、未核几条，全列出来。
这一屏是「可交付 / 部分可核 / 不可交付」的判定依据：

![核验面板](docs/screenshots/05-verify.png)

22 处引注全部回原文核对通过，依据段逐句有出处 70%——**这个 70% 会如实写在报告头上**。
它同时告诉你「22 处引注每一处都对上了原文」和「还有三成句子没有逐字出处」，
两句话都得看。C5 那列是灰的，因为这个提问没点名具体法规，判据不存在，
按规矩标「未核」而不是默认通过。

## 快速开始

需要 Python 3.10 以上。**零第三方依赖**，只用标准库。

```bash
git clone https://github.com/jingtingshanw/youju.git
cd youju

# 1. 先装数据（仓库里没有，1.03 GB，见下一节）
tar -xzf pv-data-20261026.tar.gz

# 2. 自检，30 项，不联网不调模型，2 秒
python scripts/selftest.py          # 通过 30/30 才往下走

# 3. 配一个模型 key
cp .env.example .env                 # 填 DASHSCOPE / DEEPSEEK / ARK 任一

# 4. 起服务
python app/server.py                 # → http://127.0.0.1:8848
```

自检挡的是「不会报错但会让检索少给几条」的问题：索引没重建、台账漏了某个地域、
`docs` 和 `blocks` 的行数对不上。**少给几条的后果是用户以为没有**，这是这个项目最不能出的错。

## 核验在核什么

| | 判什么 | 判据 | 不过怎么办 |
|---|---|---|---|
| **C1** | 条文号存不存在 | 在这份文件的条文索引里找 | 拦截，不许引 |
| **C2** | 引文是不是原文 | 字符级比对，相似度低于阈值判失败 | 拦截并给原文 |
| **C3** | 这份文件还有效吗 | 台账六态 | 失效件拦截，未生效件警告 |
| **C4** | 你写的法名对不对 | 名称归一 + 条文归属 | 拦截 |
| **C5** | 结论方向和原文一致吗 | 问题点名了法规才判，否则标「未核」 | 不一致降成部分作答 |

C5 常常整片是「未核」，因为大多数问题不点名具体法规。这不是坏了——判据不存在的时候
标未核比默认通过诚实，报告里也会写明。

## 边界

- **地方法规只有 8 个地域有正文**。其余 1,485 个市/县能查目录、能看标题、能给链接，
  但引不出条文。库里没有的城市不会拿邻市文件顶上。
- **人大立法只有名录，没有条文**。《城乡规划法》《文物保护法》《消防法》这一层是空的，
  规划最常引的几部法恰恰在这里。这是下一步最该补的。
- **政府门户约 38% 抓不动**（2,491 个站里 946 个：前端渲染、反爬、无入口），
  这部分靠目录层补标题，正文取不到。
- **不能判断规定在实践中的执行口径**。它给的是文件怎么写的，不是审批时怎么掌握的。

## 设计原则

- **说清核了什么、没核什么，比多做一条功能重要。** 界面上的每个数字都标出处，
  每条结论都带核验覆盖率。
- **宁可少给，不可给错。** 库外就说库外，没抓就说没抓。「没抓到」被读成「没有」，
  是这个领域最贵的错误。
- **规则层不调模型。** 能写成确定性判据的，绝不用提示词。模型负责组织语言，
  不负责判断对错。
