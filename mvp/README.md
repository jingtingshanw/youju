# 有据 · 政策效力核验引擎（最小 MVP）

**模型给答案，规则层核对答案。核不过的降级或拒答。**

一个政策法规工具，三块面板各回答一个问题：

| 面板 | 回答的问题 | 数据 |
|---|---|---|
| **问答** | 这一条怎么规定的、还能不能引 | 8 部法规 / 419 个检索单元（核验语料的全部） |
| **政策清单** | 这个方向有哪些文件，哪一级缺 | 目录层，按地域 × 主题现查 |
| **地方目录** | 省 / 市 / 县三级有哪些文件 | `catalog.db` 的 65,111 条 |

全文层还有一条独立的检索接口（`/api/kb`，1.86 万份国家级正文 / 167,595 块），
它回答「哪份文件的哪一条说了这件事」。

---

## 一条命令跑起来

```bash
python mvp/server.py
```

然后浏览器打开 **http://127.0.0.1:8765**。

其它入口：

```bash
python mvp/server.py --ask "怀化市对扬尘污染防治实施统一监督管理的是哪个部门？"
python mvp/server.py --port 9000 --model deepseek-chat
python mvp/server.py --probe          # 自检：用评估集量一次检索召回 + 闸门 2 规则自检
```

**要求**：Python 3.10+（用到了 `X | None` 类型语法），**问答链路零第三方依赖**——不需要 pip install，
不需要 Docker，不需要 Dify。

**数据依赖**：问答要 `data/kb_text_v2/*.txt` + 三张表；「地方目录」面板要 `data/catalog.db`（53 MB）；
全库检索要 `data/kb.db`（980 MB）。**没有后两个也能跑，只是那两块面板会报「目录库不可用」**——
这个降级是设计好的，不是崩溃。

**模型 key**：从 `ai-pm/.env` 读（本仓库上一级目录）。按 `DASHSCOPE` → `DEEPSEEK` → `ARK`
的顺序取第一个有 key 的，默认用 `qwen-plus`。任何 OpenAI 兼容接口都能换。

## 一次问答的完整链路

```
问题 ──► 本地检索（BM25，419 条款 / 8 部法规）
     ──► 模型生成（按 prompts/system-v3.md 的四节格式）
     ──► 闸门 2 校验（scripts/gatekeeper.py，不调模型）
     ──► 交付：结论 + 逐条依据核对 + 时效 + 五项校验明细
```

页面上的结论强度只有三种：

| 显示 | 含义 |
|---|---|
| ✓ 可作答 | 有现行有效、能在本次召回中反查到、且条号未越界的条文依据 |
| ! 部分作答 | 依据可用但需另行核验（引用失效法规条文、或依据只有台账没有条号） |
| ✕ 拒答 | 拿不出可引用的依据 |

**规则优先于模型自评**。模型说「可作答」而条号越界了，页面显示「拒答」并注明
「两者不一致，已按更保守的一方交付」。

## 四个能力边界

写在最前面，因为它们决定你在什么场合能用它。

**一 · 问答层的检索是 BM25，不是向量检索。**
用中文 2-gram 打分，不做语义理解。用户换个完全不同的说法问同一件事时可能捞不到条文
（条文写「生态环境主管部门」，用户问「环保局管不管」就悬）。语料小、法律文本用词固定，
所以在这个场景里够用——`--probe` 可以看实测召回。

**二 · 问答语料只有 8 部法规、419 个条款。**
这是**核验语料**，不是全部数据。换语料只需替换 `data/kb_text_v2/*.txt` 并同步更新 `data/` 下三张表。
1.86 万份国家级全文走的是另一条检索链路（`/api/kb`），它只给原文，不做五项规定检查。

**三 · 65,111 条地方目录只有标题，没有正文。**
面板上每条都带 `仅目录` 标记。**引用前必须回源。** 这是当前最重要的使用约束——
一条目录「搜得到」不等于「读得到」，更不等于「引得了」。

**四 · 校验层判断的是「模型自报的字段」，字段本身填错了只覆盖了一类。**
C1–C4 核对「模型自报的四行字段彼此是否自洽」，C5 核对「自报的库内状态是否属实」——
但只覆盖「问题点名了库外法规」这一种情形。其它类型的自报字段填错，仍可能漏过。
这是当前版本已知的最大结构性缺口。

## 和完整版（Dify 版）的关系

| | 完整版 | 本 MVP |
|---|---|---|
| 检索 | Dify 向量召回 + rerank | 本地 BM25（**唯一退化的部件**） |
| 生成 | Dify 应用（10 个容器） | 直连 OpenAI 兼容接口 |
| 校验 | `scripts/gatekeeper.py` | **同一份代码** |
| 提示词 | `prompts/system-v3.md` | **同一份文件** |
| 判定逻辑 | `scripts/legalkit.py` | **同一份代码** |
| 目录层 / 全文层 | **同一份数据** | **同一份数据** |
| 启动成本 | 起 Docker、建知识库、建应用 | `python mvp/server.py` |

MVP 不做第二套判定实现。它把模型的输出包装成 Dify 的形状（`answer` +
`metadata.retriever_resources`），然后交给 `scripts/ask.py` 里那个在 66 题评估上验证过的
`analyze()`。**同一个回答在两版里会得到同样的判定**，区别只在检索质量。

理由很实际：判定逻辑一旦有第二份实现，两份迟早会给出不同结论，而这种分歧最难查
（评测放过、上线拦下）。

## 实测

### 问答层检索召回（`--probe`）

判据取自 `eval/golden-set.csv` 的「判分规则」列：凡是 `『』` 包起来的就是答案必须包含的关键信息
（如『生态环境主管部门』『二万元』）。用它定位「含答案的那一条」，看它有没有进候选。

| 候选窗口 | L1 基础 | L2 推理 | 合计 |
|---|---|---|---|
| top-1 | 8/9 | 4/6 | 12/15 (80%) |
| top-3 | 8/9 | 6/6 | 14/15 (93%) |
| **top-8（默认）** | **9/9** | **6/6** | **15/15 (100%)** |

这一步失败意味着模型再强也答不对（答对了也是碰巧），所以它是 MVP 里最该盯住的数字。

### 校验层

`python mvp/server.py --probe` 末尾会顺带跑闸门 2 的规则自检：**11/11 通过**。

### 三层数据的延迟（2026-10-20 实测）

| 层 | 查询 | 耗时 |
|---|---|---:|
| 问答层（419 单元） | BM25 top-8 | 毫秒级 |
| 全文层（167,595 块） | 历史建筑 修缮 / 征收补偿 标准 / 城市更新 补偿 / 老旧小区 改造 | **5 / 6 / 9 / 35 ms** |
| 目录层（65,111 行） | 征收补偿 / 城市更新 / 历史文化保护 / 老旧小区 | **110 / 118 / 123 / 265 ms** |

目录层那 110–265 ms 是 `LIKE '%…%'` 扫全表的上限，规模再涨一个数量级必须换 FTS。

### 五类真实问答

| 场景 | 问题 | 结果 |
|---|---|---|
| 能答的 | 怀化市对扬尘污染防治实施统一监督管理的是哪个部门？ | ✓ 可作答，依据《怀化市扬尘污染防治条例》第五条 |
| 时效 | 《中华人民共和国噪声污染防治法》现在还有效吗？ | ! 部分作答，结论「已于 2026-08-15 废止」 |
| 要拒的 | 我要依据已废止的噪声法对夜间施工企业作行政处罚，决定书应引用第几条？ | ✕ 拒答（模型自报拒答） |
| 条号越界 | 深圳条例第八十条关于强制拆除的程序？（该条例共 66 条） | ✕ 拒答 |
| 问库外的法 | 《城市市容和环境卫生管理条例》对户外广告设置是怎么规定的？ | ✕ 拒答（**模型自报「可作答」，被 C5 拦下**） |

最后一行是本 MVP 最有价值的一屏：模型拿库内《呼伦贝尔市城市市容和环境卫生管理条例》
第五个条款当作依据，自报「有全文 / 可作答」，C1–C4 全部通过——只有 C5 把它拦住了。

### 对既有评估没有影响

C5 是在 MVP 里发现的，补进 `gatekeeper.py` 之后，在完整版的 66 题结果上离线重算：
**0 题触发，各项指标逐字节未变**（L4 边界处理 40/40、引用可追溯 100%、真编造 0%、时效违规 0），
规则判定与模型自报仍 66/66 一致。

## 三个接口

| 接口 | 查什么 | 特点 |
|---|---|---|
| `POST /api/ask` | 一次问答 | 检索 → 生成 → 闸门 2 |
| `GET /api/kb?q=&top=` | **全库全文**（1.86 万份） | 返回条号 + 原文片段 + 文号 + 链接；5–35 ms |
| `GET /api/local?q=&level=&region=&limit=` | **三级目录**（6.5 万条） | 2-gram 召回 + 「完整串优先」重排；110–265 ms |
| `GET /api/catalog?region=&topic=` | 目录层现查（会真抓） | 带 `coverage`，哪一级缺、为什么缺 |

`/api/local` 的排序有个坑值得记：2-gram OR 召回太宽，查「城市更新」会把
「城市园林绿化管理办法」也捞进来（因为「城市」命中）。所以先用 SQL 把「完整串命中」的排前面，
取 400 条候选，再在 Python 里按「整串命中 100 分 / 命中 gram 各 6 分 / 全 gram 命中 +40 / 长度惩罚」精排。

## 能拷走的最小集合

**现在有两个包，体积差 2,500 倍，用途完全不同。**

### 轻包（约 400 KB）——演示核心主张

```
mvp/
  server.py                     # 服务 + 本地 BM25 + 模型调用
  index.html                    # 前端（单文件）
scripts/legalkit.py             # 名称归一 / 条号解析 / 三张表读取
scripts/gatekeeper.py           # 闸门 2：C1–C5
scripts/ask.py                  # analyze()（两版共用）
prompts/system-v3.md            # 提示词
data/kb_text_v2/*.txt           # 8 部法规全文
data/doc_names.json
data/article_counts.json        # 条数表（C1 越界判据）
data/stale_ledger.json          # 时效台账（C3 外部真值）
```

`mvp/server.py` 通过 `sys.path` 引用 `scripts/` 下的模块，目录相对位置要保持。
`--probe` 需要 `eval/golden-set.csv`，只跑服务不需要。

### 全包（约 1.0 GB）——真实查询

在轻包之上加两个文件，**不能纳入 git**（需 LFS 或外置）：

```
data/catalog.db    53 MB    # 65,111 条目录 + 1.86 万份元信息 + 时效
data/kb.db        980 MB    # 167,595 个检索块 + FTS5 索引
```

**这个分裂本身是个产品结论**：「拷到任何地方都能跑」这个卖点在 1.86 万份的量级上不成立了。
演示核心主张用轻包，做真实查询用全包。

## 它不做什么

- **不做向量检索**。见边界一。
- **不给地方目录配正文**。6.5 万条只有元信息，见边界三。
- **不落盘**。每次问答不写文件（完整版的 `scripts/ask.py` 会存 JSON）。
- **没有用户体系**。无登录、无多租户、无限流，只监听 `127.0.0.1`。
- **不自动更新时效台账**。`stale_ledger.json` 是人工维护的外部真值。
- **不做引用到条文的逐字比对**。校验的是「这个条号在召回结果里存在」，
  不是「引用的原文与条文逐字一致」——后者需要先量化概括/省略带来的误报率。

## 政策清单与地方目录（目录层的两块）

MVP 原来只解决「这一条怎么规定」（判据是不能错）。真实工作的第一步是「这个方向有哪些文件」
（判据是不能漏），这两件事不是同一个任务。所以加了目录层。

### 政策清单（`/api/catalog`，现查）

填地域与主题，出一份带文号、效力级别、**效力状态**和原文链接的清单，按国家 / 省 / 市分组。

```bash
python scripts/catalog/crawl.py --region 鹰潭 --topic 城市更新     # 命令行同一份结果
python scripts/catalog/crawl.py --selftest                        # 30 项，不联网
```

实测（鹰潭 × 城市更新）：国家级 4 份（含国发〔2026〕12号《城市更新"十五五"规划》）、
市级 3 份（含《鹰潭市中心城区城市更新专项规划（2026-2035年）》）；
**省级显式标注为「缺失」**——江西省政府站是 TRS search5，没有可用接口。

### 地方目录（`/api/local`，查库）

查 `catalog.db` 的 65,111 条：省 15,864 / 市 16,303 / 县 32,614，覆盖 1,491 个地域。
可以按主题词、层级、地域组合过滤，返回分面计数（各层级各命中多少）。

**这块的重点不是「抓得多」，是抓不到的部分一定被说出来。** 覆盖度里 `missing` / `partial`
连原因一起显示，末尾有「未覆盖的部分」，并给人工补录办法（`--import` 或 `data/catalog/manual.csv`）。
当前站点覆盖：省级 21/31、市级 409/685、县级 1,115/1,775（合计 62%）。
